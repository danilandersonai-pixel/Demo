# Механизм генерации презентаций — как это сделано сейчас (NotebookLM) и как строить в сервисе «Твой урок»

**Дата:** 22.07.2026 · **Основа:** послайдовый анализ 5 реальных презентаций Дарьи Прониной (PDF-форензика), ресёрч NotebookLM (состояние на середину 2026), ресёрч пайплайнов конкурентов (Gamma, Tome, MagicSchool, obuchai), ТЗ «Твой урок» v2.0 (оркестратор генерации, раздел 5).

## 1. Как презентации сделаны СЕЙЧАС: реконструкция пайплайна Дарьи

### 1.1. Фактическая цепочка (по форензике всех 5 PDF)

```
Параграф учебника (PDF/скан, напр. «В.Р. Мединский § 38–39»)
        │  загрузка как источник
        ▼
NotebookLM (source-grounded Gemini)
        │  Studio → Slide Deck / инфографика
        │  текст: LLM-пересказ параграфа; картинки: Nano Banana Pro
        ▼
Экспорт PPTX/PDF (слайды или иллюстрации = растровые изображения)
        │
        ▼
PowerPoint 2016 (Windows 10) — РУЧНАЯ доводка:
        │  • старый .pptx как заготовка (Save As — отсюда чужой title
        │    «Дорожки Спряжения.pdf» в метаданных двух деков)
        │  • фон-«пергамент»/«бумага» на мастере
        │  • живые текстбоксы Bahnschrift поверх картинок
        │  • белые плашки-маски поверх дефектных подписей ИИ-картинок
        │  • белый PNG 1012×52 px — замазывание футера/вотермарки NotebookLM
        │  • ручной bold ключевых слов, покраска терминов
        │  • ручные патчи (допечатанный «§» ArialMT на титуле «Василия III»)
        ▼
Экспорт в PDF (creationDate = modDate — одна сессия)
```

Подтверждения по метаданным: все 5 деков — `Creator/Producer = Microsoft PowerPoint 2016`, `Author = Дарья Пронина`; даты — февраль–апрель 2026, вечерние сессии; у двух деков title унаследован от старого файла по русскому языку («Дорожки Спряжения.pdf») — конвейерная работа поверх заготовки.

### 1.2. Что делает ИИ, что — руки

| Этап | ИИ (NotebookLM) | Руки (PowerPoint) |
|---|---|---|
| Структура дека | ✔ порядок ролей = структура параграфа | — |
| Текст слайдов | ✔ ровный пересказ (49–61 слово/слайд) | правка почти не делается (опечатки остаются) |
| Иллюстрации/схемы | ✔ единый стиль на дек, кириллица внутри растра | маскировка дефектных подписей, оверлей-плашки |
| Оформление | — | фон, шрифты, рамки, bold, цвет терминов |
| Сборка | — | текстбоксы, позиционирование, экспорт PDF |
| Вотермарки/следы | — | белые заплатки поверх футера |

Три режима использования, найденные в деках:
1. **«Картинки-ассеты»** («Василий III», «Тверь и Москва», «XV век»): NotebookLM даёт текст + по одной ИИ-иллюстрации/схеме на слайд, учитель верстает слайды сама живым текстом. Наибольшая трудоёмкость, лучшая доступность текста.
2. **«Готовый слайд-картинка»** («Солнечная система»): каждый слайд — цельный JPEG 1376×768 от NotebookLM, руками только вставка в PPT, заплатка на футер, экспорт. Ноль текстового слоя, опечатки («гигаит») неисправимы.
3. **«Инфографика + оверлей»** («Природное сообщество»): готовые/сгенерированные инфографики + ручные заголовки и ярлыки поверх, белые маски на чужие подписи.

### 1.3. Сколько это стоит по времени (оценка)

- Генерация в NotebookLM: 5–15 мин (плюс до часа при ревизиях Revise на длинных деках).
- Ручная доводка: по плотности правок — **1,5–3 часа на дек** в режиме 1 (10–14 слайдов: вёрстка текстбоксов, bold, рамки, маски), **20–40 мин** в режиме 2. Все деки собраны за один вечерний присест (creation = mod date).
- Итого: учитель тратит вечер на одну презентацию. **Это и есть боль, которую продукт закрывает: свести 2–3 часа доводки к 60–90 секундам генерации + 5–10 минутам правок в онлайн-редакторе.**

## 2. Что мы узнали из самих деков: типология, нормы, стиль, ошибки

### 2.1. Единая типология слайдов (сводная по 5 декам)

| Роль | Код | Встречаемость | Описание |
|---|---|---|---|
| Титул | `title` | 5/5 | Тема + класс/предмет/учебник §NN + герой-иллюстрация |
| Определение/введение | `definition` | 4/5 | «Термин — определение 8–35 слов» в акцентной рамке |
| Обзор/классификация | `overview` | 2/5 | 3 элемента с иконками перед серией разборов |
| Контент-повествование | `content` | 5/5 | Карточка 5–6 тезисов + 1 иллюстрация |
| Разбор понятия (deep-dive) | `deepdive` | 2/5 | Параллельные рубрики «Кто это? / Функция / Роль» |
| Схема/процесс | `process` | 4/5 | Стрелочная диаграмма (в оригинале — цельный растр) + подписи |
| Сравнение | `compare` | 4/5 | Двухпозиционное («весы», «Игрок 1/2», цепь vs сеть) |
| Таймлайн/событие | `timeline` | 2/5 | Датированные буллеты «NNNN г. — событие» |
| Документ/артефакт | `artifact` | 1/5 | Реальное фото источника (Судебник 1497) + факты |
| Проблема/угрозы | `threats` | 1/5 | 3-шаговый процесс + колонки последствий |
| Итог/вывод | `summary` | 4/5 | Буллеты-выводы ИЛИ mind-map «Карта знаний» |

**Типовая драматургия дека** (порядок ролей почти всегда повторяет структуру параграфа учебника):
`title → definition/контекст → overview → 3–6 × (content|deepdive|process|compare|timeline) → доп-концепт → summary`. 8–14 слайдов на параграф.

Чего в деках систематически НЕТ (добавить как опции в продукт): «Вопросы/проверка понимания», «Домашнее задание», «Источники».

### 2.2. Нормы объёма текста (числа из анализа)

| Параметр | Норма из деков |
|---|---|
| Слов на контентный слайд | **45–80** (история 6 кл.: 49–61; XV век: 50–80; биология 5 кл.: 35–60; космос: 45–75) |
| Абзацев/тезисов на слайд | **5–6**, каждый = ровно 1 предложение |
| Слов в предложении-тезисе | **8–16** |
| Заголовок слайда | **2–6 слов** (титул до 10 в 2 строки) |
| Определение термина | «ТЕРМИН — …» **8–35 слов** |
| Выноска/«вау-факт» | **8–20 слов** |
| Callout-вывод | **10–18 слов** |
| Буллеты итогового слайда | **5 × ~10 слов** |
| Bold-выделений на абзац | **2–4** (термины, даты, топонимы) |
| Кегль тела | 16–28 pt (16 pt при 720×405; 24 pt при A4; итоговый слайд на +2 pt крупнее) |

Бюджет удивительно стабилен: NotebookLM сам держит ~50±10 слов на слайд — берём это как контрактный лимит JSON-схемы.

### 2.3. Стиль иллюстраций

- Ровно **одна иллюстрация на слайд** (кроме титула и mind-map): плоский мультяшный/изометрический вектор или claymation, единая палитра на весь дек, тематическая стилизация под предмет (пергамент/манускрипт — история, детский вектор — биология, пластилин — космос, «настольная игра» — соперничество княжеств).
- Схемы (оргсхемы, стрелки, пирамиды, mind-map) — **не фигуры PPT, а цельные растры** с текстом внутри.
- Кириллица внутри картинок в основном корректна (класс Imagen/Nano Banana), но с отказами: «гигаит», псевдокириллица на свитке, не осиленный «§».
- Фотографий почти нет: 1 музейное фото на 53 слайда (Судебник 1497) — и оно работает на достоверность.

### 2.4. Типовые ошибки генерации (чек-лист для нашего LLM-судьи)

1. **Фактические/терминологические**: «царская семья» при Василии III (титула ещё нет), «служивые» вместо «служилые», устаревшие числа спутников, «около 0°C» на Марсе.
2. **Анахронизмы в картинках**: храм Василия Блаженного в XV веке, императорская корона XVIII в. и монета XIX в. в XVI веке, имперский орёл на ордынской печати 1318 г., мозг/циркуль в средневековье.
3. **Опечатки в растровом тексте** (неисправимы без перегенерации): «гигаит», псевдокириллица.
4. **Грамматика LLM**: «убил князи», «включил» вместо «включив», «Самими богатыми», случайные заглавные посреди предложения, «Заглавная После Двоеточия» (калька Title Case).
5. **Структурные**: 9 из 12 слайдов без заголовков; обещанный Плутон отсутствует; дубль факта плашка/выноска; обобщающий тезис в конце вместо начала; сравнение сплошным текстом там, где просится таблица.
6. **Оформительские**: рассинхрон капитализации заголовков, дефис vs тире, двойные пробелы, пропуск «ё», фейковый bold, разные стили плашек между слайдами (стилевой дрейф пер-слайдовых генераций).
7. **Технические**: текст в растре (не ищется, недоступен скринридерам), мусорные 2×2 px объекты, разнобой форматов холста (720×405 / A4 / 1280×720), грязные метаданные (чужой title).

## 3. Ограничения NotebookLM-подхода: почему сервису нужен свой пайплайн

1. **Нет API.** Consumer-API у NotebookLM отсутствует; Enterprise API (GCP) не генерирует слайды. Легально встроить NotebookLM в «Твой урок» невозможно.
2. **Слайды — картинки.** Экспортный PPTX — плоские растры (Nano Banana Pro): текст не редактируется, «гигаит» лечится только перегенерацией; наш онлайн-редактор с таким работать не может.
3. **Нет шаблонов/брендинга.** Школьный стиль наложить нельзя — отсюда 2–3 часа ручной доводки, стилевой дрейф, маски и заплатки.
4. **Медленные и лимитированные правки.** Revise — по одному слайду промптом, до часа на длинных деках, без добавления/удаления слайдов; макет «плывёт» при регенерации.
5. **Кириллица в растре** — источник неисправимых опечаток и недоступности (поиск, скринридеры, конспектирование).
6. **РФ-доступность хрупкая**: сайт открывается без VPN, но нужен Google-аккаунт (часто нероссийский номер), Pro не оплачивается российскими картами. Для B2C-сервиса зависимость неприемлема; плюс 152-ФЗ — наш контур Yandex Cloud.
7. **Вотермарки/футеры** приходится замазывать вручную (белые PNG-заплатки в «Солнечной системе»).
8. Что у NotebookLM реально хорошо и что надо воспроизвести у себя: **source-grounding по учебнику** (низкие галлюцинации, привязка к §), **стабильный бюджет текста**, **единый стиль иллюстраций на дек**, устойчивая **учебная драматургия**. Остальной рынок этого не делает: лучший из 6 протестированных генераторов — 44% фактической точности, источники почти никто не привязывает (исключение — Perceptis).

## 4. Архитектура генерации презентаций в «Твой урок» (согласована с оркестратором ТЗ, раздел 5)

Пайплайн ложится в 7 шагов оркестратора без изменений; ниже — конкретика для типа `presentation`.

### 4.0. Схема

```
POST /api/generate {type:"presentation", subject, grade, topic, wishes?, source_doc_id?}
  → job_id
  │
  ├─ 1. Препроцессинг: source_doc (PDF/DOCX учебника) → текст → чанки для RAG;
  │      grade → возрастной профиль (лексика, длина предложений, бюджет слов)
  ├─ 2. Сценарий: реестр типов → шаблон "presentation" (JSON-схема + промпт + валидаторы)
  ├─ 3. Промпт 5 слоёв (см. 4.2) — ДВА вызова: (а) outline → (б) контент слайдов
  ├─ 4. LLM-роутер: outline+контент → Claude Sonnet/GPT (сложное);
  │      Haiku/DeepSeek/GigaChat — подписи, alt-тексты (простое)
  ├─ 5. Валидация: strict structured output, temp 0–0.1 → программные валидаторы
  │      (лимиты слов, орфография, «ё», тире) → Chain-of-Verification для дат/чисел
  │      → LLM-судья (см. 4.3) → до 3 точечных ретраев по слайдам
  ├─ 6a. Иллюстрации: Kandinsky/YandexART, 1 style-prompt на дек, БЕЗ текста в картинках
  ├─ 6b. Рендер: python-pptx + мастер-шаблон (см. 4.4) → PPTX;
  │      PDF — LibreOffice headless из PPTX; A4-раздатка — WeasyPrint+Jinja2 из того же JSON
  └─ 7. Сохранение → онлайн-редактор → экспорт/публикация
```

Ключевое отличие от NotebookLM-подхода: **текст всегда живой (текстовые фреймы), картинки — только иллюстративный слот без текста внутри; все подписи, схемные ярлыки и заголовки рендерим сами.** Это разом закрывает опечатки в растре, редактируемость, доступность и шаблоны.

### 4.1. JSON-схема дека (контракт LLM ↔ рендерер)

Роли — из типологии п. 2.1, лимиты — из норм п. 2.2 (жёсткие maxLength — первый эшелон защиты от переполнения, см. 4.5). Паттерн json-to-ppt: схема machine-verifiable, рендер идемпотентен.

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "PresentationDeck",
  "type": "object",
  "required": ["meta", "slides"],
  "properties": {
    "meta": {
      "type": "object",
      "required": ["topic", "subject", "grade", "theme", "source_ref"],
      "properties": {
        "topic":      {"type": "string", "maxLength": 80},
        "subject":    {"type": "string"},
        "grade":      {"type": "integer", "minimum": 1, "maximum": 11},
        "theme":      {"enum": ["manuscript", "edu_flat", "clay", "board_game",
                                "minimal", "science", "neutral"]},
        "source_ref": {"type": "string",
                       "description": "Учебник и §, напр. 'В.Р. Мединский, § 38–39'"},
        "image_style_prompt": {"type": "string", "maxLength": 300,
                       "description": "Единый стиль-промпт для всех иллюстраций дека"}
      }
    },
    "slides": {
      "type": "array", "minItems": 8, "maxItems": 16,
      "items": {"$ref": "#/$defs/slide"}
    }
  },
  "$defs": {
    "slide": {
      "type": "object",
      "required": ["role", "layout", "title"],
      "properties": {
        "role":   {"enum": ["title", "definition", "overview", "content",
                            "deepdive", "process", "compare", "timeline",
                            "artifact", "quiz", "summary", "homework", "sources"]},
        "layout": {"enum": ["title_hero", "card_left_image_right",
                            "card_right_image_left", "wide_diagram_bullets",
                            "split_40_60", "compare_two_cols", "definition_top",
                            "bullets_summary", "mindmap_overlay", "quiz_list"]},
        "title":    {"type": "string", "maxLength": 60,
                     "description": "2–6 слов. ОБЯЗАТЕЛЕН на каждом слайде (фикс дефекта NotebookLM)"},
        "subtitle": {"type": "string", "maxLength": 90},
        "paragraphs": {
          "type": "array", "maxItems": 6,
          "items": {"type": "object",
            "required": ["text"],
            "properties": {
              "text":       {"type": "string", "maxLength": 140,
                             "description": "Ровно 1 предложение, 8–16 слов"},
              "bold_terms": {"type": "array", "maxItems": 4,
                             "items": {"type": "string", "maxLength": 40}},
              "source_quote": {"type": "string", "maxLength": 200,
                             "description": "Дословный фрагмент источника-основания (grounding)"}
            }}},
        "bullets": {"type": "array", "maxItems": 6,
                    "items": {"type": "string", "maxLength": 90}},
        "definition": {"type": "object",
          "properties": {
            "term": {"type": "string", "maxLength": 40},
            "text": {"type": "string", "maxLength": 220,
                     "description": "8–35 слов, формат «Термин — определение»"}}},
        "compare": {"type": "object",
          "properties": {
            "left":  {"$ref": "#/$defs/compareSide"},
            "right": {"$ref": "#/$defs/compareSide"},
            "verdict": {"type": "string", "maxLength": 120}}},
        "timeline_items": {"type": "array", "maxItems": 5,
          "items": {"type": "object",
            "properties": {"date": {"type": "string", "maxLength": 20},
                           "event": {"type": "string", "maxLength": 90}}}},
        "callout": {"type": "string", "maxLength": 120,
                    "description": "Вывод-мораль слайда, 10–18 слов"},
        "captions": {"type": "array", "maxItems": 4,
          "items": {"type": "object",
            "properties": {"term": {"type": "string", "maxLength": 30},
                           "gloss": {"type": "string", "maxLength": 70}}}},
        "image": {"type": "object",
          "properties": {
            "prompt":  {"type": "string", "maxLength": 300,
                        "description": "Сцена БЕЗ текста; стиль добавляется из meta.image_style_prompt"},
            "kind":    {"enum": ["illustration", "diagram_bg", "hero", "none"]},
            "alt":     {"type": "string", "maxLength": 120}}},
        "quiz": {"type": "array", "maxItems": 4,
          "items": {"type": "object",
            "properties": {"q": {"type": "string", "maxLength": 140},
                           "a": {"type": "string", "maxLength": 90}}}}
      }
    },
    "compareSide": {
      "type": "object",
      "properties": {"label": {"type": "string", "maxLength": 40},
                     "points": {"type": "array", "maxItems": 4,
                                "items": {"type": "string", "maxLength": 90}}}
    }
  }
}
```

Программные пост-валидаторы поверх схемы (до LLM-судьи, бесплатные):
- счётчик слов: контентный слайд суммарно ≤ 80 слов, тезис 8–16 слов — иначе точечный ретрай слайда;
- регэксп-линт: двойные пробелы, дефис вместо тире в определениях, заглавная после двоеточия, «е» вместо «ё» по словарю, единая капитализация заголовков (Sentence case);
- структурный линт: у каждого слайда есть `title`; роли `title` и `summary` — ровно по разу; охват соответствует заявке (анти-«потерянный Плутон»: если overview перечисляет N сущностей — deep-dive-слайдов должно быть N);
- дедупликация: n-gram-пересечение текстов слайда (анти-дубль «кольца 73 000 км» в двух слотах).

### 4.2. Пятислойный промпт (пример: история, 6 класс)

```
[СЛОЙ 1 — РОЛЬ]
Ты — опытный учитель истории и методист. Ты готовишь презентацию к уроку
строго по предоставленному фрагменту учебника. Не привноси факты, которых
нет в источнике; для каждого тезиса указывай source_quote — дословный
фрагмент источника, на который он опирается.

[СЛОЙ 2 — ВОЗРАСТНОЙ ПРОФИЛЬ (grade=6)]
Аудитория: 6 класс (12–13 лет). Предложения по 8–16 слов, по одному
предложению на тезис. Лексика простая, новые термины объясняются через
слот definition. Бюджет: 45–80 слов на контентный слайд, 8–14 слайдов.
Не используй канцелярит и оценочные эпитеты («прекрасный», «мужественный»).

[СЛОЙ 3 — ПРЕДМЕТ/ТЕМА]
Предмет: История России. Тема: «Правление Василия III».
Источник: учебник В.Р. Мединский, § 38–39 (текст в блоке SOURCE).
Пожелания учителя: {wishes}.

[СЛОЙ 4 — ТРЕБОВАНИЯ ФГОС (детерминированная выборка по {история, 6})]
Планируемые результаты: {выдержка из реестра ФГОС/ПООП по предмету-классу}.
Обязательные элементы: даты и термины кодификатора темы; титулатура эпохи
(великий князь, НЕ царь до 1547 г.); термин «служилые люди».
Структура дека: титул → контекст → 3–6 контентных слайдов по логике
параграфа → сравнение или схема → итоги (5 буллетов) → проверка понимания
(2–3 вопроса) → домашнее задание.

[СЛОЙ 5 — STRUCTURED OUTPUT]
Верни строго JSON по схеме PresentationDeck (приложена). Никакого текста
вне JSON. Для каждого слайда заполни title (2–6 слов, обязательно), role,
layout из перечня, image.prompt — описание сцены БЕЗ текста и надписей
внутри изображения, в реалиях эпохи (никаких предметов позднее {верхняя
граница периода} года).

[SOURCE]
{чанки параграфа из RAG-выборки, с номерами}
```

Два вызова: (а) outline — только `role/layout/title` + план тезисов (дёшево); (б) наполнение по outline — пакетно или по-слайдно (по-слайдно дороже, но даёт параллелизм и точечные ретраи).

### 4.3. LLM-судья: критерии для слайдов

Базовые 5 критериев из ТЗ + специфика презентаций (шкала 1–5, verdict одобрено/правки/отклонено; правки → точечный ретрай слайда, ≤3 попыток):

1. **Соответствие классу** — длина предложений, лексика, бюджет слов в норме возрастного профиля.
2. **Педагогическая корректность** — драматургия «что это → как устроено → вывод»; обобщающий тезис в начале блока (не в конце — дефект слайда 4 «Василия III»); сравнение оформлено слотом compare, а не сплошным текстом.
3. **Фактическая точность + grounding** — каждый тезис имеет source_quote, реально присутствующий в источнике (программная проверка вхождения + судья на перефраз); даты/числа — через Chain-of-Verification; **анахронизм-чек**: терминология и атрибуты не позже периода темы (ловит «царскую семью» при великом князе и «служивых»).
4. **Уровень Блума** — вопросы quiz не только «вспомнить», минимум один на понимание/применение.
5. **Применимость** — учителю нечего доделывать: заголовки на всех слайдах, объём в тайминге урока, терминология совпадает с учебником.
6. *(доп.)* **Проверка image.prompt до генерации картинки** — дешевле, чем VLM-проверка результата: «императорская корона» в теме XVI века отклоняется ещё текстом.

### 4.4. Рендер: python-pptx + мастер-шаблон → PPTX → PDF

- **Холст всегда 16:9 (13.33×7.5″)** — фикс разнобоя Дарьи (720×405 / A4 / 1280×720). A4-раздатка — отдельный экспорт из того же JSON через WeasyPrint.
- **Мастер-шаблон на тему** (`meta.theme`): слой 0 — фон (пергамент/бумага/белый), палитра и шрифтовая пара из конфигурации темы. Шрифты — free-кириллица из Docker-образа (по ТЗ): PT Sans (тело), PT Serif/дисплейный free (заголовки), **с настоящими bold-начертаниями** (фикс «фейкового жирного» Bahnschrift Light). python-pptx шрифты не встраивает — тот же набор ставится на сервер конвертации.
- **Лейауты** = слоты с фиксированными координатами (маппинг `layout` → функция-рендерер):
  - `card_left_image_right` (и зеркальный): скруглённая полупрозрачная карточка x≈5%, w≈47%, тезисы с пустой строкой между абзацами, bold-раны по `bold_terms`; картинка 33–38% ширины, вертикально по центру;
  - `wide_diagram_bullets`: заголовок + широкая картинка ~3:1 в верхней половине + 3–5 буллетов;
  - `definition_top`: акцентная рамка 2–3 pt (цвет темы) «Термин — определение», ниже обычная карточка;
  - `compare_two_cols`: два симметричных блока + нижний verdict-callout (никогда сплошным текстом);
  - `bullets_summary`: 5 буллетов кеглем +2 pt, живой заголовок «Выводы»;
  - `mindmap_overlay`: центральная картинка-хаб без текста + программные плашки-подписи (автоматический аналог ручных оверлеев Дарьи);
  - `quiz_list`, `title_hero`, `split_40_60` — аналогично.
- Схемы (process/пирамида/mindmap) в v1 — **нативными фигурами pptx** (прямоугольники + соединители + текст): редактируемо, без ИИ-опечаток; ИИ-картинка — только декор без текста.
- **PDF**: PPTX → LibreOffice headless (wkhtmltopdf запрещён по ТЗ; шрифты в образе).
- Гигиена файла: чистые метаданные (title = тема, author = учитель из профиля, producer = «Твой урок»), без мусорных 2×2 px объектов, alt-тексты на картинки.

### 4.5. Переполнение текста — трёхуровневая защита

Autofit python-pptx фактически не работает (issues #973/#715: пересчёт делает только сам PowerPoint при открытии файла), поэтому:
1. **Контрактно**: жёсткие maxLength в схеме + пословный валидатор → ретрай слайда с инструкцией «сократи до N слов». Основной механизм, ~95% случаев.
2. **Измерительно**: перед рендером — замер строк через `fit_text()`/Pillow с реальным .ttf кириллического шрифта; при выходе за слот — ступенчатое снижение кегля (16→15→14 pt, не ниже минимума профиля класса).
3. **Аварийно**: перенос хвостовых тезисов на автосозданный слайд-продолжение (та же роль, суффикс «(продолжение)») + флаг в отчёт качества.

### 4.6. Иллюстрации: Kandinsky / YandexART с лимитами

- **Правило №1: никакого текста внутри генерируемых картинок.** В style-prompt всегда «без текста, без надписей»; весь текст — нативные текстбоксы/плашки поверх. (Kandinsky/YandexART пишут кириллицу хуже Nano Banana — риск снят архитектурно.)
- **Один style-prompt на дек** (`meta.image_style_prompt`) + фиксированный seed — лечит стилевой дрейф «Солнечной системы». Пример: «плоская векторная иллюстрация в стиле книжной миниатюры, палитра: бордовый, тёмно-синий, охра, золото, мягкие тени, без текста и надписей».
- **Экономика** (главный переменный риск маржи по ТЗ): Kandinsky бесплатен, YandexART ~1,5 ₽/генерация → дефолт Kandinsky, YandexART fallback/премиум. Лимиты: 1 картинка на слайд, ≤N генераций на дек по тарифу (free — титульная + иконки из локального набора; платный — все слайды). **Кэш по хэшу промпта**: одни темы генерятся тысячами учителей — переиспользование ассетов режет косты кратно.
- Латентность 5–15 с × 10 слайдов → генерировать параллельно с валидацией текста; дек показывать прогрессивно, картинки подтягивать по готовности.
- Модерационные отказы на школьные темы (войны, анатомия) → fallback: иконка из локальной библиотеки / текстовый лейаут без картинки.
- 1 «якорь достоверности» на дек (по образцу фото Судебника 1497): слот `artifact` с public-domain изображением, не из t2i.

## 6. Риски и открытые вопросы

1. **Качество схем нативными фигурами.** ИИ-растровые схемы NotebookLM выглядят богаче голых прямоугольников pptx. Митигция: библиотека пре-дизайнных SVG/фигурных компонентов (стрелки, пирамиды, весы, хабы) в стилях тем; открытый вопрос — объём дизайн-работ на 4 темы × ~8 лейаутов.
2. **Grounding без источника.** Когда учитель даёт только тему (без учебника), source_quote невозможен → факт-риск уровня рынка (44% точности у лучшего из 6). Вопрос: собственная база конспектов по кодификатору ФГОС как дефолтный источник? Отдельно — авторские права: хранить учебники нельзя, «учитель загружает свой файл» — единственный чистый режим.
3. **Экономика картинок.** «Kandinsky бесплатен без лимитов» — не SLA; смена условий бьёт по марже. Нужны кредиты на генерации в тарифах и кэш ассетов с первого дня.
4. **LibreOffice-рендер PDF**: расхождения вёрстки PPTX↔PDF (переносы, интерлиньяж) → визуальный регресс-тест на эталонных деках.
5. **Латентность полного цикла**: outline + контент + судья + ≤3 ретрая + 10 картинок — реально ли 30–90 с из ТЗ? Вероятно, прогрессивный UX: текстовый дек за 30–60 с, картинки фоном.
6. **Онлайн-редактор**: BlockNote — документный, не слайдовый. v1 — редактирование текста слотов без свободного позиционирования; canvas-редактор — этап 4+.
7. **Лицензии дисплейных шрифтов** тем (аналог a_AlbionicTitulInfl): проверить free-статус для коммерческого использования; чужие библиотеки шаблонов (Slidesgo/SlidesCarnival) в SaaS встраивать запрещено лицензией — шаблоны только свои.
8. **Юридика витрины**: оригинальные деки Дарьи содержат картинки NotebookLM — для кейса «до/после» ок, но их графику в шаблоны сервиса не переносим (генерим свою в том же духе).
9. **Урок Tome**: стендэлон-генератор презентаций монетизируется плохо (<$4M ARR при 20M юзеров). Страховка — презентация как один из типов общего оркестратора (лист + конспект + презентация + тест из одного источника), а не отдельный продукт.
