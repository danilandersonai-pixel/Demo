# Часть I — Основы

## Глава 1. Что такое Claude Code и чем он не является

Чат принимает сообщения и возвращает сообщения. Claude Code вдобавок
инспектирует рабочий каталог, правит файлы, выполняет инструменты, запрашивает
разрешения, достаёт настроенные сервисы, публикует страницы, планирует
собственные будущие ходы и делегирует другим экземплярам себя.

Это не делает его ни сотрудником, ни экспертом. Рабочая модель:

> Claude Code — быстрый исполнитель с переменным суждением, широким доступом к
> инструментам, без врождённого знания ваших невысказанных намерений и с
> сильной склонностью докладывать об успехе.

Последнее и есть операционно важное. Все механизмы контроля в книге существуют
потому, что **собственный отчёт агента о сделанном — наименее надёжный артефакт,
который он производит**.

### 1.1 Четыре вещи, которые должны быть явными

Работа идёт хорошо, когда четыре элемента заявлены, а не додуманы:

1. **Outcome (Результат)** — завершённое состояние, выраженное так, чтобы другой
   человек мог его проверить.
2. **Context (Контекст)** — файлы, ограничения, ранее принятые решения и то, что
   вне области работы.
3. **Boundaries (Границы)** — что можно менять без спроса, а что требует
   одобрения.
4. **Evidence (Свидетельство)** — как обе стороны узнают, что результат верен.

Пропуск четвёртого — это то, что превращает возможности в переделку.

### 1.2 Стек контроля

Большая часть потерь контроля — ошибка категории: слой, который **формирует
намерение**, принимают за слой, который **ограничивает действие**.

```
  УПРАВЛЯЕМАЯ ПОЛИТИКА — разворачивается организацией;
  единственный уровень, который пользователь не может снять
  ═══════════════════════════════════════════════════════

  РЕКОМЕНДАТЕЛЬНЫЙ   ┌───────────────────────────────────────────────┐
  формирует          │ 1  ИНСТРУКЦИЯ   CLAUDE.md · rules · skills ·  │
  намерение          │    промпт. Читается как контекст и обычно     │
                     │    соблюдается. Гарантии нет, особенно если   │
                     │    две инструкции конфликтуют.                │
                     └───────────────────────────────────────────────┘
                                        │
  ПРИНУДИТЕЛЬНЫЙ     ┌───────────────────────────────────────────────┐
  блокирует          │ 2  РАЗРЕШЕНИЕ   deny → ask → allow · режимы   │
  действие           │    Применяется продуктом. Deny нельзя         │
                     │    расширить снизу.                           │
                     ├───────────────────────────────────────────────┤
                     │ 3  ПЕСОЧНИЦА    файловая система и сеть,      │
                     │    покомандно. Применяется ОС: Seatbelt на    │
                     │    macOS, Linux и WSL2. Недоступна на         │
                     │    нативной Windows.                          │
                     ├───────────────────────────────────────────────┤
                     │ 4  ИЗОЛЯЦИЯ     контейнер · виртуальная       │
                     │    машина · dev container. Единственный слой, │
                     │    который удерживает отказ слоёв 2 или 3.    │
                     └───────────────────────────────────────────────┘

  ХУКИ пересекают слои 1 и 2 в обе стороны: PreToolUse-хук с кодом выхода 2
  блокирует вызов до вычисления правил разрешений, и никакое решение хука
  не может обойти совпавшее deny-правило.
```

Инструкция, которая **обязана** держать, принадлежит слою 2 или ниже.
Инструкция, которая **желательно** держит, принадлежит слою 1, где она стоит
контекста и покупает лишь склонность.

Практическое следствие: организация, записавшая свои стандарты в `CLAUDE.md`,
задокументировала намерение. Организация, записавшая их в управляемые настройки,
развернула механизм контроля.

### 1.3 Где выполняется работа

Один и тот же движок доступен через несколько поверхностей, и `CLAUDE.md`
репозитория, настройки и MCP-серверы применяются ко всем.

| Поверхность | Для чего лучше | Компромисс |
|---|---|---|
| Терминальный CLI | Самый ранний доступ к функциям, скриптование, удалённые хосты, полный набор команд | Нужна привычка к терминалу |
| Расширение VS Code | Инлайн-диффы, `@`-упоминания, ревью плана, история рядом с файлами | Часть контролей только в терминале |
| Плагин JetBrains | IntelliJ, PyCharm, WebStorm и родственные | Требует отдельно установленного CLI |
| Десктопное приложение | Параллельные сессии с изоляцией git, визуальное ревью диффов, локальные задачи по расписанию, computer use | Другая модель взаимодействия, чем терминал |
| Веб (claude.ai/code) | Облачные песочницы, работа с репозиториями, которых нет локально, длинные задачи | Нет доступа к локальным файлам; research preview |
| Мобильный | Запуск, наблюдение и корректировка задач с телефона | Малая поверхность управления, плохо для ревью диффов |
| Remote Control | Надзор за сессией, выполняющейся на вашей машине | Транскрипт ретранслируется и хранится на сервере, пока есть соединение |

### 1.4 Подходящие первые задачи

Выбирайте работу обратимую и дешёвую для проверки:

- разложить копии документов;
- собрать план отчёта из предоставленных заметок;
- сравнить два файла и вернуть таблицу различий;
- исследовать ограниченный вопрос и сохранить реестр источников;
- объяснить незнакомый репозиторий, ничего в нём не меняя.

Избегайте в качестве первой задачи всего, что трогает аккаунт, изменение
которого вы не можете себе позволить. **Возможности должны расширяться только
после того, как расширятся привычки проверять.**

### Ключевые положения главы 1

- Claude Code — агент, а не ассистент: он правит файлы, запускает команды,
  достаёт аккаунты и планирует свою работу.
- Четыре элемента обязаны быть явными в каждой инструкции: Outcome, Context,
  Boundaries, Evidence.
- В стеке контроля четыре слоя, и принудительно работают только нижние три.
  Инструкция — это предпочтение; правило разрешений — это контроль.
- Первые задачи выбирайте обратимые и дешёвые для проверки.

## Глава 2. Установка, проверка и аутентификация

### 2.1 Требования

На 23 августа 2026: macOS 13+, Windows 10 1809 / Windows Server 2019+,
Ubuntu 20.04+, Debian 10+, Alpine 3.19+; минимум 4 ГБ RAM, доступ к сети и
Bash, Zsh, PowerShell или CMD. Нужен аккаунт Pro, Max, Team, Enterprise или
Console — либо настроенный облачный провайдер.

Не всякая функция следует матрице платформ: песочница не работает на нативной
Windows; интеграция с Chrome не работает под WSL; артефакты, облачные сессии,
рутины и каналы недоступны на сторонних провайдерах моделей.

### 2.2 Установка

Нативный установщик — официальный путь по умолчанию, обновляется сам в фоне.

```
# macOS, Linux, WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex
```

Установки через менеджеры пакетов **не** обновляются автоматически:

```
brew install --cask claude-code        # стабильный канал
winget install Anthropic.ClaudeCode    # обновление: winget upgrade Anthropic.ClaudeCode
```

> **CAUTION.** Shell-установщик выполняет код на вашей машине с вашими правами.
> Никогда не подставляйте команду, скопированную из описания видео, рекламы,
> форума или непроверенного репозитория, вместо документированной.
> Проверяйте домен посимвольно.

### 2.3 Проверить до входа в аккаунт

```
claude --version
claude doctor
```

`claude doctor` выполняет проверку установки и конфигурации только на чтение;
с 2.1.206 он вдобавок предлагает сокращения для закоммиченного `CLAUDE.md`.
Внутри сессии `/login` переаутентифицирует или меняет аккаунт, `/logout`
выходит. Учётные данные хранятся в macOS Keychain, где он есть, и защищаются
правами файлов на Windows и Linux.

> **CAUTION.** Несколько функций требуют именно входа с подпиской claude.ai и
> **молча недоступны**, когда приоритет получает `ANTHROPIC_API_KEY`,
> `ANTHROPIC_AUTH_TOKEN` или `apiKeyHelper`: интеграция с Chrome, артефакты,
> рутины, облачные сессии и teleport. Если документированная команда будто бы
> отсутствует — проверяйте путь аутентификации раньше, чем версию.

### 2.4 Windows: нативно или WSL 2

- **Нативная Windows** подходит для Windows-проектов. Песочница недоступна.
  Git for Windows рекомендован, но больше не обязателен: без него инструментом
  оболочки служит PowerShell.
- **WSL 2** подходит для Linux-инструментария и **требуется** для
  песочницы Bash. Интеграция с Chrome под WSL не поддерживается.

> **CAUTION — WebDAV на Windows.** Anthropic не рекомендует включать WebDAV или
> разрешать доступ к путям вида `\\*`, которые могут содержать
> WebDAV-подкаталоги: это позволяет инициировать сетевые запросы к удалённым
> хостам в обход системы разрешений.

### CHECKPOINT главы 2

- `claude --version` печатает версию.
- `claude doctor` не сообщает о нерешённой критической проблеме.
- `claude` стартует и показывает тот аккаунт, который вы имели в виду.
- Вы знаете, обновляется ли ваша установка автоматически.
- Вы знаете, вошли вы по подписке или по API-ключу.

## Глава 3. Поверхности, проекты и границы

### 3.1 Настроить IDE

Установите VS Code, откройте **Extensions**, найдите **Claude Code** и
**убедитесь, что издатель — Anthropic**, прежде чем ставить. Из палитры команд
**Claude Code: Open in New Tab** даёт разговору полноценную вкладку редактора,
**Open in Terminal** запускает CLI внутри IDE.

### 3.2 Создать тренировочное пространство

Открытая папка — граница работы по умолчанию. В ручном режиме Claude Code может
писать только внутрь этой папки и её подпапок и спрашивает, прежде чем читать
пути вне её инструментами Read, Grep и Glob; в авторежиме он читает за границей
не спрашивая. Расширяйте границу осознанно через `--add-dir` или `/add-dir`, а
не рефлекторно.

> **CAUTION.** Открытая папка — **не песочница безопасности**. Claude Code может
> запросить дополнительные каталоги, выполнять команды, ходить в сеть и
> пользоваться подключёнными сервисами в пределах разрешений.
> **Не открывайте домашний каталог как проект**: принятие доверия там держится
> только на сессию и никогда не пишется на диск, поэтому запрос будет
> появляться при каждом запуске, а радиус поражения ошибки в разрешениях — вся
> ваша личная файловая система.

### 3.3 Монорепозитории и большие деревья

В монорепозитории вложенные `CLAUDE.md` чужих команд подхватываются из каждого
родительского каталога. Используйте `claudeMdExcludes`, чтобы их пропускать,
правила с областью по путям — чтобы грузить инструкции только для подходящих
файлов, и скиллы на уровне пакета — чтобы держать руководство локальным.
Это следует делать раньше, чем брать более широкое окно контекста.

### Ключевые положения главы 3

- Открытая папка — граница по умолчанию, а не песочница.
- В ручном режиме Claude пишет только внутри папки; в авторежиме читает за её
  пределами не спрашивая.
- Никогда не открывайте домашний каталог как проект.
- В монорепозитории сначала `claudeMdExcludes` и правила по путям, и только
  потом — увеличение окна контекста.

## Глава 4. Режимы, модели, усилие и расход

### 4.1 Контроли, которые важны в первую очередь

- **Режим разрешений** — `Shift+Tab` в CLI, индикатор режима в VS Code,
  селектор в Desktop. Цикл `default` → `acceptEdits` → `plan` есть в каждой
  сессии; два дополнительных режима встают после `plan`, когда включены, а
  `dontAsk` в цикле не появляется вовсе. Подробно — глава 7.
- **Модель** — `/model` или выбор из списка. Доступность меняется: **не
  заучивайте имя модели из записи видео.**
- **Усилие** — `/effort`, уровни `low`, `medium`, `high`, `xhigh`, `max` на всех
  поверхностях, плюс `ultracode` и `auto`, доступность которых различается.
  `ultracode` — не просто уровень усилия, см. главу 22.
- **Быстрый режим** — `/fast`, меняет глубину на задержку.
- **Советник** — `/advisor` подключает к рабочей модели более сильную,
  вызываемую в ключевые моменты.
- **Прерывание** — `Esc` останавливает текущий ход, `Ctrl+C` жёстче.
- **Настройки из промпта** — `/config`, включая ключи без отдельной команды.

### 4.2 Словарь усилия по поверхностям

`/effort` и `claude --effort` — два интерфейса к одному контролю, и они
принимают **не одни и те же слова**. Наблюдение на Claude Code 2.1.246,
26 августа 2026 — не гарантия продукта:

| Уровень | `/effort` (терминал) | `/effort` (VS Code) | `claude --effort` |
|---|---|---|---|
| `low` | да | да | да |
| `medium` | да | да | да |
| `high` | да | да | да |
| `xhigh` | да | да | да |
| `max` | да | да | да |
| `auto` | — | да | нет |
| `ultracode` | да | — † | да † |

† отсутствует в собственной справке этой поверхности · — не установлено

Два следствия важны на практике. **`claude --effort auto` отвергается**: флаг
предупреждает, что `auto` не является допустимым значением, и сессия дальше
работает на усилии по умолчанию — то есть скрипт, который его задаёт, не
получает запрошенного и при этом не падает. И **`ultracode` принимается флагом,
хотя `claude --help` его не перечисляет** — поэтому строка справки считается
свидетельством того, что поддерживается, и никогда — свидетельством того, что
отвергается.

### 4.3 Правило выбора модели и усилия

| Работа | Стартовая позиция |
|---|---|
| Найти файл; переформатировать известный текст | Более дешёвая модель, обычное усилие |
| Пересказать предоставленный материал | Обычное усилие |
| Спроектировать проект; разрешить настоящую неоднозначность | Более сильная модель, высокое усилие |
| Выполнить уже утверждённый явный план | Обычное или высокое; проверять полноту, а не креативность |
| Многоисточниковое исследование; архитектурный компромисс | `xhigh` либо динамический воркфлоу (глава 22) |

> **PRACTITIONER NOTE.** Это суждение, а не гарантия продукта. Повышение усилия
> не делает ответ правильным, а понижение не делает операцию безопасной. Усилие
> меняет, сколько модель размышляет; оно не меняет ничего в том, что ей
> **позволено** делать.

### 4.4 Расход и контекст измеряются раздельно

`/usage` сообщает стоимость сессии, лимиты плана и активность, и умеет разбивать
расход по скиллам, сабагентам, плагинам и MCP-серверам. `/cost` и `/stats` —
документированные псевдонимы. `/context` отвечает на другой вопрос: что сейчас
занимает окно разговора. Это связанные, но разные величины, и оптимизация одной
за счёт другой — частая и дорогая ошибка.

Два факта объясняют большинство неожиданных счетов:

1. Расход растёт **суперлинейно** в длинной сессии, потому что каждый запрос
   несёт накопленную историю.
2. Из-за кеширования промпта смена модели, `/compact` или смена стиля вывода
   вынуждают некешированный ход, **а правка `CLAUDE.md` не вступает в силу
   посреди сессии**. Если изменение проектных инструкций будто бы
   проигнорировано — обычно причина в этом.

### 4.5 Что оптимизировать в первую очередь

1. Перестать передавать нерелевантный материал.
2. Сохранять долговечные результаты в файлы вместо повторной генерации.
3. Делегировать только ограниченную независимую работу (глава 16).
4. Убрать неиспользуемые плагины, коннекторы и агентов — **после** измерения их
   вклада, а не до.
5. Начинать чистую сессию, когда задача сменилась.

Не оптимизируйте за счёт отказа от проверки. Более дешёвый неверный ответ — всё
равно отход, и в этой области это отход, который приходит, выглядя как успех.

### Ключевые положения главы 4

- Режим разрешений, модель, усилие и стиль вывода — четыре независимых контроля.
- `/usage` измеряет ваш расход, `/context` — что занимает окно. Это разные
  вопросы.
- Расход растёт суперлинейно в длинной сессии.
- Правка `CLAUDE.md` не действует посреди сессии: системный контекст читается
  один раз при старте.
