# Neon Velocity II: Rhythm & Dodge

Неоновая ритм-аркада на рекорд в стиле Retro Synthwave / Cyber Arcade — вторая
редакция игры, написанная с нуля. Корабль летит по дороге, уходящей в перспективу
к ретро-солнцу; из дымки у горизонта навстречу несутся кубы, циркулярные пилы и
лазерные ворота. Всё прилетает точно в долю музыки (128 ударов в минуту), сферы
на дороге играют мелодию, а комбо добавляет в саундтрек новые слои. Задача одна:
продержаться как можно дольше и побить свой рекорд.

Музыка и звуки синтезируются в браузере, шрифты лежат в сборке — интернет игре
не нужен. Интерфейс на русском, аркадные надписи (SCORE, COMBO, GAME OVER) — латиницей.

## Быстрый старт

Нужен Node.js 22 (начиная с 22.12) или 24 — этого требует Vitest 5; серверу
разработки и сборке (Vite 8) хватает и 20.19.

```bash
npm install
npm run dev        # игра на http://localhost:5173
```

## Команды

| Команда | Что делает | Что получается |
| --- | --- | --- |
| `npm run dev` | сервер разработки Vite с горячей заменой модулей | игра на `http://localhost:5173`, отладочный API включён |
| `npm run typecheck` | проверка типов (`tsc`, строгий режим) | только отчёт, файлов не создаёт |
| `npm test` | автотесты Vitest: ядро, генератор трека, рендер, звук, ввод, сохранение — в Node, без браузера | отчёт в терминале |
| `npm run test:watch` | те же тесты в режиме наблюдения | перезапуск при изменении файлов |
| `npm run build` | проверка типов и продакшен-сборка | `dist/` — `index.html` и `assets/` с относительными путями |
| `npm run build:single` | проверка типов и сборка одним файлом | `dist-single/index.html` — скрипты, стили и шрифты внутри; открывается с диска без сервера |
| `npm run build:play` | `build:single` и копия результата | `play/index.html` — тот же файл для публикации |
| `npm run preview` | локальный сервер для готовой сборки | содержимое `dist/` на `http://localhost:4173` |
| `npm run e2e` | сквозная проверка в Chromium (`scripts/e2e.mjs`) | строки PASS / FAIL / SKIP; код выхода 0 — без FAIL, 1 — есть FAIL, 2 — проверка не запустилась |

Сквозная проверка ходит по игре как игрок — клавишами, мышью, касаниями, сменой
размера окна — и читает состояние через отладочный API. Ей нужна запущенная игра
и пакет `playwright` со своим Chromium (в зависимости проекта он не входит):

```bash
npm i -D playwright && npx playwright install chromium   # один раз
npm run build && npm run preview                          # терминал 1
npm run e2e                                               # терминал 2
npm run e2e -- http://localhost:5173/                     # то же против npm run dev
```

По умолчанию проверяется `http://localhost:4173/?debug`. Параметры:
`--only=desktop,phone,progress,shop,panels,edge,fuzz` — выбрать сценарии,
`--seeds=1,2,3,4` и `--steps=150` — зёрна и длина случайного обхода экранов,
`--shots=ПАПКА` — снимок экрана при провале сценария, `--headed` — показать браузер.

## Управление

| Действие | Клавиатура | Мышь | Касание |
| --- | --- | --- | --- |
| Лететь влево / вправо | `←` `→` или `A` `D` — корабль плавно разгоняется и тормозит | корабль сам летит за курсором, нажимать не нужно | коснитесь экрана и ведите пальцем |
| Играть (в меню) | `Enter` или `Space` | кнопка «Играть» | кнопка «Играть» |
| Закрыть панель меню | `Esc` | крестик или клик по затемнению | крестик или тап по затемнению |
| Пауза / продолжить | `Esc` или `P` | кнопка паузы в углу экрана / «Продолжить» | кнопка паузы в углу экрана / «Продолжить» |
| Заново (на паузе) | `R` | «Заново» | «Заново» |
| В меню (на паузе) | `M` | «В меню» | «В меню» |
| Ещё раз (Game Over) | `Enter`, `Space` или `R` | «Ещё раз» | «Ещё раз» |
| Магазин / рекорды / меню (Game Over) | `S` / `L` / `Esc` | кнопки на экране | кнопки на экране |

Горячие клавиши определяются по положению клавиши, а не по букве, поэтому работают
в любой раскладке. Если на экране два пальца, кораблём управляет тот, что опустился
последним; когда его поднимают, управление возвращается к оставшемуся.

**Пауза.** Игра встаёт на паузу сама, когда окно теряет фокус или вкладку
сворачивают. Кадр под экраном паузы замирает; после паузы — отсчёт в два удара,
и только потом мир снова летит. Забег, брошенный с паузы («Заново», «В меню») или
закрытием вкладки, засчитывается: очки, кристаллы и место в таблице не пропадают.

Экран Game Over первые доли секунды не слушает клавиши и тапы — чтобы клавиша,
которую вы ещё держите после столкновения, не начала новый забег.

## Правила и очки

Корабль ходит только влево и вправо — дорога сама несётся навстречу. Каждый забег
начинается с такта вступления (READY… GO!).

**Препятствия.** Неоновый куб — самое частое. Циркулярная пила — широкая, но
тонкая. Лазерные ворота — луч поперёк всей дороги с одним проходом. На линии
корабля заранее загорается метка — там препятствие окажется в момент прилёта,
у ворот подсвечен проход. Генератор трека следит, чтобы проход был всегда.

**Очки.** Все начисления умножаются на множитель комбо и на бонус корабля.

| За что | Очки |
| --- | ---: |
| Каждая прожитая доля музыки | 5 × уровень скорости |
| Энергетическая сфера | 100 |
| Редкая сфера (крупнее, другого цвета) | 500 |
| Уклонение от препятствия | 20 |
| Пролёт впритирку — NEAR MISS | ещё 150 |

**Комбо и множитель.** Каждые 4 сферы подряд поднимают множитель на один:
x1 → x2 → … до x8. Пропущенная сфера или столкновение сжигают комбо до x1.
Множитель слышно: чем он выше, тем больше слоёв в музыке.

**OVERDRIVE.** На множителе x8 включается OVERDRIVE: все очки удваиваются, пока
комбо не сорвётся.

**Уровни скорости.** Каждые 15 секунд — ровно 8 тактов музыки — начинается новый
уровень: скорость растёт на 13 % (×1.00, ×1.13, ×1.26 … до ×3.00), сетка дороги
меняет цвет, экран встряхивает. Со 2-го уровня препятствия идут зигзагом и
появляются лазерные ворота, и чем выше уровень, тем у́же в них проход.

**Щит.** Корабли со щитом-призраком переживают одно столкновение за забег:
препятствие разбивается, комбо сгорает, а корабль 1,6 секунды неуязвим. Второе
столкновение — конец забега.

**Near miss.** Если препятствие прошло совсем рядом с корпусом, но не задело,
к очкам за уклонение добавляется бонус.

**Кристаллы.** Обычная сфера приносит 1 кристалл, редкая — 5. Редкая сфера
встречается с шансом 6 % (больше — с улучшением «Призма удачи»). Кристаллы
зачисляются в кошелёк в конце забега.

**Рекорд.** Как только счёт обгоняет прошлый лучший результат, вспыхивает
«NEW RECORD!». Пять лучших забегов попадают в таблицу рекордов — с датой и
временем, уровнем скорости, лучшим комбо и кораблём.

То же самое коротко показывает панель «Как играть» в главном меню.

Магазин открывается из главного меню и с экрана Game Over. Для старта дарится
150 кристаллов. Купленный корабль или тема сразу надеваются; переодеться можно
в любой момент.

**Корабли**

| Корабль | Цена | Что даёт |

| Neon Core — «Неоновое ядро» | бесплатно | стартовый корабль без особых систем |
| Neon Trail — «Неоновый шлейф» | 300 | хвост из светящихся частиц, +10 % к очкам |
| Magnet — «Магнит» | 450 | поле притягивает сферы рядом с кораблём |

| Singularity — «Сингулярность» | 2500 | шлейф, магнит и щит сразу, +15 % к очкам |

**Темы.** Тема меняет небо, солнце, горизонт, цвета дороги, препятствий и сфер,
а заодно акценты интерфейса.

| Тема | Цена | Горизонт |
| --- | ---: | --- |

**Улучшения.** У каждого три уровня, эффект уровней складывается.

| Улучшение | Цена уровней 1 / 2 / 3 | Эффект за уровень |

## Сохранение

Прогресс сохраняется автоматически в `localStorage` браузера под ключом
`neon-velocity-2/save/v1`: кристаллы, рекорд, таблица из пяти лучших забегов,
купленные и надетые корабли и темы, уровни улучшений, настройки (звук, громкость
музыки и эффектов, тряска экрана, счётчик FPS) и общая статистика.

- При загрузке проверяется каждое поле: повреждённое или отредактированное
  сохранение игру не роняет, неверные значения заменяются значениями по умолчанию.
- Две вкладки с игрой не затирают прогресс друг друга: изменения из одной вкладки
  подхватываются другой.
- «Настройки» → «Сброс прогресса» обнуляет кристаллы, покупки, рекорды и
  статистику (с подтверждением прямо в панели); настройки остаются.
- Если хранилище недоступно — приватное окно, запрет сайта, изолированный
  `<iframe>` — игра работает как обычно, но в меню и в настройках появляется
  предупреждение «Сохранение недоступно — прогресс не переживёт перезагрузку»:
  всё заработанное живёт до закрытия вкладки.

Ключ у второй редакции свой, поэтому с сохранением первой (`neon-velocity/save/v1`)
она не пересекается.

## Отладочный API

В режиме разработки (`npm run dev`) и в любой сборке, открытой с `debug` в адресе
(`?debug` или `#debug`), в странице есть объект `window.__NV__`. В обычной игре
его нет. Им пользуются сквозная проверка и инструменты баланса.

| Поле | Что это |
| --- | --- |
| `sim` | симуляция: читать `sim.state`, самому `step()` не вызывать |
| `screen()` | текущий экран: `'menu'`, `'playing'`, `'paused'`, `'gameover'` |
| `camera()` | актуальная камера — перевод координат дороги в экранные и обратно |
| `setInput(fn \| null)` | подменить ввод игрока функцией от состояния; `null` возвращает управление |
| `autopilot(on, options?)` | посадить за штурвал бота-планировщика игры; `false` — выключить |
| `takeEvents()` | события симуляции с прошлого вызова (сбор, уклонение, новый уровень, гибель…) |
| `counters()` | сколько тиков симуляции и кадров отрисовки прошло с загрузки |
| `resumeCount()` | отсчёт после паузы: сколько ударов мир ещё стоит (2, 1) или 0, если отсчёта нет |

Точные типы — в `src/debug.ts`.

## Как устроен проект

React отвечает за меню, магазин, HUD и оверлеи. Сама игра живёт вне React: цикл
`requestAnimationFrame` двигает симуляцию фиксированными тиками, раздаёт её
события звуку, рендеру и HUD и рисует кадр на Canvas 2D.

```
neon-velocity-2/
├── SPEC.md            спецификация — контракт проекта
├── index.html         страница-вход
├── scripts/e2e.mjs    сквозная проверка в браузере
└── src/
    ├── core/          ядро без DOM: тики и ритм, симуляция, генератор трека, столкновения,
    │                  бот и проверка проходимости, типы; config.ts — весь баланс
    ├── render/        камера (перспектива) и отрисовка на Canvas: небо, дорога, объекты, корабль, частицы
    ├── audio/         синтез музыки и звуков на Web Audio
    ├── input/         клавиатура, мышь и касания
    ├── state/         сохранение, чистые функции магазина и рекордов, хук useProgress
    ├── ui/            оболочка и экраны: GameHost (холст и цикл), HUD, пауза, Game Over, меню и панели
    │   ├── hud/       блоки HUD и баннеры
    │   ├── menu/      части меню и магазина, стили раскладок
    │   └── kit/       UI-примитивы: кнопки, панель, оверлей, форматирование
    ├── App.tsx        экраны, горячие клавиши, прогресс
    ├── debug.ts       отладочный API
    └── index.css      Tailwind 4, шрифты, токены цветов
```

Подробности — в [SPEC.md](SPEC.md): схема слоёв и цикла (раздел 1), файлы и их
владельцы (2), мир и время (3), симуляция (4), генератор трека (5), рендер (6),
звук и ввод (7), оболочка и HUD (8), меню (9), требования, выросшие из ошибок
первой редакции (10), задание заказчика (11) и правила кода (12). Перед сдачей
изменений обязательны `npm run typecheck` и `npm test`.

**Стек:** React 19, TypeScript 7, Tailwind CSS 4, Framer Motion 13, Lucide React,
HTML5 Canvas 2D, Web Audio API, Vite 8, Vitest 5. Шрифты JetBrains Mono и Orbitron
подключены локально.

## Чем архитектура отличается от первой редакции

Первая редакция лежит рядом, в [`../neon-velocity`](../neon-velocity). Задание
заказчика у обеих одно, устройство — разное.

| | Первая редакция | Вторая редакция |
| --- | --- | --- |
| Игровое поле | плоское: объекты падают сверху вниз по центральной колонке экрана, перспективная сетка — фон | дорога в перспективе: сетка — сама трасса, объекты выходят из дымки у горизонта и растут по мере приближения |
| Мир и экран | ширина мира 480 единиц, высота мира считается от высоты экрана | мир — дорога 100 × 400 единиц; размер и поворот экрана касаются только камеры (`src/render/camera.ts`) |
| Время | `update(dt)` с переменным шагом кадра, дробление на подшаги не длиннее 1/120 с | целые тики по 1/128 с: 60 тиков — доля, 1920 тиков — уровень скорости, ровно 15 с и 8 тактов |
| Положение объектов | накапливается шаг за шагом | вычисляется как функция тика (`src/core/motion.ts`) |
| Темп музыки | растёт с уровнем скорости | постоянный, 128 ударов в минуту; с уровнем растёт скорость подлёта |
| Случайность | `Math.random` | генератор с зерном: забег — функция зерна и ввода, без DOM, `Date` и `Math.random` |
| Препятствия | генератор на каждой доле решает, что выпустить | трек строится фразами по 8 тактов, ведёт «коридор» достижимых позиций и проходит проверку проходимости ботом |
| Эффекты | частицы и тряска — часть состояния движка | симуляция только сообщает события; частицы, тряска, вспышки, звук и баннеры строятся по ним в рендере, звуке и HUD |
| Музыка и игра | слои аранжировки добавляются с уровнем скорости | слои аранжировки включает множитель комбо, сферы играют ноты мелодии |
| Автопроверка | проверка типов | проверка типов, автотесты Vitest (включая приёмочные тесты симуляции, трека и сохранения) и сквозная проверка в браузере |
| Каталоги | `src/game`, `src/components`, `src/state` | `src/core`, `src/render`, `src/audio`, `src/input`, `src/state`, `src/ui` |
| Ключ сохранения | `neon-velocity/save/v1` | `neon-velocity-2/save/v1` |
