# Сборщик презентаций «Твой урок»

Детерминированная половина пайплайна: **JSON-дек → нативный PPTX → PDF**.
Ключи API и сеть не нужны — этой части всё равно, кто написал текст, LLM или
человек. LLM-слой подключается позже и отдаёт ровно этот же JSON.

```
описание слайдов (JSON)  →  [валидаторы]  →  [замер текста]  →  PPTX  →  PDF
        ↑                                                            
   позже сюда встанет LLM (Claude через AITunnel) + RAG по учебнику
```

## Запуск

```bash
pip install -r requirements.txt
# системное: fonts-paratype (PT Sans/Serif), libreoffice-impress, poppler-utils

python -m generator.cli fixtures/vasiliy-iii.json -o out/deck.pptx --pdf
python -m generator.cli fixtures/vasiliy-iii.json --fgos          # отчёт о соответствии ФГОС
python -m generator.cli fixtures/vasiliy-iii.json --prompt-layer  # слой ФГОС для промпта
python -m generator.cli fixtures/vasiliy-iii.json --fgos-brief    # задание ФГОС-инспектору
python -m generator.cli fixtures/vasiliy-iii.json --schema        # JSON Schema для LLM

python -m tests.test_pipeline   # 34 проверки рендера
python -m tests.test_fgos       # 122 проверки соответствия ФГОС
```

Флаг `--strict` останавливает сборку при ошибках валидации и при
несоответствии ФГОС (для CI).

## Что внутри

| Файл | Роль |
|---|---|
| `generator/schema.py` | контракт «LLM ↔ рендерер»: роли слайдов, лейауты, лимиты |
| `generator/themes.py` | дизайн-система: палитры, шрифтовые пары, кегли |
| `generator/textfit.py` | замер текста по TTF — замена несуществующему autofit |
| `generator/validators.py` | пословные и типографские линтеры, дедупликация |
| `generator/render.py` | сборка PPTX: лейауты, bold-раны, слоты картинок |
| `generator/cli.py` | командная строка, конвертация в PDF |
| `fgos/registry.py` | реестр ФГОС: выборка требований по {предмет, класс, тема} |
| `fgos/check.py` | проверка дека, отчёт учителю, задание ФГОС-инспектору |
| `fgos/data/*.json` | выдержки из федеральных рабочих программ (версионированные) |
| `fixtures/vasiliy-iii.json` | эталонный дек для проверки (см. ниже) |

## Соответствие ФГОС — проверяемое, а не декларируемое

Три уровня, разделение труда принципиальное:

1. **Реестр — детерминированный.** Текст стандарта нормативный, его нельзя
   «вспоминать» моделью: на вопрос «что требует ФГОС по истории в 7 классе»
   любая LLM выдаст правдоподобную выдумку. Данные берутся из федеральных
   рабочих программ (edsoo.ru) и версионируются: у каждого файла есть дата
   извлечения и срок сверки редакции — ФРП правятся приказами Минпросвещения
   (в т.ч. № 729 от 08.10.2025, № 808 от 10.11.2025; изменения в ФООП
   с 01.09.2026).

   Насколько это не теория: между редакциями 2023 и 2025 гг. курс истории
   России 6 класса был продлён до первой трети XVI в., и темы «Василий III»,
   «приказная система», «Боярская дума» переехали из 7 класса в 6.
   Реестр, собранный по устаревшей редакции, уверенно давал бы неверный
   вердикт — поэтому срок сверки (`revision_check_due`) обязателен.
2. **Механические проверки** (`fgos/check.py`) — бесплатные и точные:
   соответствие темы классу, обязательные понятия и даты (с учётом склонений),
   анахронизмы периода, охват планируемых результатов типами слайдов, уровни
   вопросов. Работают без ключей.
3. **ФГОС-инспектор** — отдельная модель, подключается с ключами. Судит то,
   что регэкспом не проверить: раскрыта ли единица по смыслу, методическая
   логика урока, и — главное — **анахронизмы на изображениях** (нужна модель
   со зрением). Задание для неё готовит `check.brief()`.

Результат — «Отчёт о соответствии ФГОС», который учитель может приложить
к уроку: какие дидактические единицы раскрыты, какие нет, на какие
планируемые результаты работает материал.

### Режимы: ФГОС можно выключить

Привязка к программе нужна не всем — репетитору, кружку, авторскому курсу
или уроку «для интереса» она мешает. Поэтому это не тумблер, а три режима
(`meta.fgos_mode`, флаг `--fgos-mode`):

| Режим | Требования в промпт | Отчёт | Достоверность |
|---|---|---|---|
| `full` (дефолт) | да, полный слой | да, блокирует при ошибках | да |
| `check` | нет — генерацию не ограничиваем | да, справочный, ничего не блокирует | да |
| `off` | нет | нет | **да** |

Ключевое: **проверка фактической достоверности остаётся во всех режимах.**
Запрет называть Василия III царём и границы эпохи для иллюстраций — это не
требование стандарта, а отсутствие вранья. Учителю, которому программа
безразлична, ошибка в титуловании нужна ещё меньше. В режиме `off` в промпт
уходит только компактный блок «достоверность эпохи», а отчёт называется
«Проверка достоверности» и честно сообщает, что программа не проверялась.

В режиме `check` несоответствие класса понижается до предупреждения: учитель
мог сознательно взять тему с опережением или на повторение.

| Литературное чтение | 1–4 | 8 |
| Литература | 5–9 | 14 |
| Математика (+ алгебра, геометрия) | 1–4, 5–9 | 23 |
| Окружающий мир | 1–4 | 9 |
| История | 5–9 | 17 |
| Обществознание | 6–9 | 9 |
| География | 5–9 | 11 |
| Биология | 5–9 | 13 |
| Физика | 7–9 | 10 |
| Химия | 8–9 | 7 |
| Информатика | 7–9 | 8 |

У русского языка и математики две программы (начальная и основная школа) —
нужная выбирается по классу. Синонимы названий учтены: «алгебра»,
«геометрия» и «вероятность и статистика» ведут в математику 5–9, «чтение» —
в литературное чтение.

Глубина проработки разная: 8–9 классы обществознания и географии заданы
укрупнённо, это помечено в `scope_note` соответствующих файлов. Не покрыты
пока 10–11 классы, иностранные языки, ИЗО, музыка, труд, ОБЗР, физкультура.
Непокрытый предмет не ломает пайплайн — проверка просто возвращает
«не покрыт».

Живой пример на эталонном деке: тема «Правление Василия III» по действующей
редакции относится к 6 классу — дек и оригинал Дарьи заявлены верно. Отчёт
при этом показывает пробелы: не раскрыты отношения с Крымским и Казанским
ханствами, нет слайда с исторической картой (а работа с картой — отдельный
планируемый результат).

## Ключевые решения

**Autofit в python-pptx не существует.** `MSO_AUTO_SIZE.TEXT_TO_FIT_SHAPE` —
только XML-флаг; пересчёт кегля делает сам PowerPoint при открытии файла
(issues #973/#715). Наш конвейер отдаёт PPTX сразу в LibreOffice, файл никто
не «открывает» — поэтому кегль подбираем сами (`textfit.fit_size`:
ступенчатое снижение 17→13 pt, флаг переполнения для ретрая слайда).

**Текст всегда живой.** Картинки — только иллюстративный слот без текста
внутри; заголовки, подписи, ярлыки схем рендерим нативными текстбоксами.
Это разом закрывает опечатки в растре, редактируемость и доступность.
Проверяется тестом: текст извлекается из готового PDF.

**Схема плоская** (без `anyOf`/`oneOf`): GigaChat и часть провайдеров
structured output не поддерживают union-конструкции, а схема должна работать
одинаково у всех моделей роутера.

**Тема — это конфиг, а не перевёрстка.** Один и тот же JSON собирается в
любой из пяти тем (`manuscript`, `edu_flat`, `clay`, `board_game`, `neutral`).

**Гигиена файла:** холст всегда 16:9, чистые метаданные (title = тема,
author = учитель), alt-тексты на картинках, настоящий bold вместо имитации.

## Эталонный дек

`fixtures/vasiliy-iii.json` — реальная презентация Дарьи Прониной
(`darya-pronina-site/assets/materials/pravlenie-vasiliya-iii.pdf`),
пересобранная в наш формат. Исправлены дефекты оригинала:

| Было в оригинале | Стало |
|---|---|
| 9 из 12 слайдов без заголовков | заголовок на каждом слайде (проверяется валидатором) |
| «в царской семье» при Василии III | «в великокняжеской семье» + пояснение про титул 1547 г. |
| «служивых иноземцев» | «служилых иноземцев» |
| сравнение сплошным текстом | слот `compare` с двумя колонками и выводом |
| нет вопросов и домашнего задания | добавлены слайды `quiz` и `homework` |
| холст 720×405, текст в растре | 16:9, весь текст живой |

Это же и кейс «до/после» для витрины: тот же материал, но редактируемый.

## Чего здесь пока нет

- **Генерации текста** — ждёт ключ AITunnel (Claude Sonnet 5 / Opus 4.8).
- **Генерации картинок** — ждёт ключ Yandex Cloud (YandexART). Сейчас слот
  рисуется оформленным плейсхолдером в палитре темы; при подключении модели
  геометрия слайда не изменится.
- **RAG по учебнику** — локальная `multilingual-e5-large`.
- **Схем нативными фигурами** (процесс, оргсхема, mind-map) — есть таймлайн
  и сравнение, остальные типы по мере надобности.

Конфигурация моделей — в `docs/tvoy-urok/model-stacks.md`,
обоснование выбора провайдеров — в `docs/tvoy-urok/generation-tools-and-keys.md`.
