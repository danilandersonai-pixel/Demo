# Навыки моделей: по одному на роль в пайплайне

Каждая модель в конвейере получает **свою компактную инструкцию** — навык.
Не общий промпт на всех, а роль-специфичный: автору не нужны критерии
проверяющего, дешёвой модели не нужна драматургия урока.

Это не «ещё один длинный промпт». Смысл в трёх вещах, и все три — про деньги
и качество:

**1. Кэш.** Навык — байт в байт одинаковый текст на каждом вызове, поэтому
уходит в кэшируемый префикс промпта. Чтение из кэша стоит **0,1× от входа**.
Схема дека (12 КБ) + навык + слой ФГОС — это и есть тот стабильный префикс,
за который иначе платили бы полную цену каждый раз.

**2. Меньше переделок.** Точная инструкция — меньше брака на выходе. У нас
заложено до 3 точечных ретраев на дек; каждый сэкономленный ретрай дороже,
чем весь навык.

**3. Дешёвая модель тянет больше.** Чем точнее сказано, что делать, тем ниже
класс модели, которого достаточно. Часть работы уезжает с Opus на DeepSeek.

## Роли

| Навык | Кто исполняет | Что делает |
|---|---|---|
| `author.md` | Opus 4.8 (премиум) / Sonnet 5 (стандарт) | план дека и содержание слайдов |
| `reviewer.md` | Sonnet 5 (премиум) / Haiku 4.5 (стандарт) | ищет брак: факты, возраст, методика |
| `fgos-inspector.md` | Sonnet 5 **со зрением** | соответствие программе + анахронизмы на картинках |
| `illustrator.md` | тот, кто пишет промпт (автор или helper) | формулировки для YandexART / GPT Image 2 |
| `helper.md` | DeepSeek V4 Flash | alt-тексты, подписи, сокращения |

Модель под роль выбирается пресетом (`docs/tvoy-urok/model-stacks.md`), сам
навык от модели не зависит — меняется только исполнитель.

## Чего в навыках намеренно НЕТ

- **JSON-схемы дека.** Она генерируется из `generator/schema.py` и
  подставляется загрузчиком. Продублируй её в тексте навыка — и через месяц
  она разойдётся с кодом.
- **Требований ФГОС.** Они детерминированно выбираются реестром по
  {предмет, класс, тема} — см. `fgos/registry.prompt_layer()`.
- **Норм объёма числами.** Они живут в `generator/validators.py` и
  подставляются загрузчиком оттуда же, откуда их потом проверяют. Один
  источник истины на инструкцию и на проверку.

Правило простое: если что-то проверяется кодом — в навыке об этом говорится
словами, а числа приходят из кода.

## Порядок сборки промпта

Собирает `loader.py`. Порядок — по убыванию стабильности, это и есть условие
работы кэша (он префиксный: меняется байт — инвалидируется всё после него):

```
1. навык роли          — меняется при релизе          ┐ кэш-блок 1
2. JSON-схема дека      — меняется при релизе          ┘
3. слой ФГОС            — на пару {предмет, класс}     ┐ кэш-блок 2
4. возрастной профиль   — на класс                     ┘
5. тема, пожелания, SOURCE — своё на каждый запрос     ← без кэша
```

Тихие убийцы кэша, которых загрузчик избегает: дата/время в тексте, `json.dumps`
без `sort_keys`, условные куски инструкции, разный набор навыков между
вызовами. Диагностика: если в ответе `cache_read_input_tokens == 0` на
повторном запросе — что-то в префиксе поехало.

## Использование

```python
from skills.loader import build_prompt

blocks = build_prompt(
    role="author",
    subject="История России", grade=6,
    topic="Правление Василия III",
    fgos_mode="full",
    wishes="сделать акцент на присоединении Пскова",
    source_chunks=[...],          # выборка RAG по учебнику
)
# blocks — список content-блоков с проставленным cache_control,
# готовый к отправке в Messages API
```

Навыки — обычный текст. Правятся как код: через ревью и с тестами
(`tests/test_skills.py` следит, чтобы они не разошлись со схемой и нормами).
