# Приложения

## Приложение A. Команды, которые стоит знать

Отобранный минимум из справочника автора; полный перечень смотрите через `/` в
сессии и `claude --help` в оболочке. **Интерактивные команды и флаги оболочки —
это разные интерфейсы.**

### Диагностика и настройка

| Команда | Назначение |
|---|---|
| `/doctor` | Проверка установки и конфигурации; в оболочке `claude doctor` |
| `/config` | Открыть настройки или задать отдельный ключ (псевдоним `/settings`) |
| `/status` | Какой источник управляемой политики выбран на самом деле |
| `/login` · `/logout` | Аутентификация, смена аккаунта, выход |
| `/model` · `/effort` · `/fast` · `/advisor` | Модель, уровень усилия, быстрый режим, модель-советник |

### Расход и контекст

| Команда | Назначение |
|---|---|
| `/usage` | Стоимость, лимиты, активность (псевдонимы `/cost`, `/stats`) |
| `/context` | Состав контекста — для диагностики, а не для погони за числом |
| `/compact [инструкции]` | Сжать разговор. **С потерями** — говорите, что обязано уцелеть |
| `/autocompact` | Задать окно автосжатия |
| `/clear` | Пустой контекст, новый разговор. **Снимает цель и задачи по расписанию** |

### Безопасность и контроль

| Команда | Назначение |
|---|---|
| `/permissions` | Правила allow/ask/deny. Порядок: **deny → ask → allow** |
| `/sandbox` | Панель песочницы (не на нативной Windows) |
| `/hooks` | Просмотр настроенных хуков, только чтение; показывает файл-источник |
| `/plan` | Войти в режим плана |
| `/rewind` | Откатить код и разговор к чекпойнту. **Не отменяет внешних эффектов** |
| `/diff` | Интерактивный просмотр диффа перед коммитом |

### Знание о проекте

| Команда | Назначение |
|---|---|
| `/init` | Черновик стартового `CLAUDE.md` — прочитать и сократить |
| `/memory` | Правка файлов инструкций, переключатель авто-памяти |
| `/add-dir` · `/cd` | Добавить рабочий каталог; переместить сессию |
| `/export` | Экспорт разговора текстом — **поддерживаемый артефакт аудита** |

### Сессии и делегирование

| Команда | Назначение |
|---|---|
| `/resume` · `/rename` · `/branch` | Управление сессиями |
| `/fork` · `/subtask` | Копия в фоновую сессию; форк-сабагент (**наследует разговор**) |
| `/background` | Отсоединить сессию (псевдоним `/bg`) — **уносит задачи `/loop` с собой** |
| `/list-agents` | Сабагенты, участники команды, другие сессии (псевдоним `/peers`) |
| `/agents` | Указания по файлам агентов (**больше не редактор**) |

### Расширения и автономия

| Команда | Назначение |
|---|---|
| `/mcp` | Осмотр и аутентификация MCP-серверов |
| `/plugin` · `/reload-plugins` | Управление плагинами — **сперва оценить риск произвольного кода** |
| `/chrome` | Настройка подключения браузера |
| `/goal` · `/goal clear` | Постоянное условие завершения |
| `/loop [интервал] [промпт]` | Повторяющийся промпт в пределах сессии. **Голый `/loop` запускает промпт обслуживания** |
| `/schedule` | Облачные рутины (псевдоним `/routines`) |
| `/workflows` · `/deep-research <вопрос>` | Прогресс воркфлоу; встроенный исследовательский воркфлоу |
| `/remote-control` · `/teleport` | Удалённое наблюдение; забрать облачную сессию в терминал |

### Ревью

| Команда | Назначение |
|---|---|
| `/code-review` | Ревью диффа или PR (псевдоним `/review`; `ultra` — облачный проход) |
| `/security-review` | Проход по безопасности ветки — **не замена специалисту** |
| `/verify` | Запустить и наблюдать проверку |

## Приложение E. Чек-лист выпуска

### До задачи

```
[ ] Подтверждены машина, аккаунт, организация, проект, репозиторий и ветка
[ ] Рабочий каталог узкий; это не домашний каталог
[ ] Есть чистая база или восстановимая резервная копия
[ ] Нет секретов в промптах, в файлах области работы и в контроле версий
[ ] Правила разрешений следуют минимуму прав, и вы проверили, что deny блокирует
[ ] Песочница и защита учётных данных включены, где поддерживаются
[ ] Внешние сервисы используют тестовые аккаунты или аккаунты с минимумом прав
[ ] Сторонние скиллы, плагины, маркетплейсы, MCP-серверы, каналы, хуки и
    скрипты просмотрены
[ ] Шлюзы одобрения человеком записаны в план
[ ] Явно заданы границы по токенам, времени, ходам и числу агентов
[ ] Для делегируемого ревьюера понятны режим форка и наследование разрешений
```

### Во время задачи

```
[ ] Первые вызовы инструментов соответствуют задуманному направлению
[ ] Каждый запрос разрешения понят до одобрения
[ ] Неожиданный доступ к сети, учётным данным, пакетам или аккаунтам
    останавливает задачу
[ ] Действия в браузере остаются в одобренном профиле и наборе доменов
[ ] У параллельных сессий изолированные зоны ответственности или worktree
[ ] Существенные решения и находки записываются в файлы
[ ] Устаревшая цель или цикл не конкурируют с текущей задачей
[ ] Межагентные сообщения трактуются как координация, но не как одобрение
```

### Перед выпуском

```
[ ] Дифф просмотрен файл за файлом
[ ] Автоматические проверки действительно выполнялись, и их вывод осмотрен
[ ] Поведение или рендеринг наблюдались напрямую
[ ] Независимое ревью проведено — и подтверждено, что оно независимо
[ ] Внешние побочные эффекты перечислены, включая опубликованное и отправленное
[ ] Ссылки и цитаты проверены
[ ] Нет секретов в выводе, логах, артефактах и цитатах из транскрипта
[ ] Публикация, слияние, push, платёж или смена аккаунта одобрены отдельно
[ ] Известны путь отката и владелец наблюдения
```

## Приложение F. Модель угроз (выдержка)

| Угроза | Вектор | Основной контроль | Дополнительный контроль |
|---|---|---|---|
| Непрямая инъекция промпта | Веб-страница, вывод инструмента, комментарий к PR, полезная нагрузка срабатывания, сообщение канала | Изолированный контекст веб-загрузки; обёртки недоверенного ввода; проверка межагентных сообщений классификатором | Явная цель и список разрешённых доменов; шлюз человека на внешнюю запись |
| Раскрытие учётных данных | Чтение `.env`, вывод команды, транскрипт, артефакт | Deny-правила; deny или mask учётных данных в песочнице | Ключи с минимумом прав; ротация; дисциплина вывода |
| Цепочка поставок | Скилл, плагин, маркетплейс, MCP-сервер, канал | Ревью до установки; закрепление проверенной версии | Изолированный профиль для проверки; учёт владельца и процедуры удаления |
| Неконтролируемая автономия | Рутина со всеми коннекторами; `bypassPermissions`; устаревшая цель | Шлюзы человека на необратимое; изолированная среда | Границы по ходам и времени; чтение транскрипта, а не индикатора |

## Приложение L. Модель зрелости внедрения (предложение автора)

Пять уровней организационной способности, у каждого — свои принудительные
контроли, требуемое свидетельство и ответственный владелец. Автор прямо
оговаривает, что это **его собственная конструкция**, предложенная как средство
упорядочивания, и она не проверялась эмпирически.

Порядок вопросов для решения — тот же, что в главе 32: режим разрешений по
умолчанию и кто его меняет → принудительность песочницы → допустимые коннекторы,
плагины и маркетплейсы → допустимость автономного выполнения и чьё одобрение →
что покидает периметр и на каких условиях хранения → кто отвечает, когда агент
действует.

## Приложение K. Повторная сверка

Автор предлагает пересверять книгу **ежеквартально** либо перед тем, как
опереться на неё в значимом решении, и записывать изменения в реестр
свидетельств.

Практический минимум для читателя этого издания: перед тем как положиться на
конкретное имя настройки, флаг или числовой лимит — открыть официальную
документацию и сверить. Дисциплина и категории рисков из этой книги устареют
нескоро; номера версий и имена ключей — быстро.
