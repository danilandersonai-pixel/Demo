# Neon Velocity II: Rhythm & Dodge — спецификация

Неоновая ритм-аркада на рекорд. React 19 + TypeScript + Tailwind CSS 4 + Framer Motion +
Lucide React; игра рисуется на HTML5 Canvas 2D, звук синтезируется Web Audio, прогресс
лежит в `localStorage`. Сборка — Vite 8, автотесты — Vitest.

Это вторая, заново спроектированная версия игры из `../neon-velocity`. Задание заказчика то же
(раздел 11), но три решения принципиально другие:

1. **Дорога в перспективе.** Сетка — не фон, а трасса. Корабль внизу экрана, препятствия
   выходят из дымки у горизонта и несутся к нему по дороге, вырастая по законам перспективы.
2. **Ритм — это механика.** Темп 128 BPM, поэтому «каждые 15 секунд» из задания — ровно
   8 тактов. Всё прилетает в долю, сферы играют мелодию, множитель комбо добавляет слои музыки.
3. **Детерминированное ядро.** Симуляция — чистая функция от зерна и ввода: фиксированный тик
   1/128 с, свой генератор случайных чисел, никакого DOM. Поэтому её проверяют автотесты.

## 1. Схема

```
App.tsx — экраны, клавиши, прогресс (useProgress ⇄ localStorage)
└─ <GameHost>  холст на весь экран, всегда смонтирован (z-0)
     цикл requestAnimationFrame с фиксированным шагом:
       acc += dt · state.timeScale
       пока acc ≥ TICK_DT:  sim.step(input.frame());  acc −= TICK_DT        (не больше 8 тиков за кадр)
       события sim.drainEvents() → audio.onEvent(e, late) + renderer.onEvent(e) + баннеры HUD + колбэки App
       renderer.render({ state, alpha = acc / TICK_DT, … })
       hudStore.setSnapshot(sim.hud())            (≤ 30 раз/с и сразу после важных событий)
└─ <Hud> (z-10) · <DeathFlash> (z-20) · <MainMenu> / <PauseOverlay> / <GameOverOverlay> (z-30)
└─ <Shop> / <Leaderboard> / <SettingsPanel> / <HowToPlay> (z-40) · <ScreenFx> (z-50)
```

Экран приложения (`Screen`): `menu → playing ⇄ paused → gameover`. Холст живёт всегда:
в меню на нём фоновая сцена `attract`.

## 3. Мир и время

- Дорога — плоскость: `x` поперёк, 0…`WORLD.roadW` (100); `z` вдоль, вперёд от корабля.
  Корабль стоит на линии удара `z = 0` и ездит только по `x` в пределах `[edge, roadW − edge]`.
  Объекты появляются на `z = WORLD.zFar` (400) и уходят за корабль до `z = −WORLD.zBehind`.
- Время — целые тики, 128 в секунду (`timing.ts`). Доля = 60 тиков, шестнадцатая = 15,
  такт = 240, уровень скорости = 8 тактов = 1920 тиков = 15.000 с.
- Забег стартует с `tick = −240` (такт вступления READY); `tick = 0` — GO и первая доля.
- Положение объекта не накапливается, а вычисляется: `z = zFar · (arriveTick − t) / approachTicks`,
  `x = spec.x + swayOffset(…)` (`motion.ts`). `arriveTick` всегда на сетке шестнадцатых — объект
  пересекает линию корабля точно в ритм. `approachTicks = approachTicksForLevel(уровень в момент прилёта)`,
  поэтому поздние объекты никогда не обгоняют ранние.
- Скорость растёт на 13 % за уровень: подлёт 300 тиков (2.34 с) на 1-м уровне → 100 тиков (0.78 с) на пределе.
- Экран ни на что в симуляции не влияет: разрешение, ориентация и поворот телефона — дело
  только камеры. (В первой версии поворот экрана мог убить игрока — здесь такого класса ошибок нет.)

## 4. Симуляция (`sim`)

`Simulation` — без DOM, без `Math.random`, без `Date`/`performance`. Случайность — только
`createRng(seed)`. Один `step()` = один тик. Приёмочные тесты — `src/core/sim.contract.test.ts`;
они обязаны проходить без правки самих тестов.

**Режимы.** `attract` (фон меню) · `ready` (`tick < 0`) · `playing` · `dying` · `over`.

**`startRun(seed, loadout, chart?)`**: `tick = −LEAD_IN_TICKS`, режим `ready`, корабль в центре,
`shield = shieldMax = loadout.shieldCharges`, очередь событий очищается и сразу получает `ready`
и `beat` первого тика. Трек по умолчанию — `createChart(seed, { rareChance: loadout.rareChance })`.

**Порядок одного тика (`step`)**:
1. `tick += 1`; пересчёт `level`, `speedMult`, `levelProgress` (`timing.ts`, `config.ts`).
2. `tick === 0` → режим `playing`, событие `go`. `tick > 0` и кратен 1920 → событие `levelUp`.
   Тик кратен 60 → событие `beat` (во всех режимах). В `playing` на доле с `tick > 0` начисляются
   очки за выживание.
3. Запрос тактов у трека: такт `b` запрашивается один раз, как только
   `tick ≥ b·240 − GAME.approach.base − 240` (при старте забега сразу запрашиваются такты 0 и 1).
   Элементы превращаются в сущности через `makeObstacle` / `makeCrystal` (сфере даётся `note` —
   порядковый номер с начала забега) и ждут своего `spawnTick`; в `state.obstacles` /
   `state.crystals` попадают только уже появившиеся объекты.
4. Движение корабля (ниже). `prevX` = x до движения.
5. Магнит, подбор и пропуск сфер.
6. Столкновения, затем разрешение уклонений.
7. Удаление объектов с `z < −WORLD.zBehind`. Число объектов не превышает `GAME.limits`.

В `dying` и `over` корабль не управляется, очки, подборы и столкновения не считаются, мир
продолжает лететь; в `over` новые такты не запрашиваются. `timeScale` = `GAME.death.timeScale` в
`dying`, иначе 1 (замедление реализует хост, тики остаются тиками).

**Корабль.**
- Указатель (`source === 'pointer'`, `pointerX !== null`):
  `vx = clamp((pointerX − x) · pointerFollow, ±pointerMaxSpeed)`, затем `x += vx · TICK_DT`.
  Формула точная — на неё опирается бот.
- Клавиатура (`source === 'keyboard'`): `vx += axis · accel · TICK_DT`; при `axis === 0` скорость
  гаснет `vx *= exp(−friction · TICK_DT)` (ниже 0.01 — ноль); предел `±maxSpeed`; `x += vx · TICK_DT`.
- `source === 'none'`: как клавиатура с `axis = 0`.
- `x` зажимается в `[edge, roadW − edge]`; у стены `vx = 0`. `bank` плавно следует за
  `vx / maxSpeed`, всегда в `[−1, 1]`.

**Сферы.** Для «живой» сферы с глубиной `z` и `x = crystalX(c, tick)`:
- магнит (если `magnetRadius > 0`, до прилёта осталось ≤ `magnet.leadTicks` тиков и
  `|x − player.x| ≤ magnetRadius`): `prevPull = pull`, затем `pull` сдвигается к кораблю не
  быстрее `magnet.pullSpeed` (сила плавно спадает к краю радиуса). Без магнита `prevPull = pull`;
- подбор: `|z| ≤ pickupReach(rare)` и `|x − player.x| ≤ pickupReach(rare)` → `state = 'taken'`,
  `chain += 1`, `multiplier = multiplierForChain(chain)`; если множитель вырос — `comboUp`; если
  стал максимальным — `overdrive { on: true }`; очки считаются уже с новым множителем; валюта
  `currency | rareCurrency × crystalYield`; событие `collect` (в нём `x` — X сферы);
- пропуск: `z < −pickupReach(rare)` → `state = 'missed'`, событие `miss`; если `chain > 0` —
  `comboBreak { reason: 'miss', lost: множитель до сброса }`, `chain = 0`, `multiplier = 1`, а
  если шёл OVERDRIVE — ещё и `overdrive { on: false }` на том же тике.

**Столкновения** (`collision.ts`): для каждого не разрешённого и не разбитого препятствия
берётся `contactAt` в моменты `tick − 0.5` и `tick` (защита от «проскока» на высокой скорости).
- `inRange` и `clear < 0`: если `invulnTicks > 0` — ничего; если `shield > 0` — щит:
  `shield −= 1`, `invulnTicks = GAME.shield.invulnTicks`, препятствие `destroyed = resolved = true`,
  события `shieldBreak`, затем (при `chain > 0`) `comboBreak { reason: 'hit' }` и сброс комбо
  (и `overdrive off`); иначе — смерть: событие `death`, режим `dying`, `player.alive = false`.
- `inRange` и `clear ≥ 0`: `minClear = min(minClear, clear)`.
- Объект ушёл за линию (`z < −depthReach`) и не разбит → `resolved = true`, `dodged += 1`,
  событие `dodge`; `near = minClear < GAME.nearMissClear` (и тогда `nearMisses += 1`).
- `invulnTicks` уменьшается на 1 за тик.
- Через `GAME.death.ticks` тиков после `death` — событие `gameOver` с итогом, режим `over`.

**Очки.** Любое начисление: `round(база × multiplier × (overdrive ? overdriveBonus : 1) × (1 + scoreBonus))`,
счёт всегда целый. Базы: доля — `perBeat × level`; сфера — `crystal` / `rareCrystal`;
уклонение — `dodge` (+ `nearMiss`, если впритирку).
Как только `score > highscore` и `highscore > 0` — один раз за забег `newRecord`.

**Итоги.** `result()` — после `gameOver`. `abandon()` — игрок бросил забег: в режимах
`ready` / `playing` / `dying` переводит забег в `over` без события `gameOver` и возвращает итог,
либо `null`, если `tick ≤ 0` или не заработано ничего (`score === 0` и сфер нет); в остальных
режимах — `null`. `duration` — тик смерти (или текущий) / 128. `crystals = floor(runCrystals)`.

**`startAttract(seed)`**: `tick = 0`, трек `createChart(seed, { …, attract: true })`, корабль ведёт
автопилот (плавно объезжает препятствия и подбирает сферы — можно на основе `planMove`), без
очков, столкновений и событий, кроме `beat`. Сцена должна выглядеть живой за меню.

## 5. Генератор трека (`chart`)

`createChart(seed, options)` → `ChartSource`. Приёмочные тесты — `src/core/chart.contract.test.ts`.

Трек строится как музыка — фразами. Уровень = 8 тактов:

| Такты уровня | Роль | Что прилетает |
| --- | --- | --- |
| 1–2 | вступление фразы | умеренно: одиночные кубы и пилы, длинные цепочки сфер |
| 3–4 | развитие | плотнее: пары, «лесенки», первые лазерные ворота уровня |
| 5–6 | пик | самые плотные паттерны, зигзаги, синкопы на шестнадцатых |
| 7 | передышка | почти без препятствий, щедрая «змейка» сфер — шанс поднять комбо |
| 8 | разгон к дропу | нарастающий ряд к сильной доле; финал — ворота или коридор |

Паттерны выбираются с весами по уровню (`OBSTACLES[kind].weight…`): одиночный объект; пара с
проходом; «лесенка» из 3–4 мелких кубов по восьмым; «стена» из пил с одним окном; лазерные
ворота (со 2-го уровня, проход `laserHalfGapForLevel`); «слалом» — чередование сторон; на высоких
уровнях — шестнадцатые. Со 2-го уровня часть объектов получает `sway` (`swayChance`, `swayAmp`,
`swayPeriodTicks`); **точка прилёта при этом остаётся `spec.x`**.

Сферы идут цепочками по 4–8 штук на восьмых (иногда шестнадцатых) вдоль плавной кривой —
это мелодия, которую «играет» игрок. Редкая сфера — с шансом `rareChance`.

**Честность — обязательна и проверяется тестом.**
- Генератор сам ведёт «коридор»: множество позиций, достижимых кораблём на скорости
  `GAME.fairness.assumedSpeed`, шаг за шагом сужается препятствиями и расширяется временем.
  Паттерн, после которого коридор уже `GAME.fairness.minGap` или рвётся, перестраивается или
  отбрасывается. Итог обязан проходить `verifyChart` с запасом 1 единица.
- Сферы ставятся только внутри коридора и не ближе запаса к препятствиям: каждую сферу можно
  взять, не разбившись, а соседние сферы цепочки достижимы друг за другом.
- Объект целиком остаётся на дороге весь путь, включая размах зигзага.
- Первые две доли забега пусты; в первом такте — только сферы.
- Плотность растёт с уровнем, но такт никогда не содержит больше 12 препятствий.
- Детерминизм: только `createRng`; такт `b` зависит от зерна и от тактов `< b`, симуляция
  запрашивает такты строго по порядку.
- `attract: true` — редкий декоративный трек без роста сложности (не больше 3 препятствий на такт).

## 6. Рендер (`renderer`)

Canvas 2D, 60 FPS и выше. Вся косметика живёт здесь: частицы, шлейф, тряска, вспышки. Источник
правды о геометрии — `camera.ts` (`project`, `depthScale`). Мир рисуется в момент
`t = state.tick − 1 + alpha` — положения объектов вычисляются функциями из `motion.ts` для дробного
`t`, корабль — `lerp(prevX, x, alpha)`, поэтому движение гладкое на любых герцах.

Это визуальное сердце игры. Образ — премиальный Retro Synthwave / Cyber Arcade:

1. **Небо**: градиент `skyTop → skyBottom`, звёзды с мерцанием, огромное полосатое ретро-солнце у
   горизонта (пульсирует на сильную долю), дымка `haze` вдоль горизонта.
2. **Горизонт — свой у каждой темы** (`theme.scenery`): `city` — силуэты небоскрёбов с огнями;
   `palms` — пальмы и холмы; `toxic` — трубы заводов и ядовитый туман; `aurora` — ледяные пики и
   северное сияние. Два плана с параллаксом от положения корабля.
3. **Дорога**: тёмное полотно `road`, перспективная сетка — поперечные линии «едут» на зрителя со
   скоростью уровня, продольные сходятся к точке схода; цвет сетки `grid[(level − 1) % n]` с плавным
   переходом ~1 с; яркость пульсирует в долю; светящиеся бортики `rail` и столбики вдоль них
   (проносятся мимо — главный признак скорости); на линии корабля — **линия удара**, вспыхивающая
   на каждую долю. Объекты выходят из дымки (плавное появление на дальних 15 % пути).
4. **Объекты в перспективе**, отсортированные от дальних к ближним:
   - куб — настоящий каркасный куб (8 вершин через `project`), вращается по `yawAt`; основание
     на дороге совпадает с хитбоксом;
   - пила — диск ребром к игроку, наполовину в дороге, с зубьями и искрами у полотна, вращается;
   - лазерные ворота — стойки-излучатели по краям и луч поперёк дороги с ярким ядром; проход
     обозначен скобами и подсветкой полотна;
   - сфера — гранёный кристалл с ядром и ореолом, парит над дорогой, пульсирует в долю; редкая —
     крупнее и другого цвета; при притяжении магнитом — дуга поля;
   - под каждым объектом — отражение-блик на полотне;
   - **метки прилёта**: для каждого препятствия на линии удара проявляется метка там, где оно
     окажется в момент прилёта (ширина = хитбокс, для ворот — подсвеченный проход). Яркость растёт
     по мере приближения. Это делает зигзаги честными на маленьком экране.
5. **Корабль** на линии удара: контур из `SHIP_GEOMETRY × SHIP_SIZE` в `shipColors(skin, theme)`,
   крен по `bank`, светящееся ядро, пламя сопел; шлейф частиц при `perks.trail`; кольцо щита при
   `shield > 0`; мерцание при `invulnTicks > 0`; поле магнита при `magnetRadius > 0`.
6. **Частицы** (пул, без аллокаций в кадре): подбор — 20–40 светящихся пикселей + кольцо +
   всплывающее «+100»; near miss — искры и надпись; щит — осколки; смерть — 100+ частиц, ударные
   кольца, осколки корпуса; смена уровня — волна по дороге; OVERDRIVE — скоростные линии по краям.
   Физика затухания: скорость гаснет, частица тускнеет и сжимается.
7. **Камера**: тряска `shake² × GAME.shake.maxOffset` (столкновение, щит, новый уровень, лёгкая —
   near miss), лёгкий крен мира вслед за кораблём, «удар» масштаба на дропе. Всё отключается
   при `reducedMotion`; тряска — ещё и при `shake === false`.
8. Полноэкранная вспышка, виньетка. На паузе кадр статичен и слегка приглушён; рендер **не
   перерисовывает** неизменившийся кадр паузы.

Производительность: никакого `shadowBlur` в циклах; свечение — двойной штрих и
`globalCompositeOperation = 'lighter'`, ореолы — кэш офскрин-спрайтов по цвету; небо, солнце и
горизонт кэшируются до смены размера или темы; линии сетки — одним путём на цвет. Цель —
не больше 4 мс на кадр на ноутбуке при DPR 2. Шрифт надписей на холсте —
`"Orbitron", "JetBrains Mono Variable", monospace` (в конструкторе — `document.fonts.load`).

## 7. Звук и ввод (`audio-input`)

**AudioEngine** — весь звук синтезируется, файлов нет. `AudioContext` создаётся только в
`unlock()` (жест пользователя); до этого все методы — безопасные пустышки. Граф звука строится
лениво и не блокирует жест дольше ~10 мс. Цепочка: голоса → шины music / sfx → компрессор → выход.

**Музыка управляется игрой.** События `beat` приходят с точным тиком; звук ставится на
`ctx.currentTime + LATENCY − late` (LATENCY ≈ 0.06 с), шестнадцатые внутри доли планируются сразу
(доля = 0.46875 с). Темп постоянный — 128 BPM.
- Слои зависят от **множителя комбо** (события `comboUp` / `comboBreak` / `overdrive`):
  x1 — бочка, бас, редкие хэты; x2 — плотные хэты; x3 — клэп на 2 и 4; x4 — пэд-аккорды с
  «сайдчейном» от бочки; x5–x7 — арпеджио; OVERDRIVE — открытый фильтр, лид на октаву выше.
  Срыв комбо — слои осыпаются с нисходящим свипом.
- Гармония меняется по тактам (прогрессия Am–F–C–G и её варианты по уровням); в 8-м такте уровня —
  нарастающая дробь и райзер, на `levelUp` — удар-«дроп».
- **Сферы играют мелодию**: `collect.note` выбирает ноту фразы в текущем аккорде (пентатоника,
  любое подмножество звучит чисто); редкая сфера — искрящееся арпеджио.
- Эффекты: `miss`, `comboBreak`, `dodge` c `near` (свист), `shieldBreak` (звон + удар), `newRecord`
  (фанфара), `death` (взрыв; музыка гаснет), `ready` / `go` (отсчёт вступления на долях −4…−1).
- `ui(sound)`: hover (тихий, с ограничением частоты), click, back, buy, equip, error, toggle.
  Модуль при загрузке регистрирует `setUiSoundHandler((s) => audio.ui(s))`.
- `setPaused(true)` плавно глушит всё; `setMusicActive(false)` — музыка молчит (меню).
- Включение звука подтверждается щелчком `toggle` только после `armToggleConfirm()` в этой
  вкладке: настройка, пришедшая из другой вкладки, применяется молча. Выключение — без звука.
- Ограничение числа голосов; отыгравшие узлы отключаются (без утечек); шум кэшируется.

**InputController.**
- Клавиатура (window): ←/→ и A/D по `e.code` → `axis`; обе нажаты — побеждает последняя,
  отпускание возвращает другую; `blur` окна — сброс. `preventDefault` для стрелок только когда
  ввод включён и фокус не в поле ввода.
- Указатель (target): мышь ведёт корабль движением без клика; палец/перо — касанием и ведением
  (`setPointerCapture`). Мультитач: управляет последний опущенный палец; когда он поднят,
  управление переходит к оставшемуся. `pointerX = toRoadX(clientX)`; после отпускания и ухода
  мыши значение сохраняется.
- `source` — устройство, которым управляли последним. `setEnabled(false)` — нейтральный кадр
  (`axis 0`, `pointerX null`, `source 'none'`) и никаких `preventDefault`. `attach` идемпотентен.

## 8. Оболочка (`shell`)

**App.tsx.** `useProgress()`; `loadout = getLoadout(save)`; `applyThemeCss(theme)`;
`audio.setSettings(…)`. Состояния: `screen`, `panel`, `runId`, последний итог и `RecordOutcome`.
`<MotionConfig reducedMotion="user">`, слои по схеме раздела 1.

**GameHost.tsx** — холст и цикл. Одна `Simulation`, один `Renderer`, один `InputController` на
всё время жизни; корректно переживает двойной mount StrictMode. `ResizeObserver` →
`renderer.resize(...)` (камера) — симуляцию размер не касается. Ввод включён только в `playing`;
`toRoadX` = `screenToRoadX(camera, clientX − rect.left)`.
- Новый `runId` → `sim.startRun(randomSeed(), toSimLoadout(loadout))`, `renderer.reset()`,
  `input.reset()`, `audio.setMusicActive(true)`.
- `menu` → `sim.startAttract(...)`, музыка выключена; смена темы или корабля в меню сразу видна.
- `paused` → тики не идут, кадр рисуется (рендер сам не перерисовывает статичный кадр).
- `late` для звука: `(state.tick − e.tick + alpha) · TICK_DT`.
- Брошенный забег: выход из паузы в меню, «Заново», закрытие или перезагрузка вкладки
  (`pagehide`) → `sim.abandon()`; непустой итог записывается через `actions.recordRun` ровно один раз.
- Потеря фокуса или скрытие вкладки в забеге → пауза.
- FPS — скользящее среднее. `installDebug(...)` из `src/debug.ts` (включая `autopilot` на `planMove`).

**Hud.tsx.** Сверху: SCORE (крупно, моноширинно, ведущие нули приглушены), COMBO `xN` с полоской
до следующего множителя (пружинный «поп» при росте, дрожь при срыве, особый вид в OVERDRIVE),
BEST (жёлтый с меткой, когда побит). Ниже: `LV N · SPEED ×1.13` с полоской уровня, кристаллы
забега, заряды щита, кнопка паузы — единственный интерактивный элемент. По центру — баннеры из
`useBanners()`: READY / GO, LEVEL N, **NEW RECORD!** (эффектная неоновая вспышка), SHIELD DOWN,
COMBO BREAK, OVERDRIVE. Элементы HUD могут пульсировать в долю. Первый забег — подсказка управления.

**PauseOverlay / GameOverOverlay** — `<Overlay blur>` (размытие заднего плана — требование
заказчика) + неоновая карточка, появление через Framer Motion. Game Over: «GAME OVER» с глитчем,
счёт с набором, «NEW RECORD!» или «ПЕРВЫЙ РЕКОРД», место в топ-5, статистика (уровень и скорость,
лучшее комбо, сферы, кристаллы, время, near miss), кошелёк, кнопки «Ещё раз» / «Магазин» /
«Рекорды» / «Меню».

**DeathFlash** — вспышка, расходящиеся кольца и осколки из точки взрыва (Framer Motion).
**ScreenFx** — сканлайны и виньетка.

Клавиши: меню — `Enter`/`Space` играть (если панель закрыта), `Esc` закрывает панель; забег —
`Esc`/`P` пауза; пауза — `Esc`/`P` продолжить, `R` заново, `M` меню; game over —
`Enter`/`Space`/`R` ещё раз, `S` магазин, `L` рекорды, `Esc` меню. Хоткеи — по `e.code`.

## 9. Меню (`menus`)

- **MainMenu** — логотип «NEON VELOCITY» с «II» и подзаголовком «RHYTHM & DODGE», главная кнопка
  «Играть», «Магазин», «Рекорды», «Настройки», «Как играть», плашки рекорда и кошелька, текущее

## 10. Уроки первой версии — это требования

Три круга ревью первой версии нашли 50 дефектов. Во второй они запрещены с самого начала.

Игра и состояние
- Итог брошенного забега (пауза → меню / «Заново», перезагрузка, закрытие вкладки) сохраняется
  ровно один раз; пустой забег не сохраняется.
- После «Заново» новый забег стартует с уже обновлённым рекордом.
- Две вкладки не затирают сохранения друг друга (событие `storage`; `useProgress` это уже умеет).
- Повреждённое сохранение не ломает игру; `localStorage`, который бросает исключения, — тоже.
- Корабль не «прыгает» при старте забега; в меню и забеге никаких рывков при смене режима.

Экраны и фокус
- Уходящий экран не ловит клики и клавиши: двойной клик по «Играть» не запускает два забега,
  двойной тап «В меню» не открывает панель. Только что появившееся меню ~0.6 с не ловит указатель.
- Game Over первые ~650 мс не реагирует на хоткеи и тапы (игрок ещё жмёт клавиши забега).
- Открыта панель — слой под ней `inert` (один диалог для скринридера и Tab); фокус возвращается
  на открывшую кнопку, если её выбрали с клавиатуры (`useDialogFocus`).
- `Enter` после клика мышью по кнопке звука запускает забег, а не переключает звук.
- Никаких `alert` / `confirm` / `prompt`.

HUD и вёрстка
- На одной «полке» баннеров живёт один баннер; SHIELD DOWN и COMBO BREAK не накладываются
  (потеря множителя дописывается в баннер щита). Баннеры не закрывают корабль и счёт, в том числе
  на 844×390 и 360×640. NEW RECORD! не прячет препятствия дольше ~2 с.
- HUD не слипается на ширине 320–390 px; счётчик FPS не перекрывает подсказку.
- Безопасные зоны (`env(safe-area-inset-*)`) со всех четырёх сторон; телефон боком — отдельная
  компактная раскладка для паузы, Game Over, меню и панелей.
- Подсказки клавиш не показываются на тач-устройствах (`max-sm` и `pointer-coarse`).
- Тексты не обрезаются; склонения правильные (`plural`): «21 кристалл», «7 021 очко».

Производительность
- `backdrop-filter` пересчитывается при любом изменении под ним: под паузой кадр заморожен,
  под Game Over холст замирает через ~0.8 с, а CSS-анимации этих экранов конечны. Панели меню
  фон не размывают — только затемняют.
- Никаких `setState` в каждом кадре; HUD обновляется через `hudStore`.
- Быстрый автоповтор клавиши на слайдере громкости не роняет React (нет вложенных обновлений).

Звук и ввод
- Первый звук не теряется; жест не блокируется построением графа; райзер уровня играет один раз.
- Мультитач: после подъёма второго пальца первый продолжает управлять.
- Щелчок подтверждения звука — только в своей вкладке.

Страница
- Тёмный фон с первого кадра, `lang="ru"`, свой `line-height` у текста (страница-хост может
  задать `body{font:14px system-ui}`), работа в `<iframe sandbox="allow-scripts">`.

## 12. Правила кода

- TypeScript strict, без `any`, без `// TODO`, заглушек и «упрощённых версий».
- Комментарии по-русски, коротко: зачем, а не что. Тексты интерфейса — по-русски; аркадные
  надписи (SCORE, COMBO, BEST, NEW RECORD!, GAME OVER, PAUSE, LEVEL, GO!, OVERDRIVE) — латиницей.
- Стили — Tailwind-классы и токены `index.css`; свои стили — в `.css` рядом с компонентом.
- Анимации интерфейса — Framer Motion; `prefers-reduced-motion` уважается.
- Числа баланса — только в `config.ts`; локальные константы допустимы для чистой косметики.
- Проверка перед сдачей: `npm run typecheck` и `npm test` без ошибок.
