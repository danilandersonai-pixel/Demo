# CLAUDE.md — Кубокрафт

Руководство для работы с игрой в каталоге `minecraft/`. Это самостоятельный
проект: к свадебному сайту и к `ai-factory/` отношения не имеет.

## Что это

Воксельная песочница в духе Minecraft с режимами выживания, творчества и
зомби-апокалипсиса, с четырьмя измерениями (обычный мир, Пекло, Небеса,
Космическая станция) на чистом WebGL (WebGL2, с откатом на WebGL1; шейдеры
GLSL ES 1.0). Сборки, npm и
внешних JS-библиотек нет. Снаружи грузятся только Google Fonts с фолбэками.
Текстуры, модели и звуки генерируются кодом. Графика: свет от солнца и луны
по нормалям, тени по карте глубины, HDR-постобработка со свечением,
погода и частицы — всё с пресетами качества.

**Персонажи и мобы собственные.** Странник, упырь, костяной лучник, лесной паук,
свинья, бурёнка, овца и курица, а в новых мирах — заражённый, бегун, громила,
пациент, заражённый полицейский, заражённый военный, слепой, выживший, бес,
огненный дух, пегас,
облачник, сбойный дрон и робот-уборщик. Не копировать внешний вид
и имена персонажей Minecraft: Стива, Крипера, Эндермена, зомби в голубой
рубашке и так далее. Механики (крафт, руды, редстоун-подобная схемотехника)
брать можно, названия даём свои («искровая пыль», а не «редстоун»).

## Команды

```bash
cd minecraft && python3 -m http.server          # превью → http://localhost:8000
for f in minecraft/js/*.js; do node --check "$f"; done   # проверка синтаксиса
```

Тестов в репозитории нет. Проверять удобно двумя способами:

- **Node без браузера.** Для логики мира, симуляции и мобов загрузите модули с
  заглушками `window = global` и `document.createElement → { getContext: () =>
  null }`. Порядок: noise, textures, registry, world, dims, models, entities,
  sim (`fx.js` и `renderer.js` в Node не нужны: `KC.Light` объявлен в
  `world.js`). Затем создайте `new KC.World(seed, {}, dim, type)` (`dim` — `over`,
  `hell`, `heaven`, `space`; `type` — `normal` или `city`), вызовите
  `generate`, `Entities.init` и `Sim.init`. Случайные тики и появление мобов
  идут только в чанках с `mesh`, в тесте подставляйте `c.mesh = {}`.
- **Playwright** из глобальной установки. Chromium рисует через SwiftShader с
  флагами `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`.
  FPS там низкий, а `dt` ограничен 0,1 с, поэтому игровое время идёт медленнее
  реального: ждите события через `waitForFunction`, а не таймером. Из консоли
  доступен `KC.debug` (`world`, `player`, `P`, `state`, `play`, `pause`, `weather(kind, instant)`,
  `open`, `close`, `setTime`, `setMode`, `save`, `goTo(dim, via)`, `travel`,
  `zombie`, `scenario`, `zombieDawn`, `evac()`, `heli`, `openMap`, `carHit`,
  `events.airdrop/survivor/fire`, `enterVehicle`, `exitVehicle`, `vehicle`,
  `refuel`). За рулём `driveInput` каждый кадр перезаписывает `v.ctl`
  (`throttle`, `steer`, `brake`) из ввода, поэтому в тесте жмите клавиши
  (W/S, A/D, пробел — тормоз), а не пишите `v.ctl` руками. Качество задаётся
  через `localStorage['kubocraft.settings.v1'] = {gfx: 0…3, gfxAuto: false}`
  или выбором `#set-gfx` с событием `change`; для быстрых сценарных тестов
  ставьте `gfx: 0` — в SwiftShader полные эффекты в разы медленнее.
  `gfxAuto: false` отключает автоснижение качества при низком FPS.

## Архитектура

Скрипты подключаются по порядку и пишут в общий namespace `window.KC`:

| Файл | Отвечает за |
| --- | --- |
| `noise.js` | `KC.Noise` (n2, n3, fbm2), `mulberry32`, `hash2`/`hash3` |
| `textures.js` | `KC.TILE` (имя → индекс плитки), `makeAtlas` 256×512 (`KC.ATLAS_W`/`ATLAS_H`, заодно `KC.atlasAlpha` — прозрачность пикселей для объёмных предметов), `makeIcon`, `makeHudIcons`, трещины |
| `registry.js` | `KC.B`/`KC.I`, `BLOCKS`/`ITEMS`, флаги (`OPAQUE`, `SOLID`, `REPLACEABLE`…), `breakTime`, `drops`, `RECIPES`, `SMELT`, `matchRecipe` |
| `world.js` | `Chunk` (blocks + meta), `World(seed, edits, dim, type)` (генерация, `setBlock` с метаданными и правками, `collide`, `skyAt`, `blockLightAt`), мешер |
| `dims.js` | `KC.DIMS` (имя, тяжесть, цвета неба, фиксированное время, туман, облака, вакуум) и `KC.Gen`: генераторы `hell`, `heaven`, `space`, `city`, `arrival`, `inStation`, `rollLoot`, `citySpawn`; город — `plotInfo`, `districtOf`, `cityInfo`, `findNearest`, `evacPoint`, `plotEntrance` |
| `renderer.js` | программы блоков (свет, тени, вода, свечение), сущностей, мягких частиц, неба (солнце, луна с фазами, звёзды, Млечный Путь, планета), плоских и объёмных облаков, линий; проход теней; постобработка (MSAA, bloom, тонмаппинг, цветокоррекция, лучи); `setQuality`, `render(env)` |
| `models.js` | коробочные модели с позами (атлас 1024×1024, шкурки с прозрачностью), модели техники, свет граней `faceLight`, светящиеся детали, объёмные предметы `extrude`/`drawExtruded`/`drawItem3D`, `drawModel`, `drawBlockCube`, `drawSprite`, `Batch` |
| `fx.js` | `KC.FX`: атлас мягких частиц, `emit(kind, …)`, жизнь вокруг игрока (огоньки, листопад, светлячки, пепел), погода (`weather`, дождь, снег, молнии), сборка вершин частиц |
| `entities.js` | `Ent`, физика (`move` со ступенькой 0,6, `gravityAt`), предметы, мобы (`KINDS`), ИИ ходячих и летающих, стрелы, огненные шары, лазеры и снаряды, динамит, гранаты и молотов, падающие блоки, техника (`VEHICLES`), появление по измерениям |
| `sim.js` | тик: запланированные события, жидкости, опоры, случайные тики, печи, искровая сеть, поршни, взрывы, блок-сущности |
| `audio.js` | синтез звуков, `play(имя, x, y, z)` с затуханием и панорамой |
| `player.js` | `KC.Player`: движение с тяжестью измерения, выживание (вакуум, магматит), инвентарь (36 + 4 брони), добыча, бой, огнестрел и огнемёт, броски, аптечка, врата и телепорт, `use`, сон, рука и тело |
| `ui.js` | `KC.UI`: HUD и окна-контейнеры с курсором-стопкой, книга рецептов, палитра творчества |
| `game.js` | запуск, цикл (кадр + тики 20/с), менеджер измерений (`goTo`), режим зомби, управление, посадка в технику и вождение, камера (тряска), прицел, подгрузка чанков, свет кадра (`updateLighting`), динамические огни (`gatherLights`), цветокоррекция (`gradeFor`), фоновые звуки, пресеты качества и автоснижение, сохранение, меню |

Константы: `CS = 16`, `H = 96`, `WL = 30`. Индекс блока — `x + z*16 + y*256`.
Блоки имеют id от 0 до 255, предметы — от 256. Блок одновременно является и
предметом (`ITEMS[id].block`).

## Метаданные блоков (4 бита используются по-разному)

| Блок | meta |
| --- | --- |
| вода, лава | биты 0–2 — уровень (0 — источник), бит 3 — падающая |
| печь, сундук, тыквы, верстак, кровать | биты 0–1 — «взгляд» (0 +Z, 1 −X, 2 −Z, 3 +X); у печи бит 2 — горит |
| факел, искровой факел, рычаг, кнопка, лестница | биты 0–2 — направление на опору (порядок `DIRS`); бит 3 — «включено», у искрового факела — «погас» |
| поршень | биты 0–2 — направление (`DIRS`), бит 3 — выдвинут; головка хранит направление |
| дверь | биты 0–1 — взгляд, бит 2 — открыта, бит 3 — верхняя половина |
| провод | 0–15 — мощность сигнала |
| пшеница | 0–7 — стадия; пашня: бит 0 — влажная; лампа: бит 0 — горит |
| листва | бит 0 — берёза, бит 1 — поставлена игроком (не осыпается) |
| врата пекла и небес | бит 0 — панель вдоль Z, бит 3 — верхняя половина |
| разметка дороги | 0 — полоса вдоль X, 1 — вдоль Z, 2 — зебра |
| бревно | 0 — стоит, 1 — лежит вдоль X, 2 — вдоль Z |
| объект-модель (`shape: 'model'`) | биты 0–1 — поворот «лица» (как у печи) |
| «наклейка» (`shape: 'decal'`) | биты 0–2 — направление на опору (`DIRS`): 3 — пол, 0/1/4/5 — стены |

Правки игрока хранятся как `id | meta << 8`. Порядок `DIRS`: 0 +X, 1 −X, 2 +Y,
3 −Y, 4 +Z, 5 −Z; противоположное направление — `d ^ 1`.

## Инварианты (важно при правках)

- **Генерация детерминирована и не зависит от порядка чанков.** Деревья
  соседей считаются в запасной зоне `G = 3`, ствол перезаписывает листву,
  листва ставится только в воздух.
- **Мешер** работает с паддингом 18×18×(H+2) и строит меш, только когда
  загружены все 8 соседей. Вершина — 8 float (`x y z u v тень небо свет`).
  Свет блоков — BFS в регионе 3×3 чанка от `chunk.emitterIndices()` в полосе
  высот вокруг светильников. Любое изменение рядом со светильником помечает на
  перестройку все 3×3 чанка.
- **Коллизии** считаются по коробкам (`World.collide`, `KC.collisionBox`),
  а не по целым клеткам: двери, кровати, сундуки и кактусы нестандартные.
  Выделение — по `KC.selectionBox`.
- **Слушатель `world.listener`** (его ставит `Sim`) реагирует на каждое
  изменение: планирует жидкости, проверку опор через тик, падение песка,
  блок-сущности и пересчёт искровой сети. `setBlock(..., quiet = true)`
  слушателя не зовёт — так делают сам `Sim` (мощность проводов, лампы, двери)
  и массовые правки в тестах.
- **Искровая сеть** пересчитывается в конце тика по `rsDirty`: провода вокруг
  изменений, мощность волной, затем приёмники. Искровой факел переключается с
  задержкой в 2 тика, поэтому «часы» не зависают.
- **Первое действие** (удар, установка) выполняется сразу по нажатию, таймеры
  лишь повторяют его при удержании. Кнопки, открывающие экраны на сенсоре,
  работают по `click`, а не по `pointerdown`: иначе догоняющий щелчок закроет
  окно.
- **Мобы** из выгружаемых чанков: мирные откладываются в `world.storedMobs`,
  враждебные удаляются. `world.animalChunks` не даёт заспавнить стадо повторно.
  `onChunkGenerated(c, info)`: `info` (`hs`, `bio`, `G`, `P`) есть только у
  обычного мира, в остальных — `null`, там стада ищут поверхность по `c.hmap`.
- **Измерения.** Живёт ровно один `World`. При переходе (`goTo`) текущий мир
  сворачивается в `dimData[dim]` (правки, блок-сущности, мирные мобы и
  предметы, `animalChunks`, `storedMobs`), а новый собирается `makeWorld` и
  заново подключает `Entities`, `Sim` и `Player`. `lastPos[dim]` — где игрок
  был в каждом мире, `backDim[dim]` — откуда пришёл. Врата вида `kind` ведут в
  `kind`, а из него — в `backDim[kind]`; при первом визите рядом строятся
  обратные врата. Возрождение всегда в обычном мире.
- **Сундуки мегаполиса и станции** не заполняются при генерации: чанк помнит
  их в `c.loot`, а содержимое бросается (`rollLoot`) при первом открытии
  (`Sim.chestBent`). Так тысячи сундуков не раздувают сохранение.
- **Генерация измерений** — чистая функция координат, как и у обычного мира.
  Станция описана списками коробок (`SHELLS`, `CARVES`, `FEATURES`, `SOLAR`),
  которые каждый чанк накладывает на себя; `inStation` проверяет воздух.
- **Тяжесть** берётся из `E.gravityAt(x, y, z)`: множитель из `KC.DIMS`, а внутри
  станции всегда 1. Она же масштабирует урон от падения.
- **Режим зомби** — это `scenario: 'zombie'` поверх выживания с миром
  `type: 'city'`. День засчитывается на рассвете (переход `timeOfDay` через 0)
  только в обычном мире. `hooks.hordeBoost` увеличивает лимит заражённых с
  каждым днём.
- **Город** строится кварталами 40×40 (`CELL`): дорога 8, тротуары, участок
  28×28. `plotInfo(seed, cx, cz)` — чистая функция с кешем: район
  (`districtOf`: центр в 7–9 кварталах от старта, окраина далеко, промзона по
  шуму), вид участка (`building` со стилем `tower/office/apart/hospital/police/
  helipad`, `houses`, `warehouse`, `construction`, `market`, `gas`, `park`,
  `parking`, `ruin`) и `special`. Полиция, больница, супермаркет и заправка
  рядом со стартом заданы жёстко (`FORCED`), площадка эвакуации — в клетке
  `cityCenter`. Метро — под дорогами клеток с номером ≡ 2 (mod 4): туннели на
  высоте `METRO_FLOOR`, станции на пересечениях, спуск вдоль тротуара.
- **Сценарий эвакуации** (`game.js`): рация (`I.RADIO`, сундук `armory` в
  полиции) → `zombie.radio` → стрелка на `evacPoint` → генератор на крыше
  (`B.GENERATOR`, топливо в блок-сущности, `Sim.fuelGenerator`) зажигает
  `LANDING_LIGHT` → в день `zombie.heliDay` вертолёт (моб `heli` с `vehicle`,
  им управляет `vehicleUpdate`) кружит, садится при горящих огнях и игроке на
  площадке → победа. На закате без эвакуации `heliDay += 3`.
- **ИИ заражённых:** цель по зрению (`acquire`), слух (`E.noise(x, y, z, r)`
  ставит `ai.heard`), слепые (`blind`) только слышат по `player.loud` (0 — стоит
  или крадётся, 1 — идёт, 2 — бежит). Упёршись, ломают блоки с полем `siege`
  (секунды на блок, `breaker` ускоряет), иначе обходят стену; ищут лестницу
  (`findLadder`), если игрок выше. `lightShy` (бегун) отступает от света ≥ 11.
  Особые здания заселяются толпой при подходе (`populateSpecials`,
  `world.cityPop` — день заселения).
- **События** (`cityEvents`): груз (`B.AIRDROP` падает сущностью, добыча
  `airdrop` кладётся при приземлении), выживший на крыше (`talkTo` дарит карту),
  пожар (`B.FIRE` гаснет по случайным тикам). Сигнализация машин — `carHit`.
- **Атлас блоков** 16×32 плиток (`KC.ATLAS_W`×`ATLAS_H`); таблица UV в
  мешере (`UVS`) рассчитана на все 512 плиток. Атлас моделей — 1024×1024,
  занят примерно наполовину.
- **Техника** — сущность `type: 'vehicle'` с параметрами из `VEHICLES`
  (`entities.js`): размеры `w`/`len`/`h`, скорость, разгон, поворот, прочность
  и `armor`, расход топлива, ступенька `step`, уровень сноса `crush` (1 — кусты
  и обломки, 2 — ещё двери, окна, фонари, 3 — стены с `hardness` ≤ 3), место
  водителя `seat` (вправо, высота глаз, назад от центра), дистанция камеры
  `cam`, флаги `cabin` (вид из кабины), `tint` (случайный цвет кузова),
  `cannon`. Корпус — цепочка квадратов вдоль длины (`vSamples`), столкновения —
  `vHits`; снос считается по переднему квадрату по ходу движения (`vCrush`).
  `vehiclePush` давит мобов на скорости > 3 и расталкивает остальных. Стоящая
  машина без водителя «спит» и пересчитывает физику раз в секунду. Урон игроку
  за рулём уходит в корпус (`hurtPlayer`), взрыв при `hp ≤ 0` высаживает.
  Заправка — у колонки или канистрой. Модели техники нарисованы в единицах
  1/8 блока с масштабом 2; части с именем `paint…` перекрашиваются, при виде
  из кабины скрываются части из `CABIN_HIDE`.
- **Расстановка техники при генерации** идёт через `vSpawnBlocked`, а не
  `vHits`: `gather()` считает незагруженные соседние чанки сплошными, и машина
  на краю чанка иначе никогда не встанет.
- **Оружие** описывается полем `gun` у предмета: `dmg`, `range`, `cd`, `ammo`,
  `semi` (выстрел только по свежему нажатию, `P.fresh`), `auto`, `pellets`
  (дробь; урон по мобу суммируется в `dmgMap`), `spread` и `bloom`, `scope`
  (удержание ПКМ — прицел, выстрел при отпускании), `pierce` (пробивает мобов),
  `flame` (огнемёт), `noise`, `knock`, `sound`. Пули бьют через
  `damageMob(..., bullet = true)` — без паузы неуязвимости, иначе дробь
  засчитала бы одну дробину. Броню моба `bulletproof` снайперка пробивает
  вдвое лучше. Метательное — поле `thrown` (`grenade`, `molotov`) и
  `E.throwItem`.
- **Военный блокпост** (`militaryColumn` в `dims.js`) — ограда из мешков с
  песком (`B.SANDBAG`), две вышки, палатка, ящики с добычей `military`; на нём
  стоят танк и самосвал, живут заражённые военные (`soldier`). Бульдозер
  ставится на стройке, полицейская машина — у участка, обычные машины — на
  дорогах по `ROAD_KINDS` района (`cityVehicles`).

## Графика (важно при правках)

- **Вершина блока — 8 float, формат прежний,** но `aLight.x` упакован:
  `материал × 2048 + нормаль × 256 + AO × 200` (`pk` в `world.js`; нормаль
  0…5 — грань в порядке `FACES`/`DIRS`, 6 — «со всех сторон» для плоских
  растений). Материалы — `KC.MAT` (растение, листва, вода, лава, свечение,
  портал, огонь, стекло, трава, светящееся растение, металл, мигание); мешер
  выбирает их в `matOf`, коробка модели может переопределить на свечение или
  мигание. Новому материалу нужна ветка в шейдере блоков (и в простом, и в
  `FANCY`-пути).
- **Свет считается в вершинном шейдере:** рассеянный (`uAmbTop/uAmbBot` по
  нормали × небо² + `uAmbCave`), факелы (`uBlockCol` × свет из мешера, днём
  слабее), прямое солнце/луна (`uSunCol × N·L`). В пикселе — только тень
  (`shadowAt` × `cloudShadow`), динамические огни (`dynLight`, ранний выход по
  `uNumL`) и особые материалы. Униформы с одинаковым именем в вершинном и
  пиксельном шейдере запрещены (на WebGL1 без highp это ошибка линковки) —
  в вершинном у них суффикс `V`.
- **`KC.Light`** (объявлен в `world.js`) заполняет `game.js` каждый кадр
  (`updateLighting`): направление и цвет солнца или луны, эмбиент, `shadowDir`
  (светило не ниже 20°), `shadowK`, `bright`, `wind`, `fogSun`. Его же читают
  сущности: `E.lightAt` — рассеянный свет в точке, `E.sunVis` — луч к светилу
  по вокселям (листва пропускает часть), `drawModel(..., light, roll, sunK,
  tint, glow)` освещает грани по солнцу, `glow` — светящиеся детали по имени.
- **Тени:** ортопроекция вдоль `shadowDir` вокруг камеры (`shadowHalf`),
  центр привязан к сетке текселей; в карту глубины рисуются непрозрачные
  чанки (с вырезанием по альфе), мобы и предметы. Сдвиг по нормали против
  «угрей» (`uShP.z`). За краем карты — запасной вариант по небесному свету.
- **Постобработка** (`q.post`): сцена в HDR-текстуру (half float, если есть,
  иначе RGBA8), при `msaa` — через многосэмпловый буфер; bloom — цепочка до 5
  уменьшений; `COMPOSITE_FS` — мягкое плечо тонмаппинга (до 0.72 цвет не
  меняется), цветокоррекция `env.grade` (`gradeFor`), виньетка, волны под
  водой, лучи солнца по альфе неба (небо пишет альфу 0, геометрия — 1).
- **Пресеты `QUALITY`** в `game.js` → `renderer.setQuality`: `lights`, `sway`,
  `fancy` (полный шейдер блоков), `shadows` (размер карты), `pcf`,
  `shadowHalf`, `post`, `bloom`, `msaa`, `rays`, `cloudShadows`, `clouds3d`,
  `parts` (доля частиц). Смена пересобирает программы и буферы.
  `perfWatch` снижает качество при FPS < 22 дольше 8 секунд, если
  `settings.gfxAuto`.
- **Частицы — `KC.FX`:** мягкие (свой атлас 8×8 клеток, `SP`) рисуются после
  воды: сначала полупрозрачные от дальних к ближним, потом аддитивные
  (`add`, цвет > 1 даёт свечение). Обломки блоков (`'block'`) — «твёрдые»,
  идут через программу сущностей с атласом блоков. Хук `particles(kind, …)`
  у сущностей, симуляции и игрока ведёт в `FX.emit`.
- **Погода** (`FX.weather`: `kind`, `k`, `snow`, `flash`, `wind`) только в
  обычном мире: `skyState`/`updateLighting` затягивают небо и гасят солнце,
  туман ближе, `env.wet` делает верх блоков мокрым, молнии — через
  `FX.lights()` в динамические огни. Капли гаснут на высоте `hmap` колонки —
  под крышей дождя нет.
- **Объёмные предметы:** спрайт выдавлен на толщину пикселя по
  `KC.atlasAlpha` (кэш на плитку). В руке и на земле — `drawExtruded`,
  оружие, инструменты и фонарик зеркалятся стволом к центру экрана.
- **Небесный свет** — по карте высот колонки (`psky`, `skyAt`); в Небесах у
  мира `skyFloor = 0.55`, иначе деревья под соседним парящим островом чернеют.
- При `prefers-reduced-motion` нет ветра, тряски камеры, молний и фоновых
  частиц.

## Сохранение

Ключ `kubocraft.world.v3`. Внутри: `seed`, `mode`, `diff`, `time`, `tips`,
`scenario` (`null` или `'zombie'`), `worldType`, `dim` (где игрок сейчас),
`dims` (по измерению: `edits`, `bents`, `entities`, `animalChunks`,
`storedMobs`, `cityPop`), `lastPos`, `backDim`, `moon` (счётчик ночей для
фаз луны), `zombie` (`day`, `won`, `kills`,
`rescued`, `radio`, `heliDay`, `heliActive`, `genFueled`, `ev` — события;
недостающие поля дополняет `zombieDefaults`) и
`player` (позиция, здоровье, сытость, воздух, `inv`/`armor` как
`[id, n, износ]`, `spawn`, `veh` — сидел ли в машине; при загрузке игрок
садится в ближайшую машину в радиусе 4 блоков). Техника хранится вместе с
мобами (`entities.mobs` и `storedMobs`) как `{veh: 1, k, x, y, z, yaw, hp, f,
c}` и не выгружается, пока в ней сидит игрок. Сохранение v2 (`kubocraft.world.v2`, один мир)
переносится в `dims.over`, v1 — загружается как мир творчества. Настройки лежат
в `kubocraft.settings.v1`. `localStorage` всегда оборачивается в `try/catch`.

## Соглашения

- Код в стиле ES5 внутри IIFE: `var`, объявления функций, `'use strict'`.
- Весь текст интерфейса на русском. Клавиши определяются по `e.code`.
- Интерфейс поддерживает `prefers-reduced-motion`: без частиц, без изменения
  FOV, без облёта камеры на титуле.
- **Новый блок:** id в `KC.B`, `blk(...)` в `registry.js`, плитка в
  `textures.js`, при нестандартной форме — ветка в `emitShape` и коробки в
  `collisionBox`/`selectionBox`. **Новый предмет:** `item(...)` со спрайтом,
  рецепт через `shaped`/`shapeless`.
- **Новый моб:** запись в `KINDS` (`entities.js`), модель в `models.js`, поза в
  `buildRender`, голос в `audio.js`, правило появления в `spawnRules`. Флаги
  вида: `hostile`/`passive`, `flies` + `hover`, `ranged` (`true` — лук,
  `'fireball'`/`'laser'` — снаряд без тяжести), `fireImmune`, `ignite`,
  `zombie`, `knock`, `scale`, `glow`.
- **Новый объект-модель** (скамейка, гидрант…): `blk(..., ext(prop, { model:
  { boxes: [[x0,y0,z0,x1,y1,z1, плитка или {side, top, front}, 'glow'|'blink'], …],
  coll: [...] } }))` в `registry.js`, единица — 1/16 блока, «лицом» к +Z;
  поворот, коллизия и выделение считаются сами (`rotBox`).
- **Новая «наклейка»** (афиша, трещина…): `ext(decal, { variants: [...] })` —
  вариант выбирается по координатам; ставится в воздух у грани опоры с meta =
  направление на опору.
- **Новый эффект частиц:** ветка в `emit` (`fx.js`), при нужде — спрайт в
  `makeTexture` и имя в `SP`; светящиеся — `add = true, lit = false`.
- **Новая техника:** запись в `VEHICLES` (`entities.js`), модель в
  `models.js` (колёса `wheel`, гусеницы `track`, стёкла `glassPaint`), значок
  `vehIcon` в `textures.js`, предмет с полем `vehicle` в `registry.js` (им
  ставят машину в творчестве), при желании — место в `cityVehicles`.
- **Новое оружие:** предмет с полем `gun` или `thrown`, спрайт, патроны и
  рецепты, звук выстрела в `audio.js`, добыча в таблицах `LOOT`.
- **Новое измерение:** запись в `KC.DIMS`, генератор в `KC.Gen[dim]`, ветка в
  `arrival`, способ попасть (флаг `portal` у блока врат или `use`).
- **Новое особое здание города:** шанс в `SPECIAL_ODDS`, ветка в `plotInfo` и
  функция колонки (`…Column`), таблица `LOOT`, жители в `POPULATION` и
  `BUILDING_KINDS` (`entities.js`), подпись в `SPECIAL_NAMES`/`SPECIAL_NOTES` и
  значок на карте (`MAP_ICON`).
- **Медицинский крест — зелёный.** Красный крест на белом — охраняемая
  эмблема, её не используем ни в текстурах, ни в интерфейсе.
