# Часть III — Знание о проекте и контекст

## Глава 9. Как построить рабочий `CLAUDE.md`

`CLAUDE.md` — долговечное руководство по проекту, загружаемое в начале каждой
сессии. Оно доставляется **пользовательским сообщением после системного
промпта**, а не как часть системного промпта: Claude его читает и старается
следовать, но **гарантии соблюдения нет** — особенно для расплывчатых или
конфликтующих инструкций. Инструкция, которая *обязана* держать, принадлежит
правилу разрешений (глава 7) или хуку (глава 17).

### 9.1 Где живут инструкции

| Область | Расположение | Что уместно |
|---|---|---|
| Управляемая политика | macOS `/Library/Application Support/ClaudeCode/CLAUDE.md`; Linux и WSL `/etc/claude-code/CLAUDE.md`; Windows `C:\Program Files\ClaudeCode\CLAUDE.md` либо ключ `claudeMd` в управляемых настройках | Общеорганизационные стандарты, политика безопасности, напоминания о соответствии. **Не может быть исключено никакой пользовательской настройкой** |
| Пользовательская | `~/.claude/CLAUDE.md` | Личные умолчания, которые действительно применимы везде |
| Проектная | `./CLAUDE.md` или `./.claude/CLAUDE.md` | Назначение, структура, команды, правила, проверка. Разделяется через систему контроля версий |
| Локальная проектная | `./CLAUDE.local.md` | Приватные предпочтения по проекту. Добавить в `.gitignore` |
| Подкаталог | `path/to/CLAUDE.md` | Инструкции, значимые только в этом поддереве; грузятся по требованию |

Файлы **конкатенируются**, а не переопределяются. По дереву содержимое
упорядочено от корня файловой системы вниз к рабочему каталогу, поэтому
инструкции, ближайшие к месту запуска, читаются последними; внутри каталога
`CLAUDE.local.md` дописывается после `CLAUDE.md`.

Claude Code читает `CLAUDE.md`, а не `AGENTS.md`. Если репозиторий уже
использует `AGENTS.md` — импортируйте его (`@AGENTS.md` первой строкой
`CLAUDE.md`), а не дублируйте.

### 9.2 Инициализировать, потом править

`/init` генерирует стартовый `CLAUDE.md`, анализируя проект; если файл уже есть,
команда предлагает улучшения, а не перезаписывает. Она также читает файлы правил
Cursor и Copilot. `CLAUDE_CODE_NEW_INIT=1` включает интерактивный многофазный
режим с исследованием сабагентом и проверяемым предложением до записи.

Порядок работы:

1. Запустить `/init`.
2. Прочитать каждую строку.
3. Удалить общие описания, историю изменений, переходящее состояние и
   продублированную документацию.
4. Оставить операционные факты, конвенции, отличающиеся от умолчаний
   инструментов, подводные камни и команды проверки.
5. `/memory` — посмотреть, что загружено; `/context` — подтвердить.

**Цель — менее 200 строк.** Более длинные файлы съедают контекст и снижают
следование. Файл больше 4 МиБ пропускается целиком. `/doctor` предлагает
сокращения для закоммиченного файла, вырезая то, что Claude может вывести из
кодовой базы, и сохраняя обоснования и конвенции (2.1.206+).

### 9.3 Указатель, а не склад

Длинный справочный материал принадлежит отдельным файлам с правилом извлечения.
Импорты через `@path/to/file` поддерживаются до глубины четыре, но
**импортированные файлы грузятся при старте и не снижают занятость контекста** —
они помогают организации, а не стоимости. Разбор импортов пропускает кодовые
фрагменты и блоки, поэтому `@README` в обратных кавычках остаётся буквальным.

Импорт в *проектном* файле памяти, чей путь ведёт за пределы рабочего каталога,
считается внешним, и при первой встрече показывается диалог одобрения со
списком файлов; отказ отключает их навсегда. **Этот диалог — механизм контроля
цепочки поставок**: он существует потому, что импорт в общий репозиторий может
закоммитить кто-то другой.

Блочные HTML-комментарии вырезаются перед внедрением, поэтому заметки
сопровождающего не стоят контекста.

### 9.4 Модульные правила

Большие наборы инструкций разбиваются в `.claude/rules/*.md`, обнаруживаемые
рекурсивно. Правило без frontmatter `paths` грузится при старте с тем же
приоритетом, что и `.claude/CLAUDE.md`. Правило *с* `paths` грузится, только
когда Claude читает подходящий файл:

```
---
paths:
  - "sources/**/*.md"
  - "notes/**/*.{md,txt}"
---

# Обращение с источниками

- Никогда не править файл под `sources/`.
- Фиксировать происхождение как `source-id · дата получения · URL или место`.
```

Пользовательские правила в `~/.claude/rules/` грузятся раньше проектных, что
даёт проектным более высокий приоритет. Весь список `paths` одного правила делит
бюджет в 1 000 развёрнутых шаблонов и 4 МиБ; шаблон, который его превысил бы,
используется неразвёрнутым и не совпадает ни с чем.

### 9.5 Когда пересматривать

Пересматривайте `CLAUDE.md`, когда Claude раз за разом ищет документированную
команду; когда вы дважды поправили одно и то же правило; когда изменилась
структура; когда две инструкции конфликтуют; когда `/context` показывает
непропорциональные накладные расходы на инструкции. Просите предлагаемый дифф с
обоснованием каждого добавления и удаления — **никогда не «оптимизируй это»
вслепую**.

**О сжатии.** `CLAUDE.md` из корня проекта переживает `/compact`: Claude Code
перечитывает его с диска и внедряет заново. Вложенные файлы и правила с областью
по путям перезагружаются по мере чтения соответствующих файлов. **Инструкция,
исчезнувшая после сжатия, была дана только в разговоре** — это и есть аргумент в
пользу того, чтобы её записать.

## Глава 10. Глобальные инструкции и авто-память

Долговременное знание служит трём разным целям, и их смешение даёт раздутый
контекст и устаревшее поведение:

1. **Инструкции** говорят Claude, как себя вести — `CLAUDE.md`, правила.
2. **Справочные файлы** хранят факты и процедуры, извлекаемые по требованию.
3. **Авто-память** хранит краткие заметки, которые Claude пишет себе сам.

### 10.1 Глобальные инструкции

`~/.claude/CLAUDE.md` — используйте скупо. Уместно: предпочитаемый рабочий язык,
универсальный шлюз безопасности, устойчивая конвенция вывода, указатель на
каталог пользовательских правил. Неуместно: команды конкретного проекта, стиль
одного клиента, временные приоритеты, каталог всех инструментов, которые вы
когда-нибудь можете применить.

### 10.2 Авто-память

Включена по умолчанию. Claude сохраняет четыре вида заметок, фиксируемых полем
`type` во frontmatter файла памяти:

- `user` — ваша роль, экспертиза и рабочие предпочтения;
- `feedback` — ваши исправления и подтверждённые подходы;
- `project` — текущая работа, сроки и решения, не выводимые из кода или истории;
- `reference` — где искать информацию вне проекта.

**Хранение.** У каждого проекта свой `~/.claude/projects/<project>/memory/`, где
`<project>` выводится **из git-репозитория**, поэтому все worktree и подкаталоги
одного репозитория делят один каталог памяти. `MEMORY.md` — указатель; файлы по
темам содержат детали и читаются по требованию. Перенести хранилище можно через
`autoMemoryDirectory`. Авто-память локальна для машины и не разделяется между
машинами и облачными средами.

**Лимит загрузки.** В начале каждого разговора грузятся первые 200 строк
`MEMORY.md` либо первые 25 КБ — что наступит раньше; содержимое за этой границей
не грузится.

**Отключение.** Переключатель в `/memory` пишет `autoMemoryEnabled` в
`~/.claude/settings.json`; `{"autoMemoryEnabled": false}` в настройках проекта
отключает её только для этого проекта; `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` —
запасной путь. *Это исправляет заблуждение M06.*

> **CAUTION — хранение.** Claude Code удаляет старые транскрипты сессий по
> истечении `cleanupPeriodDays`, но **исключает каталог памяти из этой уборки**.
> `MEMORY.md` и файлы по темам живут, пока вы или Claude их не отредактируете
> или не удалите. Если ваши обязательства по хранению исходят из 30-дневной
> локальной уборки — авто-память находится вне её.

Относитесь к авто-памяти как к удобству, а не к спецификации: Claude может
запомнить ситуативное или слишком широко обобщить предпочтение. **Устойчивая
правда о проекте принадлежит проверенным файлам под контролем версий.**

### 10.3 Таблица решений: где чему место

| Информация | Где ей место |
|---|---|
| «Никогда не публиковать без одобрения» | Политика разрешений плюс напоминание в `CLAUDE.md` |
| Карта каталогов проекта | Проектный `CLAUDE.md` |
| Руководство по редакторскому стилю | `references/editorial-style.md`, извлекается по требованию |
| Правила только для одного типа файлов | `.claude/rules/*.md` с frontmatter `paths` |
| Многошаговая процедура | Скилл (глава 15) |
| Текущие открытые задачи | `notes/task-state.md` или трекер задач |
| Поправка, полезная только в этой сессии | Разговор |
| Повторяющееся предпочтение, выведенное Claude | Авто-память, после вашей проверки |
| Полная история изменений | Git |
| То, что обязано держать независимо от решения Claude | Хук `PreToolUse` (глава 17) |

### 10.4 Аудит памяти

Ежемесячно для активных пространств или после любого неожиданного поведения:

```
Перечисли все файлы инструкций и памяти, влияющие на этот проект. Для каждого
укажи область, примерную стоимость в контексте, последнее релевантное
использование и любой конфликт или устаревшую запись. Предложи изменения
диффом. Не применяй их.
```

Затем проверьте список сами через `/memory` и `/context`, а `/doctor` или
`/hooks` — когда настроенное не вступает в силу. Хук `InstructionsLoaded`
логирует, какие именно файлы инструкций загрузились, когда и почему — это
окончательный ответ, если правила с областью по путям ведут себя не так.

## Глава 11. Проектировать контекст осознанно

Контекст — это то, что есть у модели на текущем ходу: системный промпт,
описания инструментов, проектные инструкции, приложенные файлы, результаты
инструментов и история разговора. **Файл на диске не является «известным» лишь
потому, что Claude мог бы его прочитать.**

### 11.1 Осмотреть окно

`/context` — для диагностики состава, а не для погони за числом. Окна, модели и
поведение автосжатия меняются; `/autocompact` задаёт окно автосжатия явно.

### 11.2 Четыре способа вернуть фокус

**1 — Сохранять устойчивое состояние.** Находки, планы, решения и открытые
вопросы принадлежат файлам проекта. **Разговор — рабочая поверхность, а не база
данных.**

**2 — Передать эстафету чистой сессии.**

```
Подготовь передачу для чистой сессии. Включи цель, выполненную работу,
утверждённые решения, открытые вопросы, точные ссылки на файлы, уже
проведённую проверку и следующее безопасное действие. Исключи разговорную
историю, не влияющую на задачу.
```

**3 — `/clear`.** Начинает заново, сохраняя проектные инструкции и память. Он
также **очищает задачи по расписанию уровня сессии и активную цель** и закрывает
группу вкладок Chrome. Сначала сохраните передачу. Предыдущий разговор не
потерян: `/resume` либо пункт предыдущей сессии в меню отката.

**4 — `/compact [инструкции]`.** Сжимает, чтобы освободить контекст. Сжатие
**с потерями** — говорите, что обязано уцелеть:

```
/compact Сохрани все утверждённые решения, неразрешённые противоречия, пути
файлов, результаты проверок и шлюз одобрения человеком. Убери отброшенные
варианты.
```

Учтите цену: `/compact` вызывает один запрос суммаризации по всей истории и
затем инвалидирует кеш промпта.

```
                        /compact   /clear   resume   /branch   fork   /rewind
   ─────────────────────────────────────────────────────────────────────────
   История разговора      резюме    нет    восстан.  копия   копия   обрезана
   Проектный CLAUDE.md    перечит. перечит. перечит. перечит. перечит. перечит.
   Правила по путям       по совп. по совп. по совп. по совп.  то же  по совп.
   Авто-память            сохран.  сохран.  сохран.  сохран.   н/д    сохран.
   Активная цель          сохран.    нет   восстан.  сохран.   н/д    сохран.
   Задачи по расписанию   сохран.    нет   восстан.* сохран.   н/д    сохран.
   Разрешения, выданные
     на сессию            сохран.  сохран.   нет    сохран.**  нет    сохран.
   Файлы на диске         сохран.  сохран.  сохран.  сохран.  сохран. откачены
   История Git            сохран.  сохран.  сохран.  сохран.  сохран. сохран.
   ─────────────────────────────────────────────────────────────────────────
    * только неистёкшие задачи   ** сохраняются /branch, теряются --fork-session
```

### 11.3 Откат, ветка, форк, подзадача

Это решает четыре разные задачи, и их регулярно путают.

| Механизм | Что делает | Куда уходит работа |
|---|---|---|
| `/rewind` | Возвращает разговор и/или файлы к чекпойнту | Более позднее состояние удаляется |
| `/branch [имя]` | Копирует разговор и переключает вас в копию; оригинал не тронут | Тот же процесс, поэтому разрешения сессии переносятся |
| `--fork-session` | Та же копия, но в **новом процессе** | Новый процесс стартует без разрешений «на эту сессию» |
| `/fork` | Копирует разговор в фоновую сессию | Работает отдельно |
| `/subtask` | Порождает **форк-сабагента**, наследующего весь разговор | Возвращает результат; вызовы инструментов остаются вне вашего контекста |

### 11.4 Снизить постоянные накладные расходы

- Держать `CLAUDE.md` кратким, а правила условными.
- Отключать неиспользуемые MCP-серверы, плагины и агентов — **после** измерения.
- Держать крупный исходный материал в файлах и ссылаться на точные разделы.
- Делегировать ограниченный независимый анализ, а не каждое мелкое действие.
- Помнить, что включение Chrome по умолчанию грузит браузерные инструменты в
  каждую сессию и увеличивает расход контекста.

## Глава 12. Сессии: возобновление, имя, хранение

Сессия — сохранённый разговор, привязанный к каталогу проекта. CLI, Desktop, веб
и VS Code ведут собственные истории.

### 12.1 Возобновление

```
claude --continue            # самая свежая интерактивная сессия здесь
claude --resume              # выбор сессии
claude --resume <имя|id>     # напрямую
claude --from-pr <номер>     # выбор, отфильтрованный по связанным с PR сессиям
claude -n research-brief-source-audit   # задать имя при старте (--name)
```

Внутри сессии `/resume` переключает разговор, `/rename` переименовывает.
В списке выбора: `Ctrl+R` — переименовать, `Ctrl+A` — расширить на все проекты,
`Ctrl+W` — на все worktree репозитория, `Ctrl+B` — фильтр по текущей ветке;
вставка URL pull request находит создавшую его сессию.

**Возобновлённая сессия восстанавливает** историю разговора, модель, агента,
режим разрешений, активную цель и неистёкшие задачи по расписанию. Три из них
имеют условия, и именно в условиях живут неожиданности:

- **Режим.** `plan` и `bypassPermissions` не восстанавливаются никогда. `auto`
  восстанавливается, только пока аккаунт отвечает требованиям авторежима.
  Manual восстанавливается как Manual там, где новая сессия стартовала бы в
  `auto` из встроенного умолчания; но если действует `defaultMode` из файла
  настроек, сессия возобновится в *нём*. `--permission-mode` перебивает
  восстановленное.
- **Модель** **не** восстанавливается, если она выведена из обращения или
  запрещена через `availableModels`; если при запуске её выбирает флаг `--model`
  или переменная окружения семейства `ANTHROPIC_MODEL`; а также у провайдеров с
  собственными идентификаторами развёртывания.
- **Задачи по расписанию** восстанавливаются только неистёкшие, а фоновые
  Bash-задачи и мониторы не восстанавливаются вовсе.

**Не восстанавливаются** `--mcp-config`, `--settings`, `--plugin-dir`,
`--fallback-model` и каталоги, добавленные через `--add-dir` — передайте их
заново. Каталоги, добавленные посреди сессии через `/add-dir`, тоже не
восстанавливаются.

**Подводный камень:** сессии, чьим *первым* промптом была команда `/loop`, не
появляются в списке выбора и пропускаются `--continue`. Если задача по
расписанию будто бы исчезла — обычно причина в этом.

### 12.2 Называть по результату

Хорошие имена переживают неделю: `client-x-brief-source-audit`,
`accessibility-remediation-plan`, `invoice-workflow-test-2026-08`.

Избегайте `test`, `new chat` и того, чем случайно оказался первый промпт.
Безымянные интерактивные сессии получают отображаемое имя вида `my-app-3f` —
оно **не** является дескриптором для возобновления — плюс сгенерированный из
первого промпта заголовок, который им является.
