# Часть IV — Расширение Claude Code

Каждая глава этой части — ещё и глава о цепочке поставок. Проходите её только
после глав 1–12.

## Глава 13. Подключение внешних инструментов через MCP

Model Context Protocol — открытый стандарт подключения ИИ-клиентов к внешним
инструментам и данным. Он расширяет возможности и доверие **одновременно**:
подключённый инструмент действует с теми полномочиями, которые вы ему дали.

### 13.1 Области видимости

| Область | Хранение | Применение |
|---|---|---|
| Local (по умолчанию) | `~/.claude.json` | Один проект, текущий пользователь; приватная конфигурация |
| User | `~/.claude.json` | Доступно во всех ваших проектах |
| Project | `.mcp.json` в корне репозитория | Общая командная конфигурация, коммитится |

У проектной области есть механизм одобрения, который часто упускают. Сервер
уровня проекта из `.mcp.json` отображается как `⏸ Pending approval`, пока вы не
запустите `claude` интерактивно и не одобрите его; отклонённые серверы
записываются в `disabledMcpjsonServers`. С 2.1.196 одобрения читаются только из
файлов настроек, **не** закоммиченных в репозиторий, пока вы не доверите
рабочее пространство — поэтому клонированный репозиторий не может одобрить
собственные серверы. **Это и есть контроль, который не даёт вредоносному pull
request незаметно подключить сервер.**

> **CAUTION.** Никогда не помещайте буквальные учётные данные в `.mcp.json`.
> Используйте OAuth, где провайдер его поддерживает, либо подстановку `${VAR}`
> со ссылкой на переменную окружения, и аккаунт с минимальными правами.

### 13.2 Транспорты

```
claude mcp add --transport http notion https://mcp.notion.com/mcp --scope project
claude mcp list
claude mcp get notion
```

- **HTTP** — предпочтительный. В JSON `type: "http"`; `streamable-http`
  принимается как псевдоним.
- **SSE** — **устарел**. Используйте HTTP, где он доступен.
- **stdio** — локальный процесс. Всё после `--` передаётся серверу без
  изменений.
- **WebSocket** (`type: "ws"`) — постоянный двунаправленный, для серверов,
  которые шлют события. Не поддерживает ни OAuth, ни флаг `--transport`;
  аутентификация только через заголовки.

Запись JSON с `url`, но без `type` — ошибка конфигурации: Claude Code читает
запись без типа как stdio и пропускает её с явным сообщением.

Внутри сессии `/mcp` показывает статус, завершает OAuth и перечисляет
инструменты сервера.

### 13.3 Безопасная процедура установки

1. Найти официальный репозиторий или документацию провайдера. Проверить URL
   посимвольно.
2. Определить минимум данных и действий, нужных задаче.
3. Использовать тестовый аккаунт или пространство с минимальными правами.
4. Осмотреть исходники, издателя, пакет и сетевые адресаты, где возможно.
5. Выбрать самую узкую работающую область.
6. Держать секреты вне `.mcp.json` и вне системы контроля версий.
7. Начать новую сессию, чтобы конфигурация перечиталась.
8. Аутентифицироваться и осмотреть выставленные инструменты через `/mcp`.
9. Сперва выполнить операцию только на чтение.
10. Для записи добавить явное одобрение — правило `ask` или шлюз человека.

> **CAUTION — вывод инструмента это недоверенный ввод.** Содержимое, возвращённое
> MCP-сервером, может содержать инструкции, адресованные агенту, приватные данные
> или материал, задуманный, чтобы увести задачу. Это **непрямая инъекция
> промпта**. Считайте любой результат инструмента данными, ограничивайте, что
> агент может делать дальше, и требуйте подтверждения перед любой внешней
> записью.

### 13.4 Стоимость контекста — измерять, а не предполагать

Определения инструментов действительно занимают контекст, но это частично
смягчено: Tool Search откладывает многие определения до надобности. Измеряйте
через `/context` и `/usage`. Убирать ненужные серверы всё равно стоит —
аргумент здесь безопасность и ясность, а не токены.

### 13.5 Организационный контроль

Администраторы могут ограничивать, какие серверы пользователи вправе добавлять,
через списки разрешений и запретов в управляемой конфигурации.
`deniedMcpServers` блокирует named-сервер целиком — включая `claude-in-chrome`,
и именно так организация централизованно выключает интеграцию с браузером.

## Глава 14. Переменные окружения и секреты

Файл `.env` — удобство разработчика, **а не граница безопасности**. Коммитьте
только шаблон с именами, никогда со значениями.

### 14.1 Почему «Claude этого не видит» небезопасно

Если Claude вправе читать `.env`, содержимое попадает в вывод инструмента. Если
он запустит команду, печатающую переменную окружения, значение попадёт в
транскрипт открытым текстом. Подпроцесс может его передать. Фраза в `CLAUDE.md`
«не читай секреты» — предпочтение, а не принуждение. *Это заблуждение M04 и самое
частое ложное убеждение у новичков.*

### 14.2 Слоистые механизмы контроля

1. **Минимальные права.** Выдавать учётные данные, ограниченные сервисом,
   действием и средой. Это **единственный** контроль, ограничивающий ущерб уже
   после раскрытия.
2. **Deny-правила разрешений.** Блокировать чтение файлов и каталогов с
   секретами.
3. **Контроль учётных данных в песочнице.** `sandbox.credentials.files` и
   `.envVars`, `deny` или `mask`. Запрещённые переменные сбрасываются перед
   каждой командой в песочнице.
4. **Сетевые ограничения.** Запретить `curl` и `wget` на уровне Bash и разрешать
   конкретные домены через `WebFetch(domain:…)`.
5. **Дисциплина вывода.** Никогда не выводить, не логировать и не подставлять
   секрет в команду, которую увидит модель.
6. **Гигиена git.** Игнорировать файлы секретов и просматривать staged-дифф
   перед каждым коммитом.
7. **Ротация.** Немедленно отзывать, если учётные данные попали в транскрипт,
   коммит, лог, артефакт или недоверенный сервис.

Не вставляйте конфигурацию безопасности, не проверив, что она блокирует.
Попросите Claude попытаться выполнить запрещённое чтение и подтвердите отказ,
затем проверьте в `/permissions`, из какого файла пришло правило.

### 14.3 Реагирование на инцидент

1. Остановить задачу.
2. **Отозвать или сменить учётные данные. Это делается раньше всего остального.**
3. Убрать их из файлов, логов и любого опубликованного артефакта.
4. Если закоммичено — выполнить процедуру удаления чувствительных данных
   хостинг-провайдера; удалить последнюю строку недостаточно.
5. Просмотреть транскрипт сессии, журналы аудита подключённых систем и — для
   организаций — журнал аудита Claude Code.
6. Исправить тот механизм контроля, который допустил раскрытие, и добавить на
   него регрессионную проверку.

## Глава 15. Превращать повторяемую работу в скиллы

Скилл — переиспользуемый пакет инструкций и необязательных ресурсов. Claude
вызывает его, когда описание совпадает с задачей, либо вы зовёте его как
`/имя-скилла`. В отличие от `CLAUDE.md`, тело скилла грузится только при
использовании, поэтому длинный справочный материал почти ничего не стоит, пока
не понадобится.

```
~/.claude/skills/<name>/SKILL.md     # пользовательская область
.claude/skills/<name>/SKILL.md       # область проекта
```

Пользовательские команды слились со скиллами: и `.claude/commands/deploy.md`, и
`.claude/skills/deploy/SKILL.md` создают `/deploy`.

### 15.1 Строить скилл из наблюдённой работы

1. Выполнить процедуру вручную, вместе с Claude, один раз.
2. Определить входы, инструменты, решения, выходы и режимы отказа.
3. Попросить Claude написать минимальный скилл из того, что реально произошло.
4. Прочитать каждый файл и каждую выдачу инструмента.
5. Проверить на действительно другом примере.
6. Исправить вывод руками.
7. Обновить скилл **общим** уроком, а не случайной деталью.

### 15.2 Frontmatter, важный для безопасности

| Поле | Действие |
|---|---|
| `allowed-tools` | Инструменты, которыми Claude может пользоваться **без спроса** в течение хода, вызвавшего скилл. Выдача снимается с вашим следующим сообщением |
| `disallowed-tools` | Инструменты, убранные из пула на время активности скилла; тоже снимается со следующим сообщением |
| `disable-model-invocation: true` | Вызвать может только вы. Также предотвращает предзагрузку в сабагентов и запуск при срабатывании задачи по расписанию со скиллом в качестве промпта (2.1.196+) |
| `context: fork` | Запускает скилл в собственном контексте сабагента |
| `shell` | `bash` (по умолчанию) или `powershell` для инлайн-shell в теле скилла |
| `hooks` | Хуки жизненного цикла, регистрируемые при вызове скилла, активные **до конца сессии**; `once: true` ограничивает одним запуском |

Два поведения легко упустить. `${CLAUDE_SKILL_DIR}` и `${CLAUDE_PROJECT_DIR}`
подставляются и в теле, и в Bash-правилах внутри `allowed-tools`, поэтому скилл
может запустить вложенный скрипт без запроса. И отрендеренный `SKILL.md`
попадает в разговор один раз и **остаётся до конца сессии** — Claude Code не
перечитывает файл на последующих ходах, поэтому пишите постоянное руководство, а
не одноразовые шаги.

Ставьте `disable-model-invocation: true` на всё, что имеет побочные эффекты —
`/commit`, `/deploy`, `/send-message`. Вам не нужно, чтобы Claude сам решал, что
код выглядит готовым к отгрузке.

### 15.3 Ревью безопасности скилла

Перед установкой или запуском стороннего скилла осмотрите: `SKILL.md` и каждый
упомянутый файл; `allowed-tools`, `disallowed-tools` и блок `hooks`; инлайн-shell;
установку пакетов и сетевые вызовы; читаемые и записываемые пути; доступ к
учётным данным; любую инструкцию, отговаривающую от проверки или подавляющую
вывод.

Контроли: `disableBundledSkills` выключает все встроенные скиллы кроме
`/doctor`; `skillOverrides` ставит отдельный скилл в `"off"` или
`"user-invocable-only"` без правки файла; deny-правило `Skill` ограничивает
доступ Claude; `disableSkillShellExecution` заменяет строки инлайн-shell
заглушкой.

> **CAUTION.** Звёзды, число загрузок, рекомендация из видео или официально
> звучащее имя — **не ревью безопасности**. Закрепляйте проверенную версию и
> повторяйте ревью после каждого обновления. *Заблуждение M12.*

## Глава 16. Делегировать ограниченную работу сабагентам

Сабагент — специализированный экземпляр с собственным окном контекста,
системным промптом, доступом к инструментам и разрешениями. Делегируйте, когда
независимость, фокус или параллелизм улучшают результат, — а не чтобы мелкое
действие выглядело значительным.

### 16.1 Свежий контекст, форки и почему это важно

Обычный сабагент стартует с чистого листа: он получает собственный системный
промпт, сообщение делегирования, иерархию `CLAUDE.md`, снимок git-status и
предзагруженные скиллы. Он **не** получает историю разговора родителя, его стиль
вывода и авто-память.

**Форк** устроен иначе: он наследует весь разговор, системный промпт родителя,
инструменты и модель и делит с родителем кеш промпта. `/subtask` создаёт именно
такой.

> **CAUTION — главная поправка этой главы.** Режим форка **включён по умолчанию в
> интерактивных сессиях**, управляется переменной `CLAUDE_CODE_FORK_SUBAGENT`
> (`1` — вкл, `0` — выкл). «Ревьюер», созданный походя в интерактивной сессии,
> унаследует те самые рассуждения, которые должен проверять. Если нужна
> настоящая независимость — используйте явное определение агента и подтвердите
> контекст ревьюера. *Заблуждение M03.*

Независимость для целей ревью убывает так:
**сабагент > участник команды > агент воркфлоу > форк.**
Неуточнённая просьба «дай ревьюера» в интерактивной сессии даёт **наименее**
независимый вариант.

### 16.2 Где живут сабагенты и кто побеждает

| Источник | Область | Приоритет |
|---|---|---|
| Управляемые настройки | Вся организация | 1 (высший) |
| Флаг CLI `--agents` | Текущая сессия | 2 |
| `.claude/agents/` | Текущий проект | 3 |
| `~/.claude/agents/` | Все ваши проекты | 4 |
| `agents/` плагина | Где плагин включён | 5 (низший) |

`/agents` больше не открывает редактор агентов *(изменено в 2.1.198)*: он
направляет попросить Claude создать или обновить агента, которого вы затем сами
читаете как Markdown. *Заблуждение M13.* `/list-agents` (псевдоним `/peers`)
перечисляет сабагентов, участников команды и другие сессии.

Ключевое следствие о разрешениях: родитель в `acceptEdits`, `bypassPermissions`
или `auto` побеждает собственный `permissionMode` сабагента — а `auto` это то,
с чего сессии стартуют на Pro, Max и Team. Фон — поведение по умолчанию,
вложенность идёт на три слоя, предел — двадцать одновременных сабагентов.

### 16.3 Скилл или сабагент?

| Потребность | Что предпочесть |
|---|---|
| Применить процедуру в текущем контексте | Скилл |
| Независимое суждение, свежий контекст | Сабагент (не форк) |
| Продолжить текущее рассуждение в стороне, не засоряя контекст | Форк / `/subtask` |
| Параллельный ограниченный анализ | Несколько сабагентов |
| Детерминированное действие с файлом или командой | Скрипт или хук — **не модель** |
| Переиспользуемая процедура, координирующая ревьюеров | Скилл, вызывающий сабагентов |
| Десятки и сотни агентов с кодифицированной оркестрацией | Динамический воркфлоу (глава 22) |
| Равные, которые общаются и делят список задач | Команды агентов (глава 30) |

### 16.4 Бриф делегирования

Каждый промпт сабагенту должен называть: точный вопрос; файлы или источники,
которыми можно пользоваться; разрешённые инструменты и действия; требуемый
формат возврата; критерии успеха; когда остановиться и доложить о
неопределённости. **Никогда не делегируйте «почини всё».**

## Глава 17. Поведение по событиям: хуки

Хук выполняет настроенное действие в момент события жизненного цикла. Хуки —
способ сделать так, чтобы нечто произошло **из-за события**, а не потому, что
модель вспомнила предложение. Это единственный механизм в книге, одновременно
детерминированный и написанный пользователем.

### 17.1 События

Наиболее значимые на практике:

- `SessionStart`, `SessionEnd` — сопоставляются по типу старта (`startup`,
  `resume`, `clear`, `compact`, `fork`) и по причине завершения.
- `UserPromptSubmit` — до обработки промпта; выход 2 отклоняет его.
- `PreToolUse` — до вызова инструмента; выход 2 блокирует его.
- `PermissionRequest` — когда вызову нужно решение по разрешению; возвращайте
  JSON-решение, а не выход 2.
- `PermissionDenied` — после отказа авторежима; может задать `retry`.
- `PostToolUse`, `PostToolUseFailure`, `PostToolBatch` — постфактум; **не могут
  отменить внешний побочный эффект**.
- `Stop`, `StopFailure`, `SubagentStart`, `SubagentStop`, `TeammateIdle` —
  жизненный цикл хода и агента; выход 2 на `Stop` не даёт остановиться.
- `TaskCreated`, `TaskCompleted` — общий список задач; выход 2 блокирует
  операцию.
- `PreCompact`, `PostCompact`, `InstructionsLoaded`, `ConfigChange`,
  `CwdChanged`, `DirectoryAdded`, `FileChanged`, `WorktreeCreate`,
  `WorktreeRemove`, `Notification`, `MessageDisplay`, `Elicitation`,
  `ElicitationResult`.

`ConfigChange` заслуживает отдельного упоминания: он позволяет организации
аудировать или блокировать изменения настроек, сделанные во время сессии.

### 17.2 Типы обработчиков

Доступны пять: `command` (shell или exec, с `async` и `asyncRewake`), `http`
(POST, с интерполяцией заголовков `allowedEnvVars`), `mcp_tool` (вызов
инструмента на уже подключённом сервере), `prompt` (однооборотная оценка
моделью, плейсхолдер `$ARGUMENTS`, по умолчанию 30 секунд) и `agent` (порождает
сабагента; экспериментально).

Таймауты по умолчанию: 600 секунд для `command`, `http` и `mcp_tool` — 30 секунд
под `UserPromptSubmit`, 10 под `MessageDisplay`; 30 для `prompt` и 60 для
`agent`. Хуки `SessionEnd` делят бюджет в 1,5 секунды.

### 17.3 Модель угроз

Хук — исполняемый код, запускаемый автоматически. Создавайте их из проверенных
скриптов в репозитории, а не вставляйте из непроверенных источников; помните,
что хуки из файлов настроек подчиняются доверию к рабочему пространству, а
скилл может зарегистрировать хук, живущий до конца сессии.

## Глава 18. Оценка и установка плагинов

Плагин — распространяемый набор. Маркетплейс — каталог, указывающий Claude Code
на плагины; **это не проверка безопасности уровня магазина приложений**.

### 18.1 Что может содержать плагин

| Каталог или файл | Содержимое |
|---|---|
| `.claude-plugin/plugin.json` | Манифест: имя (пространство имён скиллов), описание, версия, автор |
| `skills/` | Скиллы, вызываемые как `/plugin-name:skill-name` |
| `commands/` | Устаревшие плоские файлы-скиллы |
| `agents/` | Определения сабагентов |
| `hooks/hooks.json` | Обработчики событий |
| `.mcp.json` | Конфигурации MCP-серверов |
| `.lsp.json` | Конфигурации языковых серверов |
| `monitors/monitors.json` | **Фоновые мониторы**, запускаемые автоматически; каждая строка stdout приходит к Claude как уведомление |
| `bin/` | **Исполняемые файлы, добавляемые в `PATH` инструмента Bash**, пока плагин включён |
| `settings.json` | Настройки по умолчанию — включая `agent`, активирующий одного из агентов плагина как **основной поток**, заменяя системный промпт, ограничения инструментов и модель |
| `output-styles/` | Стили вывода, которые плагин может навязать через `force-for-plugin` |

Прочтите эту таблицу дважды. Плагин может положить исполняемые файлы в ваш
`PATH`, запустить фоновые процессы, сменить системный промпт основной сессии и
зарегистрировать хуки — **всё это при включении**.

### 18.2 Шлюз установки

Перед добавлением маркетплейса или плагина:

1. Подтвердить точного издателя и репозиторий.
2. Прочитать манифест и сверить каждый компонент с таблицей выше.
3. Просмотреть хуки, исполняемые файлы, установочные скрипты, MCP-адреса,
   мониторы и выдачи инструментов.
4. Поискать сетевые вызовы, чтение учётных данных, persistence и
   автообновления.
5. Закрепить проверенную версию. Плагин без поля `version` берёт версию из
   цепочки запасных вариантов, а источник типа `command` обновляется в обход
   версионного шлюза.
6. Проверить в изолированном профиле через `--plugin-dir`.
7. Измерить влияние на контекст и расход.
8. Записать владельца, назначение, версию, дату одобрения и процедуру удаления.

Anthropic ведёт два публичных маркетплейса: `claude-plugins-official`
(курируется Anthropic, регистрируется автоматически при первом интерактивном
запуске) и `claude-community` (сторонние заявки после ревью и автоматического
скрининга; одобренные закрепляются на коммит SHA). **Ни один из них не является
гарантией.**

> **CAUTION.** Официальная документация утверждает, что плагины и маркетплейсы
> могут выполнять произвольный код с вашими пользовательскими привилегиями.
> «Установлено» означает «доверено к выполнению», а не «видно в меню».
> *Заблуждение M18.*

### 18.3 Собрать вместо того, чтобы принести

Если из большого плагина нужна одна процедура, написать маленький локальный
скилл по её идее обычно безопаснее и проще, чем импортировать непрозрачный код и
неиспользуемые коннекторы. Сохраняйте лицензии и указание авторства при
адаптации чужого материала.

## Глава 19. Стили вывода: Claude Code за пределами разработки

Стили вывода изменяют **системный промпт**: они меняют роль, тон и формат ответа
по умолчанию и — единственные среди механизмов этой книги — могут вовсе убрать
встроенные инструкции Claude Code по разработке ПО. Для читателя, применяющего
Claude Code к исследованиям, операциям, аналитике или письму, это самое прямое
соответствие продукта задаче.
