# Отрисовка

## ASCII-дерево в чат

Задача этого блока — чтобы человек сориентировался, не открывая ссылку. Значит
он должен помещаться на экран целиком. Ориентир: **не длиннее 40 строк**.

Формат:

```
danilandersonai-pixel/  ·  6 репозиториев  ·  обновлено 28 июля

├── Demo · public · push 28 июл
│   свадебный сайт-приглашение, статика без сборки
│   ├── CLAUDE.md
│   ├── .github/workflows/deploy-pages.yml
│   └── yegor-diana-wedding/
│       ├── index.html
│       └── assets/{css,js}
│   ⎇ main · claude/github-repos-agent-qxj4zi (без PR)
│
├── claude-skills · public · push 14 июн
│   коллекция скиллов для Claude Code
│   └── ...
│
└── nail · public · push 25 апр · спит 3 месяца
```

Правила, которые делают этот блок читаемым:

- **Однострочное описание сразу под именем.** Это то, ради чего всё затевалось:
  человек не должен вспоминать, что такое `warp-loader`.
- **Сёстринские директории схлопывай** в `assets/{css,js}`, когда внутри лежит
  только структура без интересных файлов. Экономит строки без потери смысла.
- **Ветки — строкой `⎇` под деревом**, только если их больше одной. Одна
  единственная `main` не несёт информации и тратит строку.
- **Незакрытые хвосты — прямо в строке репозитория**, коротко: `(без PR)`,
  `PR #3 висит 20 дней`. Это то, что человек ищет глазами.
- **Спящие репозитории** сворачивай в одну строку без дерева.

После дерева — одна-две строки живого текста: что изменилось с прошлого раза,
куда стоит вернуться. Не пересказывай дерево словами, оно уже перед глазами.
Скажи то, чего в нём не видно.

## HTML-страница

### Как пользоваться шаблоном

`assets/template.html` — самодостаточная страница: стили, разметка и рендерер
уже внутри. От тебя нужна одна операция — заменить строку

```js
const DATA = __REPO_MAP_DATA__;
```

на собранный JSON. Ничего больше в шаблоне трогать не нужно.

Шаблон рассчитан на публикацию через инструмент `Artifact`: в нём нет тегов
`<!doctype>`, `<html>`, `<head>` и `<body>` — их добавляет сам инструмент.

### Что шаблон делает сам

Не дублируй эту работу вручную, она уже сделана:

- сортирует репозитории по дате последнего push, свежие сверху;
- раскрывает дерево первых двух уровней, глубже — по клику;
- помечает приватные репозитории значком, публичные оставляет чистыми;
- показывает ветки и PR в боковой колонке карточки;
- подсвечивает незакрытые хвосты из `flags`;
- фильтрует по строке поиска — и по именам репозиториев, и по именам файлов;
- переключается между светлой и тёмной темой вслед за темой читателя;
- на узком экране складывает колонки в одну.

### Если шаблона не хватает

Дополняй сам шаблон, а не пиши разовую вёрстку поверх. Смысл шаблона в том, что
карта выглядит одинаково от запуска к запуску — человек привыкает, где что
лежит, и читает её быстрее с каждым разом. Разовая вёрстка этот эффект убивает.

При правках шаблона держи два требования:
- страница остаётся самодостаточной: никаких внешних шрифтов, скриптов и
  картинок, иначе она не отрисуется;
- обе темы остаются рабочими — читатель может смотреть в любой.

### Публикация

```
Artifact(
  file_path: "<путь к заполненному файлу>",
  favicon: "🗺️",
  description: "Карта репозиториев <owner> на <дата>"
)
```

Держи `favicon` одинаковым между запусками и публикуй **в тот же файл**, если
обновляешь карту — тогда ссылка остаётся прежней и человек может держать её в
закладке. Новый путь к файлу означает новый адрес, и старая закладка протухает.
