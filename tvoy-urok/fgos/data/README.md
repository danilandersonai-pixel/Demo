# Данные реестра ФГОС

Выдержки из **федеральных рабочих программ** (ФРП) с портала
[edsoo.ru](https://edsoo.ru/rabochie-programmy/). С 2023 г. именно ФРП, а не
примерные программы, являются нормативной основой.

## Почему данные, а не модель

Требования стандарта — нормативный текст. Модель, которую спросили «что
требует ФГОС», выдаст правдоподобную выдумку. Поэтому справочник
детерминированный: он даёт чек-лист как данность, а модель (ФГОС-инспектор)
только судит, выполнен ли он.

## Версионность обязательна

ФРП правятся приказами Минпросвещения — например, № 729 от 08.10.2025,
№ 808 от 10.11.2025; изменения в ФООП вступают с 01.09.2026.

Реальный случай из практики: между редакциями **2023 и 2025 гг.** курс
истории России 6 класса был продлён до первой трети XVI в. Темы «Василий III»,
«приказная система», «Боярская дума» переехали **из 7 класса в 6**. Реестр,
собранный по редакции 2023 г., уверенно и неправильно сообщал бы учителю о
несоответствии класса.

Поэтому в каждом файле обязательны:

- `source.url` — прямая ссылка на использованный PDF;
- `source.extracted` — дата извлечения;
- `source.edition_note` — чем эта редакция отличается, на что смотреть;
- `source.revision_check_due` — дата, после которой `SubjectSpec.revision_stale()`
  начинает выдавать предупреждение в отчёте.

## Структура файла

```jsonc
{
  "source":  { ... },              // см. выше
  "subject": "История",
  "metasubject": {                 // УУД, общие для всех классов предмета
    "groups": [{ "code", "title", "items": [{ "code", "text" }] }]
  },
  "result_groups": [               // группы планируемых результатов
    { "code": "hron",
      "title": "Знание хронологии",
      "evidence_roles": ["timeline"],        // роли слайдов = признак покрытия
      "evidence_hint": "слайд-таймлайн с датами",
      "evidence_source_quote": false }       // засчитывать цитаты источника
  ],
  "grades": {
    "6": {
      "period": "...",                        // что за курс
      "boundary_note": "...",                 // границы курса — для проверки класса
      "subject_results": [{ "code": "hron", "items": ["..."] }],
      "sections": [{
        "code": "ru6.vasiliy3",
        "title": "...",
        "keywords": ["василий iii", "псков"], // по ним тема сопоставляется с разделом
        "units": ["..."],                     // дидактические единицы — чек-лист охвата
        "required_terms": ["удельная система"],
        "required_dates": ["1510"],
        "anachronism_guard": {                // необязательно
          "comment": "Титул царя принят Иваном IV в 1547 г.",
          "forbidden_terms": ["царская семья"],
          "period_end_year": 1533
        }
      }]
    }
  }
}
```

`result_groups` живут в данных, а не в коде: у каждого предмета свои
результаты — у истории работа с картой и источниками, у биологии описание
процессов и классификация.

## Как добавить предмет

1. Скачать действующую ФРП с edsoo.ru (брать **самую свежую** редакцию —
   искать по году в пути, напр. `/2025/07/`).
2. `pdftotext -layout frp.pdf frp.txt`, найти разделы `СОДЕРЖАНИЕ ОБУЧЕНИЯ`
   (дидактические единицы) и `ПЛАНИРУЕМЫЕ РЕЗУЛЬТАТЫ`.
3. Создать `<предмет>.json` по структуре выше. Ключевые слова разделов
   писать в нижнем регистре; поиск идёт по основам слов, поэтому падеж
   не важен, но многословные ключи («природные зоны») получают больший вес,
   чем общие («природа») — это защищает от попадания темы не в тот класс.
4. Зарегистрировать файл в `_SUBJECT_FILES` (`fgos/registry.py`), включая
   синонимы названия предмета, как его может написать учитель.
5. Добавить кейсы в `tests/test_fgos.py::test_all_subjects`.

Если предмета в реестре нет, проверка возвращает `None` — пайплайн работает,
просто без отчёта о соответствии.
