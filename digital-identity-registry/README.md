# Реестр цифровых личностей

Локальное приложение, которое помнит, какому сервису вы отдали какую почту,
какой номер и какие данные — и показывает, что от чего зависит. Никаких
утёкших баз, никакого бэкенда, никакой синхронизации.

Одна работа приложения — **показывать связи**: карта «личности ↔ сервисы»
с подсветкой опасных цепочек восстановления.

## Запуск

```bash
npm install
npm run dev      # → http://localhost:5173
```

Прочее: `npm test` (криптослой и аналитика), `npm run build`, `npm run preview`.

## Чего приложение не делает никогда

- **не хранит пароли и коды 2FA** — для этого менеджер паролей;
- **не делает ни одного сетевого запроса** — в `index.html` жёсткий CSP с
  `connect-src 'none'`, шрифты лежат в `public/fonts`;
- **не проверяет утечки** и не обращается к внешним базам;
- **не синхронизируется** и не имеет облачного аккаунта.

Это архитектурные инварианты. Фичи, которые их нарушают, отклоняются.

## Как устроено хранение

- Все данные шифруются целиком: AES-256-GCM, ключ из мастер-пароля через
  PBKDF2-SHA256 (600 000 итераций), соль генерируется при инициализации.
- В IndexedDB лежит ровно одна запись — шифрованный конверт. При ручном
  просмотре базы не читается ни один адрес, домен или имя сервиса.
- **Мастер-пароль не восстанавливается.** Нигде не хранится ни он, ни ключ.
  Страховка — регулярный экспорт бэкапа (Настройки → «Экспортировать бэкап»).
- Экспорт — один `.json` с шифротекстом и параметрами KDF; открывается тем же
  паролем. Файлы бэкапов добавлены в `.gitignore` — не кладите их в git
  и облака.

## Что смотреть

- **Карта** — личности слева, сервисы справа, связи патч-кабелями. Цвет —
  критичность сервиса, пунктир — канал восстановления. Красным подсвечены:
  критичный сервис на публичной/мусорной почте, восстановление критичного
  сервиса на мусорный ящик, замкнутые на себя recovery, скомпрометированные
  личности.
- **Миграция** — порядок переезда: сначала фундамент (почтовые провайдеры),
  потом зависимые, с учётом цепочек recovery.
- **Журнал** — спам на алиас автоматически показывает подозреваемые
  источники утечки.
- **Ревизия** — что год не пересматривалось, где критичный сервис на SMS,
  какие удаления зависли без подтверждения.

Пощупать всё сразу: Настройки → «Загрузить демо-данные» — в наборе нарочно
есть каждый класс проблем.

## Замечание про dev-режим

Боевой CSP запрещает соединения полностью. Dev-серверу Vite нужны WebSocket
для HMR и inline-скрипт React Fast Refresh — эти два послабления подставляет
плагин `devOnlyCsp` из `vite.config.ts` **только** в режиме `serve`.
`npm run build` отдаёт `index.html` с нетронутым `connect-src 'none'`;
проверить можно, открыв DevTools → Network на собранной версии — за всю
сессию там ноль исходящих запросов.

## Шрифты

Unbounded (заголовки), Golos Text (текст), JetBrains Mono (адреса и домены) —
все с кириллицей, лежат локально в `public/fonts`. Моноширинный для адресов —
функция, а не эстетика: в нём видно разницу между `l` и `1` в алиасе.
