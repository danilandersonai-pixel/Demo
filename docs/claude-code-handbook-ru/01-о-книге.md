# О книге и как её читать

## Что это за книга

Справочник о том, как безопасно и продуктивно управлять Claude Code —
не «какие есть функции», а что можно доверять, что нужно принудительно
ограничить, какое свидетельство подтверждает корректность и что организация
должна уметь показать аудитору.

Четыре тезиса книги:

1. Возможности без определённого и **наблюдаемого условия завершения** — это не
   продуктивность.
2. Инструкция, разрешения, песочница и изоляция ОС — четыре разных слоя стека
   контроля, **принудительно работают только нижние три**. Смешение их — самая
   частая причина потери контроля.
3. Сторонние скиллы, плагины, маркетплейсы, каналы и MCP-серверы — это
   **зависимости цепочки поставок**, и управлять ими надо соответственно.
4. Единица доверия — **наблюдаемое свидетельство**, а не заключительная фраза
   агента «готово».

Однофразовая версия: внедряйте возможности с той скоростью, с какой способны
подтверждать их результат, и не быстрее.

## Базис проверки и период полураспада

Каждое утверждение о поведении продукта сверялось с официальной документацией
Anthropic: базис — Claude Code 2.1.241 (23 августа 2026), повторная сверка —
2.1.246 (26 августа 2026).

Автор прямо предупреждает: интерфейсы, лимиты, права по тарифам и превью-функции
меняются еженедельно, и период полураспада такого текста измеряется неделями.
Тридцать пять заметок о поведении, привязанном к конкретному релизу, приходятся
примерно на девяносто релизов.

## Пометки доказательности

Автор маркирует утверждения, и эти же пометки сохранены здесь:

| Пометка | Значение |
|---|---|
| VERIFIED | Подтверждено официальной документацией на 23 августа 2026 |
| PRACTITIONER NOTE | Приём из практики автора или сообщества. Не гарантия продукта |
| UNVERIFIED | Правдоподобно и в обороте, но не подтверждается первоисточником |
| CAUTION | Действие с существенными последствиями: безопасность, приватность, деньги, регуляторика, потеря данных |
| CHECKPOINT | Свидетельство, которое читатель должен увидеть, прежде чем идти дальше |

## Чего книга не устанавливает (слова самого автора)

- **Документация — не работающая система.** Проверка велась по документации;
  реальная установка ведёт себя иначе. Непроверяемые утверждения помечены
  UNVERIFIED (их три, все про то, что предлагает селектор `/effort`).
- **Платные стандарты проверены структурно, не текстуально.** Идентификаторы
  контролей ISO/IEC 27001:2022 были доступны только через вторичные пересказы.
- **Один автор, один рецензент.** Независимого разбора не было; черновик и ревью
  делались с помощью ИИ-агентов, то есть один класс инструментов и писал, и
  проверял.
- **Модель зрелости и упражнения — предложения, а не результаты исследования.**

## Независимость

Книга не издана Anthropic, не одобрена ею и не аффилирована с ней.

## Четыре маршрута чтения

| Маршрут | Главы | О чём |
|---|---|---|
| **Базовый** | 1–12 | От установки до управляемого метода работы. Пройти до того, как добавлять автономию и сторонние компоненты — без него ничего из глав 13+ не безопасно |
| **Расширения** | 13–19 | Что меняет досягаемость агента: коннекторы, секреты, скиллы, сабагенты, хуки, плагины, стили вывода. Каждая глава здесь — ещё и глава о цепочке поставок |
| **Автономия** | 20–30 | Браузер, цели, воркфлоу, три разных планировщика, облако, каналы, артефакты, команды агентов. Организующий вопрос не «может ли оно это» а «как я узнаю, что оно сделало» |
| **Управление** | 31–33 + приложения D, F, K | Для тех, кто отвечает перед кем-то ещё: управляемая политика, резидентность данных, наблюдаемость, аудит, доступность |

Глава 34 собирает всё в один верифицированный результат; Приложение E — чек-лист
выпуска к ней.

**Учитесь в одноразовой папке.** Не изучайте разрешения, хуки, действия в
браузере и планировщики в рабочем репозитории и не открывайте домашний каталог
как проект.

## Сквозной пример книги

Все примеры строят **Research Brief Workspace** — намеренно не программный
проект: агентная работа подаётся как общая операционная дисциплина, и пример без
системы сборки делает дисциплину видимой.

```
research-brief-workspace/
├── CLAUDE.md
├── README.md
├── sources/          # неизменяемый исходный материал
├── notes/            # рабочие выписки
├── drafts/           # неутверждённые черновики
├── deliverables/     # только утверждённое человеком
├── references/       # политики, которые агент подтягивает по запросу
├── templates/        # переиспользуемые структуры
└── .claude/
    ├── settings.json
    ├── rules/
    ├── skills/
    └── agents/
```

К главе 34 воркфлоу исследует ограниченный вопрос, ведёт реестр свидетельств,
пишет черновик, отдаёт его на ревью агенту, который его не писал, рендерит
результат и останавливается на человеческом шлюзе выпуска, который не может
пройти сам.
