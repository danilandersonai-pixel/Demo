# Часть IX — Итоговая работа

## Глава 34. Построить верифицированного агента research-брифов

Метод автора называется **Evidence-Gated Delivery** — поставка со шлюзами на
свидетельствах. Восемь стадий, у каждой названный шлюз и наблюдаемое
свидетельство.

### Стадия 1 — Установить контроль

Узкий каталог проекта, Git с чистой базой, правила разрешений с проверенными
deny, включённая песочница.

**Свидетельство:** запрещённое чтение действительно блокируется, и вы видите, из
какого файла пришло правило.

### Стадия 2 — Создать знание о проекте

1. Довести `CLAUDE.md` до объёма менее 200 строк.
2. Добавить `references/source-policy.md` с правилом извлечения, а не встраивать
   его в текст.
3. Добавить правило с областью по путям для `sources/**`, запрещающее изменение.
4. Добавить `templates/claim-ledger.md` и `templates/brief.md`.
5. Осмотреть авто-память через `/memory` и убрать неточное и чрезмерно
   обобщённое.

**Свидетельство:** `/context` показывает ожидаемые файлы инструкций и никаких
других; инструкции не противоречат друг другу.

### Стадия 3 — Выбрать регистр

Создать стиль вывода «Аналитик свидетельств» и выбрать его через `/config`.
Начать новую сессию, чтобы системный промпт пересобрался.

**Свидетельство:** первый ответ новой сессии различает утверждение источника и
собственный вывод **без отдельной просьбы**.

### Стадия 4 — Сделать переиспользуемую процедуру

1. Выполнить один бриф вручную, вместе с Claude.
2. Создать скилл `research-brief` из наблюдённой процедуры.
3. Прочитать каждый файл и каждую выдачу инструмента. Свести `allowed-tools` к
   минимуму.
4. Проверить на действительно другом наборе источников.

**Свидетельство:** второй прогон соблюдает тот же контракт вывода, не перенося
тематических допущений из первого.

### Стадия 5 — Добавить независимого ревьюера

1. Создать сабагента `evidence-reviewer` только на чтение.
2. **Убедиться, что это не форк.** Режим форка — умолчание в интерактивных
   сессиях: вызовите агента по имени и по его первому выводу проверьте, что он
   не знает о черновом разговоре.
3. Убедиться, что родительская сессия не в `acceptEdits`, `bypassPermissions`
   или `auto` — каждый из них перебивает `permissionMode` ревьюера. **На планах
   Pro, Max и Team сессия стартует именно в `auto`, поэтому это не
   формальность.**

**Свидетельство:** ревьюер называет утверждения, которые вы намеренно оставили
неподтверждёнными.

### Стадия 6 — Добавить ровно один элемент ограниченной автоматизации

Один хук, один монитор или одна цель — не три сразу.

### Стадия 7 — Отрендерить и проверить

Проверки должны действительно выполниться, а их вывод — быть осмотрен.

### Стадия 8 — Человеческий шлюз выпуска

Продвижение из `drafts/` в `deliverables/` не может быть пройдено агентом
самостоятельно.

## Заключительная мысль

> Внедряйте возможности с той скоростью, с какой способны подтверждать их
> результат, и не быстрее.

Четыре элемента брифа — Outcome, Context, Boundaries, Evidence — проходят через
всю книгу: они же контракт плана (глава 6), бриф делегирования (глава 16),
условие завершения (глава 21) и шлюз выпуска (глава 34). Пропущенный четвёртый
элемент — это то, что превращает возможности в переделку.
