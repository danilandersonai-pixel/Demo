## 2. Ключевые архитектурные решения

- **Симуляция отделена от рендера и DOM.** `Sim` — чистые данные и функции, детерминирована (сид, свой RNG, фиксированные 60 UPS). Это дало бесплатно: юнит-тесты без браузера, песочницу (клон через serialize/deserialize), бота-плейтестера в Node и стресс-бенчмарк.
- **Предметы на лентах — плоские `Uint16Array`/`Float32Array`**, 4 слота на тайл, отсортированы по позиции. Никаких объектов на предмет; 10 000 предметов + 8 000 сущностей = 1.6 мс/тик.
- **Действия скриптов — «заявки на прогон»**: `disable`/`set_priority`/`route`/`limit` действуют, пока скрипт их повторяет. Это естественно даёт «временно отключай» из референса, делает откат безопасным и позволяет Debugger'у видеть «дребезг» по счётчикам переключений.
- **`self.power` считает номинальный спрос** (как если бы скрипты ничего не выключали) — иначе правило «энергии < 80 % → выключи чипы» само себя отменяло бы каждый тик.
- **Галлюцинации — мутации исходника**, которые проявляются в фабрике (неверный предмет → действие молча не выполняется; инверсия → чипы выключаются днём), а не подсвечиваются. Debugger находит их по логам рантайма, дребезгу и статике.
- **Git хранит конфигурацию автоматизации** (файлы скриптов + группы + ручные приоритеты), откат — это новый коммит; полный снимок фабрики — опция, стоящая памяти.
- **Всё — процедурная графика**: здания рисуются «коробками» с тремя гранями + отдельный аддитивный слой огней; миниатюры UI рендерятся из тех же текстур.
- **HQ — центральный склад**: ленты можно заводить прямо в базу, а манипуляторы берут из неё. Это сильно упростило раннюю игру (и бота).

## 3. Что далось легко

- Ядро логистики, энергосеть, парсер и интерпретатор — почти всё работало с первого прогона тестов.
- Схема «чистая симуляция + клоны» окупилась трижды: песочница, бот, бенчмарк.
- Раскладка вайб-панели и Git-колонки практически 1:1 с изображениями 1 и 3.

## 4. Где застревал и как выходил

| Проблема | Как нашёл | Решение |
|---|---|---|
| Остров почти целиком из гор | ASCII-карта в тесте | Пороги биомов по квантилям высот |
| Движок намерений не видел половину русских слов | Дамп разбора в JSON | `ru()`-перезапись регулярок: кириллица как символ слова для `\w` и `\b` |
| В демо здания стояли призраками | Статусы зданий в тесте | `place(..., {force, instant})` |
| `connectPower` ставил 81 столб и съедал всю медь | Лог бота | Запланированные столбы-призраки считаются покрытием |
| Рендер 16–28 мс на стресс-тесте | Профиль: сам кадр 1 мс, но пересборка инструкций Pixi 10–20 мс | Слои → независимые render groups; кадры лент и иконки предметов → общий атлас. Итог 3–7 мс |
| Панель браузера скрыта → requestAnimationFrame 1 FPS | FPS в debug-API | Кадры для проверок гоняю вручную через `__vf.frame()`; e2e в видимом Playwright-браузере |
| Трава выглядела «шахматкой» (дебаг-сетка) | Разбор скриншотов | Варианты тайлов стали ближе по цвету, добавлено гладкое поле оттенков |
| Медленный npm-реестр | Таймауты | Фоновая установка + параллельная работа над документами; Playwright закреплён на версии с уже скачанным Chromium |

## 5. Что упрощено или вырезано (и почему)

- **Одна полоса на ленте** (промпт разрешает). Боковая подгрузка — на середину тайла.
- **Трубы**: сеть = общий бассейн объёма, без давления и направлений.
- **Дроны летают по прямой**, враги ходят по прямой без поиска пути.
- **Логистические дроны** — упрощённая модель «доставить недостающее / разгрузить забитое», без сундуков-запросов.
- **Architect** строит параметрическую линию одного рецепта; поставку сырья к её входу игрок организует сам (или сундуками-фидерами, как в демо).
- **Сборка ресурсов для построек** — из общего пула складов, без физической доставки материалов дронами (дрон летит, но материалы списываются при назначении).
- **Режим «Настоящий ИИ»**: реальный вызов API протестирован только без сети (заглушка кода, отложенная генерация, ключ не попадает в сохранения). Ключа у меня не было, и подставлять чужие ключи я не стал.
- **Фазы коммитились парами** (0–1, 2–3, 5–6, 7–8), а не по одной — фазы были тесно связаны; каждый коммит проходил typecheck/test/build.

## 6. Известные баги и шероховатости

- Огонь дальнего здания ночью может просвечивать сквозь ближнее (аддитивный слой огней над миром).
- Высокие здания нельзя выбрать кликом по крыше — выбор идёт по тайлу основания.
- На пересечении границ чанков возможны редкие ошибки порядка отрисовки деревьев и зданий.
- При большом числе месторождений рядом подписи на стратегической карте перекрываются.
- Звук — простой синтез; эмбиент включается только после первого клика (политика автозапуска браузеров).
