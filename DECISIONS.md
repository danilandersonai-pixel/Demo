# DECISIONS.md — принятые решения

Файл ведётся автономно: спорные развилки решаются на месте и фиксируются здесь
с обоснованием. Формат: решение → альтернативы → почему так.

---

## Этап 0. Разведка окружения (что реально есть на этой машине)

Проверено командами `node --version`, `git --version`, `ls ~/.claude/...`
31.07.2026 на Linux 6.18.5 (x86_64), Node **v22.22.2**, npm 10.9.7,
git **2.43.0**.

### Где Claude Code хранит транскрипты

```
~/.claude/projects/<закодированный-путь-проекта>/<sessionId>.jsonl
```

Для проекта `/home/user/Demo` каталог называется `-home-user-Demo`:
все не буквенно-цифровые символы пути заменены на `-`. Рядом с `.jsonl`
лежит служебный `<sessionId>.ccr-tip.json` — его игнорируем.

Файл — JSONL, **одна запись на строку**, дописывается в конец в реальном
времени по мере работы Клода. Замеренный размер живой сессии — 64 КБ на
20 записей.

### Какие записи встречаются

| `type` | Что это | Что берём |
| --- | --- | --- |
| `user` | сообщение человека **или** результат инструмента | `message.content` (строка = реплика человека; массив с `tool_result` = результат) + `toolUseResult` |
| `assistant` | ответ Клода; **один блок контента на строку** | `message.content[0]`: `text` / `thinking` / `tool_use` |
| `attachment` | служебные вложения (`deferred_tools_delta` и т.п.) | игнорируем |
| `queue-operation` | постановка промпта в очередь | используем как «человек дал задание» |
| `last-prompt` | указатель на последний промпт | игнорируем |

Полезные поля верхнего уровня есть почти у всех записей: `uuid`,
`parentUuid`, `timestamp` (ISO), `sessionId`, `cwd`, `gitBranch`, `version`.

Ключевые формы:

- **Вызов инструмента** — `assistant` с блоком
  `{type:"tool_use", id:"toolu_…", name:"Bash", input:{command, description}}`.
- **Результат** — `user` с блоком
  `{type:"tool_result", tool_use_id:"toolu_…", content, is_error}` и
  дублирующим полем верхнего уровня `toolUseResult`
  (для Bash — `{stdout, stderr, interrupted, isImage}`).
  Связь вызов→результат идёт по `tool_use_id`, это и есть наш «джойн».
- **Токены** — `assistant.message.usage`:
  `input_tokens`, `output_tokens`, `cache_creation_input_tokens`,
  `cache_read_input_tokens`.

### Решение 0.1. Уровни источников данных (деградация)

**Уровень A — транскрипты.** Хвостим активный `.jsonl`, склеиваем
`tool_use` → `tool_result`, получаем богатую ленту: какой инструмент, с
какими аргументами, чем кончился, сколько токенов.

**Уровень B — только ФС + git.** Если каталога транскриптов нет (другая
версия Claude Code, другой `HOME`, запуск не рядом с Клодом) — панель
работает на вотчере файловой системы и опросе git. Лента беднее
(«файл изменён», «ветка переключилась»), но карта проекта, git-панель,
словарь и пульс сессии остаются полностью рабочими.

Уровень определяется на старте и **пересматривается на лету**: если
транскрипт появится позже, приложение само переключится на A и скажет об
этом в ленте. Обратно (A → B) — если каталог исчез.

### Решение 0.2. Хуки Claude Code — сознательно НЕ используем

Хуки поддерживаются (`settings.json`, ключ `hooks`), и как источник они
были бы точнее транскрипта: `PreToolUse`/`PostToolUse`/`Stop` приходят
мгновенно. **Но** их включение требует записи в `.claude/settings.json`
наблюдаемого проекта — а это прямое нарушение требования «приложение
ничего не меняет в проекте пользователя».

Компромисс: в README описан необязательный рецепт «если хотите мгновенный
сигнал остановки — добавьте `Stop`-хук руками», а сервер принимает такие
события на `POST /api/hook`. По умолчанию канал существует, но никто в него
не пишет, и приложение на него не рассчитывает.

### Решение 0.3. Ноль зависимостей вместо `chokidar`

Разрешён был `chokidar`, но Node 22 умеет `fs.watch(dir, {recursive:true})`
на всех трёх целевых ОС (Linux — с Node 20). Своя обёртка + дебаунс —
это ~120 строк, зато `npm install` не нужен вовсе и «всё офлайн»
выполняется буквально: скачал папку → `node server.js`.

Подстраховка: если рекурсивный `fs.watch` бросит исключение (экзотическая
ФС, сетевой диск), вотчер молча переходит в режим периодического
пересканирования дерева (`--poll`, по умолчанию 3 с). Панель этой разницы
не замечает.

## Архитектурные решения

### Решение 1. CommonJS, а не ESM

`require` + `module.exports`. Причина приземлённая: `node --test` и
относительные пути в CJS ведут себя одинаково на всех версиях Node ≥ 18,
без `type: "module"`, без расширений в импортах, без сюрпризов
`__dirname`. Проект без сборки — лишний слой совместимости не нужен.

### Решение 2. Чистые модули отдельно от ввода-вывода

Всё, что можно протестировать без диска и сети, вынесено в чистые функции:
`transcript-parse.js`, `git-parse.js`, `humanize.js`, `filetypes.js`,
`debounce.js`, `ignore.js`, `paths.js`. Модули с побочными эффектами
(`watcher.js`, `git.js`, `transcript.js`, `server.js`) их только вызывают.
Отсюда же берётся требуемое покрытие тестами: 30+ тестов бьют по чистым
функциям на реальных фикстурах, а не по HTTP.

### Решение 3. SSE, а не WebSocket

Требование задания, и оно правильное: поток односторонний
(сервер → браузер), SSE — это `text/event-stream` на голом `node:http`,
с автоматическим переподключением в браузере из коробки. WebSocket
потребовал бы ручной реализации рукопожатия и кадров (зависимости
запрещены).

Буфер: кольцо на **500 последних событий** в памяти. Новый клиент
получает их одним снимком (`event: snapshot`), затем живой поток.
Поддержан заголовок `Last-Event-ID` — при переподключении досылаются
только пропущенные события.

### Решение 4. Одна модель события

Всё, что происходит, приводится к одной форме, чтобы клиент не разбирался
в источниках:

```js
{
  id: 42,                    // монотонный номер (он же SSE id)
  ts: 1769823505459,         // время, мс
  kind: 'tool' | 'file' | 'git' | 'session' | 'system' | 'user' | 'assistant',
  action: 'read' | 'edit' | 'run' | 'search' | 'changed' | 'commit' | ...,
  source: 'transcript' | 'fs' | 'git' | 'hook',
  title: 'Клод изменил engine/game.js',   // человеческий язык, русский
  hint:  'Правка файла: 42 строки добавлено, 7 удалено',
  file: 'engine/game.js',    // если применимо
  level: 'info' | 'warn' | 'error',
  detail: { … },             // дифф, вывод команды, аргументы — для клика
  raw: { … }                 // сырая запись — для режима «Подробно»
}
```

`raw` возвращается всегда: переключатель «Просто / Подробно» — чисто
клиентский, без похода на сервер.

### Решение 5. Дедупликация событий ФС и транскрипта

Когда Клод правит файл, событие приходит дважды: из транскрипта
(`Edit engine/game.js`) и из вотчера (`изменён engine/game.js`) с разницей
в доли секунды. Правило: если событие ФС по тому же пути приходит в
пределах **2500 мс** после события транскрипта с тем же файлом — оно
поглощается (в ленту не идёт, но карту проекта обновляет). Обратный
порядок тоже учитывается: событие транскрипта помечает файл «горячим»
задним числом.

### Решение 6. Детектор остановки — затишье + признаки завершения

Считаем, что Клод остановился и ждёт человека, когда выполняется любое из:

1. **Затишье**: с последней записи в транскрипте прошло больше
   `--idle` секунд (по умолчанию **45**) **и** последняя запись — это
   `assistant`-текст (то есть Клод договорил, а не оборвался на
   инструменте).
2. Пришёл `Stop`-хук (если пользователь его настроил).
3. Транскрипт не растёт дольше `idle × 3` при любом хвосте — «похоже,
   сессия завершилась».

Порог 45 с выбран эмпирически: один вызов инструмента у Клода редко длится
дольше, а человек за 45 с ещё не успевает уйти далеко. Значение
настраивается флагом и в панели.

Сигнал шлётся **один раз на переход** «работает → ждёт». Обратный переход
(появилась новая запись) снимает флаг молча. Так уведомление не
повторяется каждые несколько секунд.

### Решение 7. Звук генерируется, а не лежит файлом

Уведомление звучит через `AudioContext` (два коротких синуса, 660→880 Гц).
Причина: бинарный `.mp3`/`.wav` в репозитории без сборки — лишний вес и
лишний запрос, а `AudioContext` есть везде и работает офлайн. Браузер
требует «жеста пользователя» до первого звука — поэтому в панели есть
явная кнопка «🔔 Проверить сигнал», она же разблокирует звук.

### Решение 8. Оценка токенов — честно приблизительная

`usage` в транскрипте есть, но: он относится к одному ответу модели,
дублируется между блоками одного сообщения (мы дедуплицируем по
`message.id`), и ничего не говорит о стоимости. Поэтому в панели —
только сумма `input/output/cache` с явной подписью «оценка, считается по
транскрипту, может расходиться с биллингом». Никаких денег и процентов
от лимита не показываем: это было бы враньё.

### Решение 9. Git — только чтение, жёстко

Список разрешённых команд захардкожен в `lib/git.js`
(`rev-parse`, `status --porcelain`, `log`, `diff --stat`, `diff`,
`branch`, `rev-list`, `show`). Любой вызов идёт через `execFile` с
массивом аргументов — не через шелл, поэтому подстановка из имени файла
невозможна. Запись, `checkout`, `add`, `commit` в коде отсутствуют как
класс. Плюс глобальные флаги `-c core.pager=cat --no-optional-locks`,
чтобы не трогать индекс и не подвешиваться на пейджере.

### Решение 10. Слушаем только 127.0.0.1

`server.listen(port, '127.0.0.1')` — без флага «слушать наружу» вообще.
Панель показывает содержимое чужих файлов и вывод команд; открывать это
в локальную сеть по умолчанию нельзя, а «удобный флаг» рано или поздно
кто-нибудь включит. Нужен доступ с другой машины — есть `ssh -L`.

### Решение 11. Кодировка пути проекта → каталог транскриптов

Основной путь: `path.resolve(project).replace(/[^a-zA-Z0-9]/g, '-')`.
Подстраховка (и главный механизм на Windows, где кодировка исторически
менялась): просматриваем **все** каталоги в `~/.claude/projects/`, читаем
первую строку самого свежего `.jsonl` и сравниваем поле `cwd` с нашим
проектом через `path.relative`. Совпало — берём этот каталог.

### Решение 12. Дерево проекта — снимок + инкремент

Полное сканирование дерева делается на старте и по запросу `/api/tree`
(с ограничениями: глубина 12, максимум 8000 файлов — чтобы не подвесить
сервер на монорепозитории). Дальше дерево живёт инкрементально: вотчер
шлёт точечные `file`-события, клиент правит своё дерево на месте.
«Тепловой след» — чисто клиентский таймер: 100 % при событии, гаснет за
90 с, перерисовка раз в секунду через один общий `requestAnimationFrame`.

### Решение 13. Дифф — `git diff`, а при его отсутствии ничего не выдумываем

Дифф файла берём как `git diff -- <file>` (для незакоммиченных) или
`git show <sha> -- <file>`. Если git нет или файл не под контролем версий —
показываем карточку файла без диффа и честную строку «дифф недоступен: файл
не под git». Реконструировать дифф из транскрипта (там есть `old_string` /
`new_string` у `Edit`) мы **тоже** умеем — это фолбэк для уровня B.

### Решение 14. Русский язык и словарь — в данных, а не в коде

Все формулировки лежат в таблицах (`humanize.js`, `filetypes.js`,
`glossary.js`), а не размазаны по логике. Добавить объяснение нового
инструмента = дописать строчку в таблицу. Словарь — 30+ терминов,
раздаётся по `/api/glossary`, в вёрстке термины помечаются `?` через
`data-term`.

### Решение 15. Журнал прошлых сессий — по файлам транскриптов

Список сессий = список `.jsonl` в каталоге проекта, отсортированный по
`mtime`. Для каждой читаем первую и последнюю строку (без загрузки всего
файла): начало, конец, первый промпт человека, число записей. Открытие
старой сессии парсит её целиком и отдаёт ленту одним ответом
(`/api/session/<id>`) — это не поток, а архив.

### Решение 16. Тур первого запуска — в `localStorage`, без сервера

Флаг `shturman.tour.done`. Тур не лезет в сеть и не пишет на диск
пользователя. Перезапустить — кнопка «Тур» в шапке.

### Решение 17. Несколько проектов — реестр, а не один экземпляр

`--project` можно повторить. Внутри — реестр приложений по ключу (короткое
имя папки, при совпадении добавляется номер), маршруты принимают
`?project=<ключ>`. Одиночный запуск **тоже** приводится к виду реестра
обёрткой `asRegistry`, поэтому в маршрутах нет ни одного `if` про
количество проектов.

Неизвестный ключ молча отдаёт основной проект: закладка на старую вкладку
не должна ломать панель.

Одинаковые пути схлопываются на этапе разбора флагов. Два наблюдателя на
одну папку — это удвоенные события в ленте и удвоенная нагрузка, и ничего
полезного взамен.

Переключение на клиенте — полный сброс локального состояния (лента, дерево,
подсветка, архив) и переподключение потока. Держать несколько лент в памяти
одновременно ради быстрого переключения не стоит: панель смотрят, а не
листают.

### Решение 18. Дифф без git — восстановление из транскрипта

У `Edit` в транскрипте лежат `old_string` и `new_string`, у `Write` —
`content`. Этого достаточно для настоящего построчного диффа, поэтому на
уровне B и для файлов вне контроля версий мы больше не пишем «недоступно».

Алгоритм — LCS на матрице длин (`lib/textdiff.js`), результат по форме
совпадает с разбором `git diff`, так что клиент рисует оба одинаково.
Предохранитель: выше 1200 строк матрицу не строим, показываем «было целиком
/ стало целиком» — квадратичная память на большом файле опаснее, чем
некрасивый дифф.

Такой дифф помечен `reconstructed: true` и подписан «по транскрипту» с
пояснением, что это **одна правка Клода**, а не полная разница с сохранённой
версией. Выдавать его за git-дифф было бы враньём.

### Решение 19. Субагенты — отдельный поток, а не общая куча

Записи субагента лежат в том же файле с `isSidechain: true`. Прятать их
жалко (это настоящая работа над проектом), но и смешивать нельзя: новичок
не поймёт, кто трогал файл.

Компромисс: событие помечается флагом, а `humanize` **подменяет
подлежащее** — «Клод читает a.js» превращается в «Помощник: читает a.js».
Иконка, пояснение и уровень остаются прежними: действие-то одно и то же.
В ленте такие карточки сдвинуты и приглушены, есть отдельный фильтр.

### Решение 20. `[hidden]` должен побеждать наш `display`

Найдено при проверке в браузере. У оверлеев (шторка, модальное окно, тур,
полоса паузы, переключатель проектов) в CSS стоит `display: flex` — и он
пересиливает `[hidden] { display: none }` из стилей браузера по
специфичности. Все «спрятанные» элементы висели поверх панели.

Лечится одной строкой `[hidden] { display: none !important; }` в начале
файла. `!important` здесь не костыль, а ровно тот случай, для которого он
существует: правило про доступность обязано выигрывать у оформления.

Отсюда же вывод про проверку: тесты этого поймать не могли — их надо было
именно **увидеть**. Панель снимается headless-хромом через CDP
(`Page.captureScreenshot`), потому что штатный `--screenshot` зависает:
SSE держит соединение открытым и «загрузка страницы» не завершается
никогда.

### Решение 21. «Спроси Клода» — выключено по умолчанию

Пункт 1 из «если осталось время». Реализовано как `POST /api/ask` →
`execFile('claude', ['-p', prompt])` с таймаутом 60 с. **Выключено**, пока
пользователь не включит переключатель в настройках (и это состояние
живёт в `localStorage` + подтверждается заголовком запроса). Причина:
расходует лимиты человека, а он может об этом не знать. Если бинаря
`claude` в `PATH` нет — кнопка не показывается вовсе.

## Задание 2. Оболочка для телефона и компьютера

### Решение 22. Конфиг живёт в домашнем каталоге, а не в проекте

`.shturman.json` кладётся в `~`, хотя имя файла и намекает на «рядом с
проектом». Причина одна и она важнее удобства: первая версия пообещала, что
Штурман **ничего не пишет в наблюдаемую папку**, и это обещание проверяется
отдельным тестом. Свой конфиг — не повод его нарушить: человек увидел бы
новый файл в `git status` и справедливо усомнился бы в остальных обещаниях.

Запись атомарная (временный файл + переименование): прерванная запись не
должна оставлять обрезанный JSON, иначе следующий запуск потеряет всё.
Битый или чужой файл молча откатывается на умолчания — падать из-за
настроек нельзя.

### Решение 23. Ярлыки создаются только по явной команде

`Штурман.bat` и `Штурман.command` появляются в папке проекта, а это запись
в чужую папку. Поэтому их создаёт **отдельная команда**
`shturman --install-shortcuts`, а не автозапуск: человек попросил — человек
получил. Существующие файлы не перезаписываются без `--force`: вдруг их
правили под себя.

Мелочи, без которых ярлыки не работают: в `.bat` нужен CRLF и `chcp 65001`
(иначе русский текст в cmd.exe превращается в кракозябры), в `.command` —
бит исполнения (без него Finder и файловые менеджеры Linux не запускают
файл двойным кликом). Оба скрипта сначала проверяют наличие Node и
объясняют, где его взять, — иначе новичок увидит только мигнувшее окно.

### Решение 24. Ключ доступа вместо пароля, и честно о границах

Режим `--share` защищён одноразовым ключом на 128 бит, вшитым в ссылку и
QR-код. Это **не** защита от взлома: трафик идёт по http, в одной сети его
можно подслушать. Задача скромнее и оттого выполнима — не пустить в панель
случайного соседа по Wi-Fi, который просто перебирает адреса.

Так и написано в интерфейсе: «панель видна другим устройствам в вашей сети,
войти можно только по ссылке с ключом». Обещать шифрование, которого нет,
хуже, чем не обещать ничего.

Решения помельче, но существенные:
- **С самой машины ключ не спрашивается.** Придумывать себе пароль на
  собственном компьютере незачем, а привычный `http://127.0.0.1:4517`
  должен работать как в первой версии.
- **Сравнение ключей в постоянное время** (`timingSafeEqual`): обычное `===`
  выдаёт по времени, сколько символов угадано. Сделать правильно здесь
  дёшево.
- **Ключ переезжает в куку** при первом заходе, чтобы не болтаться в адресной
  строке и в истории браузера. Без `Secure` — с ним браузер выбросил бы куку
  на http; `SameSite=Lax` от подстав со стороны чужих страниц.
- **Оболочка PWA (манифест, sw.js, иконки, страница «сервер не запущен»)
  отдаётся без ключа.** Иначе установленное на телефон приложение при
  выключенном сервере показало бы белый экран вместо объяснения.

### Решение 25. Свой QR-кодировщик вместо разрешённой зависимости

Задание разрешало взять пакет `qrcode`. Не взял: «скачал папку — запустил,
без npm install и без интернета» — заявленное свойство первой версии, и
менять его на одну картинку нельзя, тем более что главный закон этого
задания — ничего не потерять.

Риск понятен: самодельный QR, который не сканируется, хуже зависимости.
Поэтому корректность не предполагается, а **доказана**: матрица сверена с
эталонным пакетом побитово на 1102 случайных входах всех версий 1–10 —
расхождений ноль. Сверка нашла три настоящие ошибки, которые «на глаз» не
видны:

1. биты строки формата кладутся старшим вперёд, а не младшим;
2. вторая копия строки формата делится 7 + 8, а не 8 + 7 — ячейку
   `(size-8, 8)` занимает обязательный тёмный модуль;
3. в четвёртом правиле штрафа доля тёмных модулей округляется вверх, и от
   этого зависит, какая маска победит.

Эталонный пакет ставился во временную папку и в проект не попал; в тестах
остался контрольный вектор, снятый после сверки.

Область намеренно узкая: только байтовый режим, только уровень коррекции M,
версии 1–10. Этого хватает на `http://192.168.100.100:65535/?t=<32 hex>` с
запасом, а всё лишнее — лишний код и лишние ошибки.

### Решение 26. Одна разметка, раскладку меняет CSS

Требование задания, и оно правильное. Практически это значит: секции
`data-view` лежат в разметке всегда, а на узком экране CSS показывает ровно
одну и включает нижние вкладки. Никаких «если телефон — построй другое
дерево» в JS: расходиться двум версиям попросту негде.

Побочные решения, вытекающие отсюда:
- **Шторка одна на оба форм-фактора.** На телефоне выезжает снизу, на
  компьютере становится боковой панелью — меняются только CSS-правила.
  Модальное окно первой версии убрано: две сущности для одного и того же
  расходились бы.
- **На телефоне заголовок секции скрыт** — его дублирует подпись вкладки.
- **Пять кнопок шапки уходят под «⋯»**, и список строится из тех же
  действий, что и кнопки. Разойтись они не могут по построению.

### Решение 27. Виртуализация ленты и экономия SSE

Тысяча событий в разметке на телефоне — это заметные задержки прокрутки.
Поэтому в DOM живут только видимые карточки плюс запас, а высоту прокрутки
держат две распорки.

Тонкость, на которой это ломалось: при переключении «Просто/Подробно»
высота карточки меняется втрое, старый `scrollTop` уводит окно за конец
списка, и лента становится пустой. Окно теперь прижимается к границам
списка — нашлось живым прогоном в браузере, тесты такое не ловят.

SSE в фоне отключается через минуту: держать открытое соединение на
свёрнутой вкладке телефона — это разряжать батарею впустую. При
возвращении подключаемся заново и подтягиваем пульс.

### Решение 28. Иконки рисуются кодом

Растеризатора в проекте нет, ставить его ради восьми картинок — снова
зависимость. Компас — это круги, прямоугольники и два треугольника, поэтому
`tools/make-icons.js` рисует их прямо пикселями со сглаживанием 3×3 и
собирает PNG вручную (zlib есть в Node). Иконки лежат в репозитории
готовыми: пользователю генератор запускать не нужно.

### Решение 29. Данные не кэшируются service worker'ом никогда

Кэшируется только оболочка. Показать вчерашнюю ленту как сегодняшнюю — хуже,
чем честно сказать «связи нет»: человек как раз и смотрит в панель, чтобы
узнать, что происходит **сейчас**. Поэтому `/api/*` всегда идёт в сеть, а при
отказе возвращается `503` с флагом `offline`, который панель показывает как
«связь потеряна».

### Решение 30. Общий доступ включается из панели, но только с компьютера

Требовать «остановите Ctrl+C и запустите заново с флагом» — ровно тот барьер,
который это задание убирает. Поэтому в панели есть кнопка.

Технически это второй слушатель на тот же обработчик. Первая попытка
привязать его к `0.0.0.0` провалилась: этот адрес включает и петлю, уже
занятую основным сервером, — `EADDRINUSE`. Слушатели вешаются на конкретные
адреса машины, и это заодно честнее — слушаем ровно те интерфейсы, что
показали человеку в QR-коде.

Управлять переключателем можно **только с самого компьютера**: иначе
зашедший по ссылке гость смог бы им распоряжаться — например, выключить
доступ хозяину или, наоборот, оставить его открытым. Выключение реально
закрывает сокет и рвёт открытые соединения гостей: «выключил доступ» должно
означать именно это, а не «перестал показывать кнопку».

### Решение 31. Офлайн-страница важнее закэшированной оболочки

Первая версия service worker при отказе сети отдавала закэшированную панель.
Выглядело разумно — но панель без сервера пуста: все данные приходят из
`/api`, и человек видел фильтры, поиск и надпись «Пока тихо» вместо
объяснения, что сервер надо запустить.

Теперь при отказе навигации отдаётся именно `offline.html`. Кэш оболочки
остаётся, но его роль — быстрый старт при живом сервере, а не замена ему.

Разделение получилось чистое:
- сервер умер, пока панель открыта → она сама показывает «связь потеряна»
  (SSE это замечает);
- приложение открыли при выключенном сервере → страница с тремя шагами,
  что нажать на компьютере, и автопроверкой связи каждые пять секунд.

## Задание 3. Редизайн

### Решение 32. Опорная мысль вместо набора красивых значений

**Развилка.** Можно было собрать «современно выглядящую» палитру и шкалу
и разложить по ним существующие экраны. Так делают быстро.

**Решение.** Сначала сформулирована опорная мысль — «это приборная панель
наблюдателя», — и все значения выведены из неё.

**Почему.** Из мысли следуют проверяемые правила: раз на прибор смотрят
мельком, главное показание должно читаться с трёх метров; раз прибор не
кричит без повода, цвет означает состояние, а не украшение; раз прибор
живой, пока работает механизм, движение должно что-то значить. Без такой
мысли каждое решение приходится защищать вкусом, а вкус не аргумент в споре
и не проверяется тестом.

### Решение 33. Латунь означает ровно одно состояние мира

**Развилка.** Обычный путь — акцентный цвет для «всего важного»: активная
вкладка, ссылки, главные кнопки, выделения, счётчики, прогресс.

**Решение.** Единственный акцент интерфейса — латунь — означает **«нужен
ты»**. Пока Клод работает, латуни на экране нет вообще.

**Почему.** Главная функция Штурмана — сказать, что Клод остановился и ждёт.
Если акцент рассыпан по интерфейсу, момент остановки ничем не выделяется:
экран и так весь в акценте. Ограничение неудобное (активные элементы
приходится показывать заливкой и весом, а не цветом), но оно и делает сигнал
сигналом. Заодно это решило проблему, которую аудит назвал местом №1.

### Решение 34. Картушка вместо перекрашенного чипа

**Развилка.** Можно было увеличить существующий чип состояния и сделать его
цветным — быстро, безопасно, «редизайн выполнен».

**Решение.** Индикатор перепроектирован целиком: диск 56px со своей строкой
во всю ширину, четыре состояния, три независимых канала различения
(движение, цвет, форма). Чип из шапки и всплывающая карточка сигнала
удалены.

**Почему.** Аудит показал, что одна мысль рассказывалась в трёх местах и ни
одно не выглядело главным. Увеличение чипа оставило бы ровно эту проблему.
Три канала различения — не украшательство: **движение** читается боковым
зрением, когда человек смотрит в другое окно; **форма** работает при
дальтонизме; **цвет** — самый быстрый канал, когда смотрят прямо. Любого
одного достаточно.

### Решение 35. Старостильные цифры Georgia для показаний приборов

**Развилка.** Инструменты для разработчиков набирают числа либо гротеском,
либо моноширинным. Оба варианта безопасны и оба безлики.

**Решение.** Показания приборов — слово состояния, числа пульса, счётчик
git — набраны Georgia с её разновысокими цифрами. В абзацы и заголовки
сериф не пускается.

**Почему.** Характер нужно было взять, не подключая шрифт: панель обязана
работать офлайн. Georgia есть везде, а её старостильные цифры на крупном
кегле читаются как гравированная шкала — ровно то, что нужно приборной
панели. Ограничение «только показания» защищает от штампа «кремовый лендинг
с серифом»: как только серифом набирают предложение, панель превращается в
журнал.

### Решение 36. Разметка без единого слова

**Развилка.** Обычно статические подписи оставляют в HTML, а через словарь
гоняют только динамику. Это проще и не даёт мигания пустых надписей.

**Решение.** В `index.html` нет ни одного слова интерфейса: подписи
приходят из `copy.js` по `data-copy`, значки — из `icons.js` по `data-icon`.

**Почему.** Пока часть слов живёт в разметке, а часть в коде, «единый
словарь» — обещание, а не факт: одно и то же начинает называться по-разному,
что и произошло в прошлых версиях. Теперь это проверяется тестом. Мигание
закрылось само: запуск приборов и так держит экран первые 900 мс. Исключения
оговорены — `<title>`, `<meta>`, `<noscript>` и офлайн-страница должны
работать до первой строки JavaScript.

### Решение 37. Плотность меняет только воздух

**Развилка.** «Компактный режим» часто уменьшают целиком: кегли, отступы,
кнопки. Так на экран влезает больше всего.

**Решение.** Множитель плотности умножает **только** ряд отступов. Кегли,
зоны касания и толщины линий не меняются никогда; в компактном режиме
дополнительно сворачиваются в одну строку заголовок и пояснение события.

**Почему.** Компактность не имеет права ухудшать читаемость и попадание
пальцем — иначе это не настройка, а ловушка. Свёрнутые строки ничего не
теряют: полный текст всегда в карточке события. Замер: +38% событий на
экран при неизменных 44px и 16px.

### Решение 38. Пустой экран знает свою причину

**Развилка.** Один аккуратный текст «ничего нет» на все случаи — меньше кода
и меньше строк в словаре.

**Решение.** Тринадцать разных пустых экранов, у каждого своя причина, свой
текст и (почти всегда) кнопка следующего шага.

**Почему.** Старый общий текст врал в двух случаях из трёх: при 200 событиях
в ленте он сообщал, что «Штурман ждёт первых действий». Новичок в такой
ситуации решает, что сломался он или панель. Причина и выход стоят
тринадцати веток в словаре.

### Решение 39. Контраст меряется браузером, а не на глаз

**Развилка.** Можно было проверить пары цветов калькулятором контраста при
проектировании палитры и считать вопрос закрытым.

**Решение.** `tests/manual/design-probe.js` обходит **каждый** текстовый узел
живой страницы, определяет фактическую подложку (с учётом полупрозрачных
слоёв) и считает контраст; прогон идёт на двух ширинах в обеих темах.

**Почему.** Пары цветов в палитре проходили, а на экране — нет: текст лежал
на карточке, карточка на панели, панель на фоне, и полупрозрачные подложки
складывались. Именно так нашлись последние пять почти-провалов (4.08–4.43),
которые калькулятор палитры показать не мог. Отдельная тонкость: `color-mix`
в вычисленных стилях приходит как `color(srgb …)`, и разбор строки давал
чушь — цвет пришлось «проявлять» через canvas.

### Решение 40. Девять читаемых подписей лучше четырнадцати слипшихся

**Развилка.** В графе внимания подписи файлов налезали друг на друга. Можно
было уменьшить кегль (и потерять читаемость), развести узлы физической
симуляцией (и притащить в проект силовую раскладку) или оставить как есть.

**Решение.** Кольцо стало двухрядным — соседние узлы уходят на разный
радиус, — а подпись рисуется, только если не пересекается с уже
нарисованной. На плотном кольце это девять имён вместо четырнадцати.

**Почему.** Слипшийся текст не читает никто, то есть четырнадцать подписей
на деле давали ноль. Скрытые имена не потеряны: узел остаётся кликабельным,
его имя есть в подсказке, а рядом стоит переключатель «Список», где все
файлы показаны таблетками с полным именем и зоной касания 44px. Замер после
правки: пересечений подписей — ноль.
