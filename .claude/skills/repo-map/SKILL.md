# Repo Map

Человек держит несколько репозиториев параллельно и теряет нить: что где лежит,
на какой ветке он остановился, какой PR висит незакрытым. Эта карта возвращает
ему общую картину за один взгляд.

Ключевая мысль при работе со скиллом: **ты не просто перечисляешь репозитории —
ты отвечаешь на вопрос «где я остановился».** Список имён легко получить и без
тебя. Ценность в том, что рядом с каждым репозиторием видно живую структуру
файлов и незакрытые хвосты работы.

## Что на выходе

Всегда выдавай оба формата, именно в таком порядке:

1. **ASCII-дерево прямо в ответе** — человек должен сориентироваться, не открывая
   ничего. Это первое, что он увидит.
2. **HTML-страница через инструмент Artifact** — родословное древо со всеми
   деталями, к которому можно вернуться позже по ссылке.

Порядок важен: если сначала уйти в сборку HTML, человек несколько минут смотрит
в пустоту. Короткое дерево в чате — это ответ, HTML — это справочник.

И в том, и в другом формате **текущее положение отмечается явно** — «вы здесь»
на репозитории и на ветке. Без этой отметки карта отвечает на вопрос «что у меня
есть», а нужен ответ на «где я сейчас».

## Процедура

### Шаг 0. Понять, где человек находится

Начинай отсюда, до всяких запросов к GitHub. Это дёшево, работает всегда и даёт
самое ценное — точку отсчёта:

```bash
git rev-parse --show-toplevel        # текущий репозиторий
git rev-parse --abbrev-ref HEAD      # текущая ветка
git status --porcelain | wc -l       # сколько файлов не сохранено
git rev-list --left-right --count origin/<основная>...HEAD   # отставание/опережение
```

Несохранённые файлы важны отдельно: GitHub про них не знает, а человек только
что с ними работал. Если он создал папку и спрашивает, где он, — ответ «вижу
только то, что на GitHub» выглядит как поломка.

Если каталог не является git-репозиторием, просто пропусти шаг: карта соберётся
без отметки «вы здесь».

### Шаг 1. Собрать данные

Подробности вызовов, глубина обхода и что игнорировать — в
`reference/collect.md`. Прочитай его перед сбором, там же разобран главный
подводный камень: репозиторий не читается, пока он не подключён к сессии.

Коротко последовательность:

1. Полный список репозиториев — инструментом с суффиксом `__list_repos`.
   **Имя сервера перед суффиксом в разных сессиях разное** (иногда читаемое,
   иногда UUID), поэтому не набирай его по памяти: найди в списке доступных
   инструментов тот, что оканчивается на `__list_repos`.
2. Для каждого репозитория параллельно: дерево файлов, ветки, открытые PR,
   первые строки README/CLAUDE.md для однострочного описания.
3. Свести всё в один JSON по схеме из `reference/collect.md`.

Если `list_repos` недоступен или требует подтверждения, действуй по порядку:
сначала загляни в память — `.claude/repo-map/snapshot.json`. Есть снимок —
достраивай карту на нём, пометив `"stale": true`. Нет снимка — собирай по
репозиториям, уже подключённым к сессии.

В обоих случаях скажи вслух, что список неполный. Молчать нельзя: человек
решит, что у него всего один репозиторий.

Вызовы к разным репозиториям независимы — отправляй их пачкой в одном сообщении,
а не по одному. На шести репозиториях это разница между несколькими секундами и
минутой.

### Шаг 2. Показать ASCII-дерево

Формат описан в `reference/render.md`. Держи его компактным: это срез для
ориентации, а не полный листинг. Если репозиториев больше восьми, показывай
подробно только те, где были изменения за последние две недели, а остальные
сверни в одну строку каждый.

### Шаг 3. Опубликовать HTML

1. Загрузи скилл `artifact-design` — этого требует инструмент Artifact.
2. Возьми `assets/template.html`, замени в нём `__REPO_MAP_DATA__` на собранный
   JSON. Больше в шаблоне менять ничего не нужно: разметка, стили и рендерер уже
   внутри, и они рассчитаны на светлую и тёмную тему.
3. Запиши результат в файл и опубликуй через `Artifact` с `favicon: "🗺️"`.

Шаблон существует ровно для того, чтобы не сочинять страницу заново на каждом
запуске — так карта выглядит одинаково от раза к разу, и человек привыкает к
одному и тому же расположению элементов. Если шаблона не хватает под конкретный
запрос, лучше дополнить сам шаблон, чем писать разовую вёрстку.

### Шаг 4. Сохранить снимок

Запиши собранный JSON в `.claude/repo-map/snapshot.json` текущего репозитория.
В следующий раз он спасёт карту, если доступ к GitHub окажется закрыт.

Снимок переживёт сессию только в коммите — облачный контейнер стирается
целиком. Поэтому предложи закоммитить его одной строкой, но **не коммить сам**:
человек мог позвать карту посреди своей работы, и лишний коммит в его ветке —
сюрприз. Отказался — ничего страшного, снимок просто не переживёт сессию.

## Аргументы

Скилл вызывается как `/repo-map [аргументы]`:

| Аргумент | Что делает |
|---|---|
| *(пусто)* | Полная карта всех репозиториев |
| `<имя-репозитория>` | Только он, но глубже: дерево на 4 уровня |
| `--fast` | Без деревьев файлов: только список, ветки и PR |
| `--depth N` | Переопределить глубину обхода (по умолчанию 3) |

## Чего не делать

**Не клонируй репозитории ради дерева.** Всё нужное отдаёт GitHub API, а
клонирование шести репозиториев съедает минуты и место на диске.

**Не выдумывай содержимое.** Если репозиторий не удалось прочитать — так и
напиши в карточке: «не удалось прочитать, нужно подключение». Ложная структура
в карте хуже, чем честный пропуск, потому что человек будет на неё опираться.

**Не превращай карту в аудит.** Задача — сориентировать, а не оценить качество
кода, не предложить рефакторинг и не найти баги. Если по ходу заметил что-то
важное, скажи одной строкой после карты.

## Файлы скилла

- `reference/collect.md` — какие вызовы делать, глубина, фильтры, обработка
  недоступных репозиториев, схема JSON
- `reference/render.md` — формат ASCII-дерева и устройство HTML-шаблона
- `assets/template.html` — самодостаточный шаблон страницы с рендерером внутри
