О книге и как её читать

Что это за книга

Справочник о том, как безопасно и продуктивно управлять Claude Code — не «какие есть функции», а что можно доверять, что нужно принудительно ограничить, какое свидетельство подтверждает корректность и что организация должна уметь показать аудитору.

Четыре тезиса книги:

  1. Возможности без определённого и наблюдаемого условия завершения — это не продуктивность.
  2. Инструкция, разрешения, песочница и изоляция ОС — четыре разных слоя стека контроля, принудительно работают только нижние три. Смешение их — самая частая причина потери контроля.
  3. Сторонние скиллы, плагины, маркетплейсы, каналы и MCP-серверы — это зависимости цепочки поставок, и управлять ими надо соответственно.
  4. Единица доверия — наблюдаемое свидетельство, а не заключительная фраза агента «готово».

Однофразовая версия: внедряйте возможности с той скоростью, с какой способны подтверждать их результат, и не быстрее.

Часть 0 — Устаревшие советы и распространённые заблуждения

Прочитайте эту часть до того, как выполнять любую процедуру из книги — и любую процедуру, найденную где-либо ещё.

Claude Code меняется еженедельно. Совет, написанный под релиз трёхмесячной давности, не просто устарел: в ряде документированных случаев он перевёрнут, и читатель, следующий ему, делает противоположное тому, что намеревался. На дату проверки в широком обороте находится двадцать одно такое утверждение.

Это реестр, а не разбор: строка фиксирует ходовое утверждение, позицию по первоисточнику и главу, которой принадлежит исправление. Авторитетна глава, а таблица нужна, чтобы читатель, уже держащий одно из этих убеждений, заметил столкновение. Выделенные полужирным — те, чьи последствия операционные, а не косметические.

Часть I — Основы

Глава 1. Что такое Claude Code и чем он не является

Чат принимает сообщения и возвращает сообщения. Claude Code вдобавок инспектирует рабочий каталог, правит файлы, выполняет инструменты, запрашивает разрешения, достаёт настроенные сервисы, публикует страницы, планирует собственные будущие ходы и делегирует другим экземплярам себя.

Это не делает его ни сотрудником, ни экспертом. Рабочая модель:

Claude Code — быстрый исполнитель с переменным суждением, широким доступом к инструментам, без врождённого знания ваших невысказанных намерений и с сильной склонностью докладывать об успехе.

Последнее и есть операционно важное. Все механизмы контроля в книге существуют потому, что собственный отчёт агента о сделанном — наименее надёжный артефакт, который он производит.

1.1 Четыре вещи, которые должны быть явными

Работа идёт хорошо, когда четыре элемента заявлены, а не додуманы:

  1. Outcome (Результат) — завершённое состояние, выраженное так, чтобы другой человек мог его проверить.
  2. Context (Контекст) — файлы, ограничения, ранее принятые решения и то, что вне области работы.
  3. Boundaries (Границы) — что можно менять без спроса, а что требует одобрения.
  4. Evidence (Свидетельство) — как обе стороны узнают, что результат верен.

Пропуск четвёртого — это то, что превращает возможности в переделку.

1.2 Стек контроля

Большая часть потерь контроля — ошибка категории: слой, который формирует намерение, принимают за слой, который ограничивает действие.

1.4 Подходящие первые задачи

Выбирайте работу обратимую и дешёвую для проверки:

  • разложить копии документов;
  • собрать план отчёта из предоставленных заметок;
  • сравнить два файла и вернуть таблицу различий;
  • исследовать ограниченный вопрос и сохранить реестр источников;
  • объяснить незнакомый репозиторий, ничего в нём не меняя.

Избегайте в качестве первой задачи всего, что трогает аккаунт, изменение которого вы не можете себе позволить. Возможности должны расширяться только после того, как расширятся привычки проверять.

Ключевые положения главы 1

  • Claude Code — агент, а не ассистент: он правит файлы, запускает команды, достаёт аккаунты и планирует свою работу.
  • Четыре элемента обязаны быть явными в каждой инструкции: Outcome, Context, Boundaries, Evidence.
  • В стеке контроля четыре слоя, и принудительно работают только нижние три. Инструкция — это предпочтение; правило разрешений — это контроль.
  • Первые задачи выбирайте обратимые и дешёвые для проверки.

Глава 2. Установка, проверка и аутентификация

2.1 Требования

На 23 августа 2026: macOS 13+, Windows 10 1809 / Windows Server 2019+, Ubuntu 20.04+, Debian 10+, Alpine 3.19+; минимум 4 ГБ RAM, доступ к сети и Bash, Zsh, PowerShell или CMD. Нужен аккаунт Pro, Max, Team, Enterprise или Console — либо настроенный облачный провайдер.

Не всякая функция следует матрице платформ: песочница не работает на нативной Windows; интеграция с Chrome не работает под WSL; артефакты, облачные сессии, рутины и каналы недоступны на сторонних провайдерах моделей.

2.2 Установка

Нативный установщик — официальный путь по умолчанию, обновляется сам в фоне.

# macOS, Linux, WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

Установки через менеджеры пакетов не обновляются автоматически:

brew install --cask claude-code        # стабильный канал
winget install Anthropic.ClaudeCode    # обновление: winget upgrade Anthropic.ClaudeCode

CAUTION. Shell-установщик выполняет код на вашей машине с вашими правами. Никогда не подставляйте команду, скопированную из описания видео, рекламы, форума или непроверенного репозитория, вместо документированной. Проверяйте домен посимвольно.

2.3 Проверить до входа в аккаунт

claude --version
claude doctor

claude doctor выполняет проверку установки и конфигурации только на чтение; с 2.1.206 он вдобавок предлагает сокращения для закоммиченного CLAUDE.md. Внутри сессии /login переаутентифицирует или меняет аккаунт, /logout выходит. Учётные данные хранятся в macOS Keychain, где он есть, и защищаются правами файлов на Windows и Linux.

CAUTION. Несколько функций требуют именно входа с подпиской claude.ai и молча недоступны, когда приоритет получает ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN или apiKeyHelper: интеграция с Chrome, артефакты, рутины, облачные сессии и teleport. Если документированная команда будто бы отсутствует — проверяйте путь аутентификации раньше, чем версию.

2.4 Windows: нативно или WSL 2

  • Нативная Windows подходит для Windows-проектов. Песочница недоступна. Git for Windows рекомендован, но больше не обязателен: без него инструментом оболочки служит PowerShell.
  • WSL 2 подходит для Linux-инструментария и требуется для песочницы Bash. Интеграция с Chrome под WSL не поддерживается.

CAUTION — WebDAV на Windows. Anthropic не рекомендует включать WebDAV или разрешать доступ к путям вида \\*, которые могут содержать WebDAV-подкаталоги: это позволяет инициировать сетевые запросы к удалённым хостам в обход системы разрешений.

CHECKPOINT главы 2

  • claude --version печатает версию.
  • claude doctor не сообщает о нерешённой критической проблеме.
  • claude стартует и показывает тот аккаунт, который вы имели в виду.
  • Вы знаете, обновляется ли ваша установка автоматически.
  • Вы знаете, вошли вы по подписке или по API-ключу.

Глава 3. Поверхности, проекты и границы

3.1 Настроить IDE

Установите VS Code, откройте Extensions, найдите Claude Code и убедитесь, что издатель — Anthropic, прежде чем ставить. Из палитры команд Claude Code: Open in New Tab даёт разговору полноценную вкладку редактора, Open in Terminal запускает CLI внутри IDE.

3.2 Создать тренировочное пространство

Открытая папка — граница работы по умолчанию. В ручном режиме Claude Code может писать только внутрь этой папки и её подпапок и спрашивает, прежде чем читать пути вне её инструментами Read, Grep и Glob; в авторежиме он читает за границей не спрашивая. Расширяйте границу осознанно через --add-dir или /add-dir, а не рефлекторно.

CAUTION. Открытая папка — не песочница безопасности. Claude Code может запросить дополнительные каталоги, выполнять команды, ходить в сеть и пользоваться подключёнными сервисами в пределах разрешений. Не открывайте домашний каталог как проект: принятие доверия там держится только на сессию и никогда не пишется на диск, поэтому запрос будет появляться при каждом запуске, а радиус поражения ошибки в разрешениях — вся ваша личная файловая система.

3.3 Монорепозитории и большие деревья

В монорепозитории вложенные CLAUDE.md чужих команд подхватываются из каждого родительского каталога. Используйте claudeMdExcludes, чтобы их пропускать, правила с областью по путям — чтобы грузить инструкции только для подходящих файлов, и скиллы на уровне пакета — чтобы держать руководство локальным. Это следует делать раньше, чем брать более широкое окно контекста.

Ключевые положения главы 3

  • Открытая папка — граница по умолчанию, а не песочница.
  • В ручном режиме Claude пишет только внутри папки; в авторежиме читает за её пределами не спрашивая.
  • Никогда не открывайте домашний каталог как проект.
  • В монорепозитории сначала claudeMdExcludes и правила по путям, и только потом — увеличение окна контекста.

Глава 4. Режимы, модели, усилие и расход

4.1 Контроли, которые важны в первую очередь

  • Режим разрешений — Shift+Tab в CLI, индикатор режима в VS Code, селектор в Desktop. Цикл default → acceptEdits → plan есть в каждой сессии; два дополнительных режима встают после plan, когда включены, а dontAsk в цикле не появляется вовсе. Подробно — глава 7.
  • Модель — /model или выбор из списка. Доступность меняется: не заучивайте имя модели из записи видео.
  • Усилие — /effort, уровни low, medium, high, xhigh, max на всех поверхностях, плюс ultracode и auto, доступность которых различается. ultracode — не просто уровень усилия, см. главу 22.
  • Быстрый режим — /fast, меняет глубину на задержку.
  • Советник — /advisor подключает к рабочей модели более сильную, вызываемую в ключевые моменты.
  • Прерывание — Esc останавливает текущий ход, Ctrl+C жёстче.
  • Настройки из промпта — /config, включая ключи без отдельной команды.

/effort и claude --effort — два интерфейса к одному контролю, и они принимают не одни и те же слова. Наблюдение на Claude Code 2.1.246, 26 августа 2026 — не гарантия продукта:

4.4 Расход и контекст измеряются раздельно

/usage сообщает стоимость сессии, лимиты плана и активность, и умеет разбивать расход по скиллам, сабагентам, плагинам и MCP-серверам. /cost и /stats — документированные псевдонимы. /context отвечает на другой вопрос: что сейчас занимает окно разговора. Это связанные, но разные величины, и оптимизация одной за счёт другой — частая и дорогая ошибка.

Два факта объясняют большинство неожиданных счетов:

  1. Расход растёт суперлинейно в длинной сессии, потому что каждый запрос несёт накопленную историю.
  2. Из-за кеширования промпта смена модели, /compact или смена стиля вывода вынуждают некешированный ход, а правка CLAUDE.md не вступает в силу посреди сессии. Если изменение проектных инструкций будто бы проигнорировано — обычно причина в этом.

4.5 Что оптимизировать в первую очередь

  1. Перестать передавать нерелевантный материал.
  2. Сохранять долговечные результаты в файлы вместо повторной генерации.
  3. Делегировать только ограниченную независимую работу (глава 16).
  4. Убрать неиспользуемые плагины, коннекторы и агентов — после измерения их вклада, а не до.
  5. Начинать чистую сессию, когда задача сменилась.

Не оптимизируйте за счёт отказа от проверки. Более дешёвый неверный ответ — всё равно отход, и в этой области это отход, который приходит, выглядя как успех.

Ключевые положения главы 4

  • Режим разрешений, модель, усилие и стиль вывода — четыре независимых контроля.
  • /usage измеряет ваш расход, /context — что занимает окно. Это разные вопросы.
  • Расход растёт суперлинейно в длинной сессии.
  • Правка CLAUDE.md не действует посреди сессии: системный контекст читается один раз при старте.

Часть II — Безопасный метод работы

Глава 5. Запустить и направлять сессию

5.1 Начинать с проверяемого брифа

Первому сообщению не нужен особый синтаксис — ему нужна структура, при которой пропуск виден. Заголовки служат читателю не меньше, чем модели: они делают отсутствующую границу заметной до того, как она станет инцидентом.

Цель
Собрать одностраничный research-бриф из файлов в notes/.

Область
Использовать только предоставленные заметки. Пробелы в свидетельствах —
обозначать, а не заполнять по памяти или из сети.

Результат
Сохранить drafts/brief-v1.md: краткое резюме, три вывода, таблица
«утверждение → источник».

Границы
Не править исходные файлы. Не обращаться к другим папкам и к интернету.

Готово, когда
Каждое фактическое утверждение сопоставлено с названной заметкой-источником.

5.2 Смотреть на начало незнакомой работы

Claude Code показывает прогресс и вызовы инструментов. В начале задачи читайте их и спрашивайте: те ли файлы он читает; не пытается ли совершить внешнее действие, которого вы не просили; совпадает ли его трактовка «готово» с вашей; делегировал ли он — и с каким брифом.

Когда направление устоялось, следить за каждой строкой не нужно. А вот работа без присмотра требует более жёстких границ и более сильной проверки завершения, а не более слабых.

5.3 Корректировать без перезапуска

Наберите сообщение и нажмите Enter — оно встанет в очередь. Если инструменты работают, Claude получит его по завершении вызовов и сможет скорректироваться в том же ходе. Когда правка не может ждать — Esc останавливает текущий ответ или вызов инструмента. Явно говорите, продолжать ли:

Стоп. Не используй интернет — я упустил эту границу. Сохрани уже выполненный
локальный анализ, отбрось внешний материал и продолжи только с утверждённых
заметок.

CAUTION. Прерывание не отменяет уже сделанные изменения файлов и не отзывает внешнее действие. Смотрите дифф или состояние чекпойнта.

5.4 Побочные вопросы, фокус и запись

  • /btw — задать побочный вопрос, не добавляя его в историю разговора.
  • /focus — свернуть вид до последнего промпта и ответа.
  • /recap — однострочное резюме сессии.
  • /export — записать отрендеренный текстовый транскрипт.

Последнее важно для аудита: это поддерживаемый способ сохранить свидетельство происходившего, и он предпочтительнее разбора сырого JSONL-транскрипта, чей формат внутренний и меняется между релизами.

5.5 Голосовой ввод

Диктовка облегчает составление длинных брифов, но читайте расшифровку перед отправкой. Имена файлов, флаги команд, отрицания и числа — там, где диктовка ошибается, и потерянное «не» в формулировке границы — самая дорогая однословная ошибка в этой книге.

Глава 6. План, комментарий, одобрение, выполнение

6.1 Когда планировать

Режим плана — когда у работы несколько стадий, неясные требования, дорогие внешние действия или широкий охват файлов. Вход: /plan, селектор режима или claude --permission-mode plan. В режиме плана Claude читает и исследует, но не правит исходники.

План должен снижать неопределённость до правок, а не пересказывать вашу просьбу в более длинной форме.

6.2 Минимально полный план

План готов к одобрению, когда он называет:

  1. предполагаемый результат и явные исключения;
  2. входные данные и файлы-источники истины;
  3. каждый файл или систему, которые изменятся;
  4. упорядоченные шаги реализации;
  5. решения, остающиеся за человеком;
  6. тесты или свидетельство осмотра для каждого существенного результата;
  7. внешние побочные эффекты;
  8. путь отката или восстановления.

Для отчёта пункт 6 означает покрытие источников, проверку ссылок, орфографию и рендеринг; для программы — автотесты плюс прямое наблюдение поведения.

6.3 Читать план как договор

Не одобряйте план за то, что он длинный или уверенный. Комментируйте конкретные слабости:

Шаг 3 слишком широк. Раздели извлечение из источников и интерпретацию и
потребуй одну строку реестра свидетельств на каждое существенное утверждение
до начала написания.
Добавь шлюз одобрения человеком перед любой публикацией или внешней отправкой.
Определи, что значит «полностью» для итогового файла и как ты это проверишь.

Принятие плана вдобавок даёт сессии сгенерированное по плану название — мелкий, но полезный артефакт аудита.

6.4 Одобрять правильную область

Одобрение плана — не карт-бланш на любой метод. Сохраняйте тот режим разрешений, в котором собирались быть. Хороший план в сочетании с авторежимом может поддержать долгое выполнение без присмотра, но авторежим — это режим разрешений с классификатором: он не песочница и не гарантия.

6.5 Требовать отчёт о завершении — и проверять его

Сообщи: изменённые файлы; тесты или проверки, которые реально выполнялись,
с их выводом; нерешённые ограничения; все внешние побочные эффекты.
Не описывай проверку, которая не запускалась.

Затем смотрите свидетельство сами: /diff открывает интерактивный просмотр незакоммиченных изменений, git diff — версия, которую можно заархивировать.

Глава 7. Разрешения, песочница и чекпойнты

Разрешения — это принудительно применяемые продуктом правила использования инструментов. Инструкции в промпте или в CLAUDE.md влияют на то, что Claude пытается делать; они не выдают и не отзывают доступ. Это различение — фундамент всей книги.

7.1 Режимы разрешений

На планах Pro, Max и Team встроенный стартовый режим — авторежим. Это категорическое утверждение текущей документации, а не тенденция; настройки организации, поверхность и defaultMode могут его изменить, поэтому смотрите селектор, а не предполагайте.

Два факта о режимах имеют операционные последствия:

  • plan и bypassPermissions никогда не восстанавливаются при возобновлении сессии: возобновлённая сессия возвращается в тот режим, с которого началась бы новая.
  • bypassPermissions распространяется: участники команды агентов наследуют ведущего, работающего без проверок, а дочерний агент наследует режим родителя, и собственный permissionMode дочернего не может это перебить. Исключение — сабагенты воркфлоу, и они работают в обратную сторону: они всегда идут в acceptEdits и наследуют ваш список разрешённых инструментов, каким бы ни был режим сессии.

Вывод: режим сессии не является надёжным указателем того, что позволено порождённому ею агенту — ни в одну, ни в другую сторону.

7.2 Правила и порядок их вычисления

/permissions открывает просмотр и правку правил Allow, Ask и Deny.

Правила вычисляются в порядке deny → ask → allow. Решает первое совпадение в этом порядке, и специфичность порядок не меняет.

Поэтому широкое Bash(aws *) в deny блокирует любой подходящий вызов, включая тот, что совпадает и с более узким allow вроде Bash(aws s3 ls). Deny-правило не может нести исключений.

Две тонкости стоит запомнить:

  • Голое имя инструмента в deny убирает инструмент из контекста Claude целиком — он его вообще не видит. Правило с областью вроде Bash(rm *) оставляет инструмент доступным и блокирует подходящие вызовы.
  • Правило deny или ask срабатывает через ведущее присваивание переменной окружения, а allow — нет: Bash(rm *) в deny поймает и FOO=bar rm -rf tmp/.

Пример набора правил:

{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Read(~/.ssh/**)",
      "Bash(git push *)",
      "Bash(curl *)",
      "Bash(wget *)"
    ],
    "ask": ["WebFetch", "WebSearch"],
    "allow": ["WebFetch(domain:code.claude.com)"]
  }
}

Заметьте, чего этот пример не делает: поскольку deny идёт раньше allow, правило allow для WebFetch не побеждает ни одно deny-правило, а deny на Bash(curl *) — причина направлять веб-доступ через инструмент WebFetch с указанием домена, а не через оболочку.

Подстановки в спецификаторе домена совпадают только между точками, если не стоят в начале: WebFetch(domain:.example.com) поймает поддомены, но не example.com, а WebFetch(domain:example.) поймает example.org, но не example.evil.com.

Симлинки разрешаются против обоих списков: ссылка внутри разрешённого каталога, указывающая на ~/.ssh/id_rsa, блокируется.

Командные правила — в .claude/settings.json; личные переопределения и сохранённые одобрения — в .claude/settings.local.json (не коммитится); пользовательские — в ~/.claude/settings.json. Управляемые настройки стоят выше всех и не переопределяются ничем, включая аргументы командной строки.

7.3 Понять запрос до одобрения

На поддерживаемых запросах разрешения Bash или PowerShell Ctrl+E просит объяснить команду и её риск, ничего не выполняя. Отказ — тоже ответ, и отказ с комментарием, предлагающим более безопасную альтернативу, часто самый быстрый путь вперёд.

Перед одобрением того, чего вы не писали, спросите:

  • Какие именно файлы, аккаунт или хост это трогает?
  • Цель разрешена явно или опирается на широкую подстановку?
  • Операция обратима?
  • Может ли она поместить учётные данные в вывод?
  • Можно ли ту же информацию сперва получить только на чтение?

7.4 Песочница

/sandbox открывает панель песочницы. Песочница ограничивает файловую систему и сеть ниже слоя модели, принудительно, силами ОС, для каждой Bash-команды и её дочерних процессов. Работает на macOS (Seatbelt), Linux и WSL2; нативная Windows не поддерживается.

Контроли, которые стоит знать:

  • sandbox.filesystem.denyWrite, denyRead, allowRead. Где правила чтения пересекаются, побеждает более специфичный путь, и deny держит внутри более широкого allow: allowRead: ["~/"] вместе с denyRead: ["~/**/.env"] оставляет все .env заблокированными, а остальной домашний каталог читаемым.
  • sandbox.credentials.files и sandbox.credentials.envVars, каждая запись deny или mask. Запрещённые файлы нечитаемы внутри песочницы; запрещённые переменные окружения сбрасываются перед каждой командой. Маскирование позволяет команде получить значение, скрыв его из вывода инструмента.
  • autoAllowBashIfSandboxed по умолчанию true, поэтому команды в песочнице идут без запросов; поставьте false, если запросы всё же нужны.

7.5 Чекпойнты и откат

Claude Code записывает чекпойнты перед правками файлов, а /rewind восстанавливает разговор, код или и то и другое. Это полезно. Это не резервная копия, и пробелы систематические:

  • внешние действия локальным откатом не отменяются;
  • изменения через Bash-команды или внешние программы не отслеживаются как чекпойнты правок файлов;
  • большинство правок сабагентов не попадает в историю чекпойнтов родителя;
  • запись через симлинки и жёсткие ссылки может выпасть из покрытия;
  • неотслеживаемые и игнорируемые файлы требуют отдельной заботы;
  • действия в браузере, сообщения, опубликованные артефакты и отправленные коммиты нельзя отозвать.

CHECKPOINT главы 7

  • На чувствительных путях стоят deny-правила, и вы проверили, что они действительно блокируют.
  • Внешняя запись требует ask или человеческого шлюза.
  • Вы знаете, активна ли песочница и что она покрывает.
  • Вы умеете показать текущий дифф и состояние чекпойнта.
  • bypassPermissions не используется вне изолированной среды.

Глава 8. Защитить работу с помощью Git и GitHub

Git ведёт локальную историю. GitHub размещает репозиторий удалённо и добавляет совместную работу, ревью и контроль доступа. Это связанные, но не взаимозаменяемые вещи: коммит может существовать целиком на вашей машине — и часто это именно то, что нужно, пока агент работает.

8.1 Безопасная последовательность для начинающего

Создайте .gitignore до первого коммита:

.env
.env.*
!.env.example
.claude/settings.local.json
CLAUDE.local.md
secrets/
*.key
*.pem

Это отправная точка, а не детектор секретов. Осматривайте перед коммитом:

git status
git diff --staged
git add .
git commit -m "Create research brief workspace"

8.2 Добавлять удалённый репозиторий осознанно

Подтвердите владельца, имя репозитория, видимость и URL, и только после второго осмотра секретов и диффа выполняйте push. Claude может предложить все эти команды; создание аккаунта, аутентификация, видимость и одобрение выпуска — за вами.

8.3 Рабочий цикл с участием агента

  1. Claude резюмирует предполагаемое изменение.
  2. Вы одобряете план локальной правки.
  3. Claude правит и выполняет проверку.
  4. Вы осматриваете git diff.
  5. Claude предлагает сообщение коммита, основанное на диффе.
  6. Вы одобряете коммит.
  7. Push или pull request — отдельное действие со шлюзом человека.

CAUTION. Автоматический хук «закоммитить и запушить в конце сессии» может опубликовать секреты, сломанную работу, сгенерированный мусор или изменения не из той ветки. Если автоматизировать необходимо — выделенная ветка, защищённая ветка по умолчанию, ключи с ограниченной областью, пред-push-проверки и отчётность об отказах.

8.4 Автоматическое ревью и его пределы

  • /security-review — проход по безопасности изменений текущей ветки.
  • /code-review (псевдоним /review) — ревью диффа или pull request.
  • /code-review ultra — многоагентное ревью в облаке.

Ничто из этого не заменяет человека-ревьюера или специализированную оценку и не должно быть единственным шлюзом выпуска.

8.5 Восстановление шире репозитория

Git не покрывает неотслеживаемые файлы, внешние базы и сервисы, значения в менеджерах секретов, действия в браузере, опубликованные артефакты и локальную конфигурацию, исключённую через .gitignore. Планируйте восстановление для процесса, а не только для дерева исходников.

Часть III — Знание о проекте и контекст

Глава 9. Как построить рабочий CLAUDE.md

CLAUDE.md — долговечное руководство по проекту, загружаемое в начале каждой сессии. Оно доставляется пользовательским сообщением после системного промпта, а не как часть системного промпта: Claude его читает и старается следовать, но гарантии соблюдения нет — особенно для расплывчатых или конфликтующих инструкций. Инструкция, которая обязана держать, принадлежит правилу разрешений (глава 7) или хуку (глава 17).

9.2 Инициализировать, потом править

/init генерирует стартовый CLAUDE.md, анализируя проект; если файл уже есть, команда предлагает улучшения, а не перезаписывает. Она также читает файлы правил Cursor и Copilot. CLAUDE_CODE_NEW_INIT=1 включает интерактивный многофазный режим с исследованием сабагентом и проверяемым предложением до записи.

Порядок работы:

  1. Запустить /init.
  2. Прочитать каждую строку.
  3. Удалить общие описания, историю изменений, переходящее состояние и продублированную документацию.
  4. Оставить операционные факты, конвенции, отличающиеся от умолчаний инструментов, подводные камни и команды проверки.
  5. /memory — посмотреть, что загружено; /context — подтвердить.

Цель — менее 200 строк. Более длинные файлы съедают контекст и снижают следование. Файл больше 4 МиБ пропускается целиком. /doctor предлагает сокращения для закоммиченного файла, вырезая то, что Claude может вывести из кодовой базы, и сохраняя обоснования и конвенции (2.1.206+).

9.3 Указатель, а не склад

Длинный справочный материал принадлежит отдельным файлам с правилом извлечения. Импорты через @path/to/file поддерживаются до глубины четыре, но импортированные файлы грузятся при старте и не снижают занятость контекста — они помогают организации, а не стоимости. Разбор импортов пропускает кодовые фрагменты и блоки, поэтому @README в обратных кавычках остаётся буквальным.

Импорт в проектном файле памяти, чей путь ведёт за пределы рабочего каталога, считается внешним, и при первой встрече показывается диалог одобрения со списком файлов; отказ отключает их навсегда. Этот диалог — механизм контроля цепочки поставок: он существует потому, что импорт в общий репозиторий может закоммитить кто-то другой.

Блочные HTML-комментарии вырезаются перед внедрением, поэтому заметки сопровождающего не стоят контекста.

9.4 Модульные правила

Большие наборы инструкций разбиваются в .claude/rules/.md, обнаруживаемые рекурсивно. Правило без frontmatter paths грузится при старте с тем же приоритетом, что и .claude/CLAUDE.md. Правило с* paths грузится, только когда Claude читает подходящий файл:

---
paths:
  - "sources/**/*.md"
  - "notes/**/*.{md,txt}"
---

# Обращение с источниками

- Никогда не править файл под `sources/`.
- Фиксировать происхождение как `source-id · дата получения · URL или место`.

Пользовательские правила в ~/.claude/rules/ грузятся раньше проектных, что даёт проектным более высокий приоритет. Весь список paths одного правила делит бюджет в 1 000 развёрнутых шаблонов и 4 МиБ; шаблон, который его превысил бы, используется неразвёрнутым и не совпадает ни с чем.

9.5 Когда пересматривать

Пересматривайте CLAUDE.md, когда Claude раз за разом ищет документированную команду; когда вы дважды поправили одно и то же правило; когда изменилась структура; когда две инструкции конфликтуют; когда /context показывает непропорциональные накладные расходы на инструкции. Просите предлагаемый дифф с обоснованием каждого добавления и удаления — никогда не «оптимизируй это» вслепую.

О сжатии. CLAUDE.md из корня проекта переживает /compact: Claude Code перечитывает его с диска и внедряет заново. Вложенные файлы и правила с областью по путям перезагружаются по мере чтения соответствующих файлов. Инструкция, исчезнувшая после сжатия, была дана только в разговоре — это и есть аргумент в пользу того, чтобы её записать.

Глава 10. Глобальные инструкции и авто-память

Долговременное знание служит трём разным целям, и их смешение даёт раздутый контекст и устаревшее поведение:

  1. Инструкции говорят Claude, как себя вести — CLAUDE.md, правила.
  2. Справочные файлы хранят факты и процедуры, извлекаемые по требованию.
  3. Авто-память хранит краткие заметки, которые Claude пишет себе сам.

10.1 Глобальные инструкции

~/.claude/CLAUDE.md — используйте скупо. Уместно: предпочитаемый рабочий язык, универсальный шлюз безопасности, устойчивая конвенция вывода, указатель на каталог пользовательских правил. Неуместно: команды конкретного проекта, стиль одного клиента, временные приоритеты, каталог всех инструментов, которые вы когда-нибудь можете применить.

10.2 Авто-память

Включена по умолчанию. Claude сохраняет четыре вида заметок, фиксируемых полем type во frontmatter файла памяти:

  • user — ваша роль, экспертиза и рабочие предпочтения;
  • feedback — ваши исправления и подтверждённые подходы;
  • project — текущая работа, сроки и решения, не выводимые из кода или истории;
  • reference — где искать информацию вне проекта.

Хранение. У каждого проекта свой ~/.claude/projects/<project>/memory/, где <project> выводится из git-репозитория, поэтому все worktree и подкаталоги одного репозитория делят один каталог памяти. MEMORY.md — указатель; файлы по темам содержат детали и читаются по требованию. Перенести хранилище можно через autoMemoryDirectory. Авто-память локальна для машины и не разделяется между машинами и облачными средами.

Лимит загрузки. В начале каждого разговора грузятся первые 200 строк MEMORY.md либо первые 25 КБ — что наступит раньше; содержимое за этой границей не грузится.

Отключение. Переключатель в /memory пишет autoMemoryEnabled в ~/.claude/settings.json; {"autoMemoryEnabled": false} в настройках проекта отключает её только для этого проекта; CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 — запасной путь. Это исправляет заблуждение M06.

CAUTION — хранение. Claude Code удаляет старые транскрипты сессий по истечении cleanupPeriodDays, но исключает каталог памяти из этой уборки. MEMORY.md и файлы по темам живут, пока вы или Claude их не отредактируете или не удалите. Если ваши обязательства по хранению исходят из 30-дневной локальной уборки — авто-память находится вне её.

Относитесь к авто-памяти как к удобству, а не к спецификации: Claude может запомнить ситуативное или слишком широко обобщить предпочтение. Устойчивая правда о проекте принадлежит проверенным файлам под контролем версий.

Глава 11. Проектировать контекст осознанно

Контекст — это то, что есть у модели на текущем ходу: системный промпт, описания инструментов, проектные инструкции, приложенные файлы, результаты инструментов и история разговора. Файл на диске не является «известным» лишь потому, что Claude мог бы его прочитать.

11.1 Осмотреть окно

/context — для диагностики состава, а не для погони за числом. Окна, модели и поведение автосжатия меняются; /autocompact задаёт окно автосжатия явно.

11.2 Четыре способа вернуть фокус

1 — Сохранять устойчивое состояние. Находки, планы, решения и открытые вопросы принадлежат файлам проекта. Разговор — рабочая поверхность, а не база данных.

2 — Передать эстафету чистой сессии.

Подготовь передачу для чистой сессии. Включи цель, выполненную работу,
утверждённые решения, открытые вопросы, точные ссылки на файлы, уже
проведённую проверку и следующее безопасное действие. Исключи разговорную
историю, не влияющую на задачу.

3 — /clear. Начинает заново, сохраняя проектные инструкции и память. Он также очищает задачи по расписанию уровня сессии и активную цель и закрывает группу вкладок Chrome. Сначала сохраните передачу. Предыдущий разговор не потерян: /resume либо пункт предыдущей сессии в меню отката.

4 — /compact [инструкции]. Сжимает, чтобы освободить контекст. Сжатие с потерями — говорите, что обязано уцелеть:

/compact Сохрани все утверждённые решения, неразрешённые противоречия, пути
файлов, результаты проверок и шлюз одобрения человеком. Убери отброшенные
варианты.

Глава 12. Сессии: возобновление, имя, хранение

Сессия — сохранённый разговор, привязанный к каталогу проекта. CLI, Desktop, веб и VS Code ведут собственные истории.

12.1 Возобновление

claude --continue            # самая свежая интерактивная сессия здесь
claude --resume              # выбор сессии
claude --resume <имя|id>     # напрямую
claude --from-pr <номер>     # выбор, отфильтрованный по связанным с PR сессиям
claude -n research-brief-source-audit   # задать имя при старте (--name)

Внутри сессии /resume переключает разговор, /rename переименовывает. В списке выбора: Ctrl+R — переименовать, Ctrl+A — расширить на все проекты, Ctrl+W — на все worktree репозитория, Ctrl+B — фильтр по текущей ветке; вставка URL pull request находит создавшую его сессию.

Возобновлённая сессия восстанавливает историю разговора, модель, агента, режим разрешений, активную цель и неистёкшие задачи по расписанию. Три из них имеют условия, и именно в условиях живут неожиданности:

  • Режим. plan и bypassPermissions не восстанавливаются никогда. auto восстанавливается, только пока аккаунт отвечает требованиям авторежима. Manual восстанавливается как Manual там, где новая сессия стартовала бы в auto из встроенного умолчания; но если действует defaultMode из файла настроек, сессия возобновится в нём. --permission-mode перебивает восстановленное.
  • Модель не восстанавливается, если она выведена из обращения или запрещена через availableModels; если при запуске её выбирает флаг --model или переменная окружения семейства ANTHROPIC_MODEL; а также у провайдеров с собственными идентификаторами развёртывания.
  • Задачи по расписанию восстанавливаются только неистёкшие, а фоновые Bash-задачи и мониторы не восстанавливаются вовсе.

Не восстанавливаются --mcp-config, --settings, --plugin-dir, --fallback-model и каталоги, добавленные через --add-dir — передайте их заново. Каталоги, добавленные посреди сессии через /add-dir, тоже не восстанавливаются.

Подводный камень: сессии, чьим первым промптом была команда /loop, не появляются в списке выбора и пропускаются --continue. Если задача по расписанию будто бы исчезла — обычно причина в этом.

12.2 Называть по результату

Хорошие имена переживают неделю: client-x-brief-source-audit, accessibility-remediation-plan, invoice-workflow-test-2026-08.

Избегайте test, new chat и того, чем случайно оказался первый промпт. Безымянные интерактивные сессии получают отображаемое имя вида my-app-3f — оно не является дескриптором для возобновления — плюс сгенерированный из первого промпта заголовок, который им является.

Каждая глава этой части — ещё и глава о цепочке поставок. Проходите её только после глав 1–12.

Глава 13. Подключение внешних инструментов через MCP

Model Context Protocol — открытый стандарт подключения ИИ-клиентов к внешним инструментам и данным. Он расширяет возможности и доверие одновременно: подключённый инструмент действует с теми полномочиями, которые вы ему дали.

13.1 Области видимости

ОбластьХранениеПрименение
Local (по умолчанию)~/.claude.jsonОдин проект, текущий пользователь; приватная конфигурация
User~/.claude.jsonДоступно во всех ваших проектах
Project.mcp.json в корне репозиторияОбщая командная конфигурация, коммитится

У проектной области есть механизм одобрения, который часто упускают. Сервер уровня проекта из .mcp.json отображается как ⏸ Pending approval, пока вы не запустите claude интерактивно и не одобрите его; отклонённые серверы записываются в disabledMcpjsonServers. С 2.1.196 одобрения читаются только из файлов настроек, не закоммиченных в репозиторий, пока вы не доверите рабочее пространство — поэтому клонированный репозиторий не может одобрить собственные серверы. Это и есть контроль, который не даёт вредоносному pull request незаметно подключить сервер.

CAUTION. Никогда не помещайте буквальные учётные данные в .mcp.json. Используйте OAuth, где провайдер его поддерживает, либо подстановку ${VAR} со ссылкой на переменную окружения, и аккаунт с минимальными правами.

13.2 Транспорты

claude mcp add --transport http notion https://mcp.notion.com/mcp --scope project
claude mcp list
claude mcp get notion
  • HTTP — предпочтительный. В JSON type: "http"; streamable-http принимается как псевдоним.
  • SSE — устарел. Используйте HTTP, где он доступен.
  • stdio — локальный процесс. Всё после -- передаётся серверу без изменений.
  • WebSocket (type: "ws") — постоянный двунаправленный, для серверов, которые шлют события. Не поддерживает ни OAuth, ни флаг --transport; аутентификация только через заголовки.

Запись JSON с url, но без type — ошибка конфигурации: Claude Code читает запись без типа как stdio и пропускает её с явным сообщением.

Внутри сессии /mcp показывает статус, завершает OAuth и перечисляет инструменты сервера.

13.3 Безопасная процедура установки

  1. Найти официальный репозиторий или документацию провайдера. Проверить URL посимвольно.
  2. Определить минимум данных и действий, нужных задаче.
  3. Использовать тестовый аккаунт или пространство с минимальными правами.
  4. Осмотреть исходники, издателя, пакет и сетевые адресаты, где возможно.
  5. Выбрать самую узкую работающую область.
  6. Держать секреты вне .mcp.json и вне системы контроля версий.
  7. Начать новую сессию, чтобы конфигурация перечиталась.
  8. Аутентифицироваться и осмотреть выставленные инструменты через /mcp.
  9. Сперва выполнить операцию только на чтение.
  10. Для записи добавить явное одобрение — правило ask или шлюз человека.

CAUTION — вывод инструмента это недоверенный ввод. Содержимое, возвращённое MCP-сервером, может содержать инструкции, адресованные агенту, приватные данные или материал, задуманный, чтобы увести задачу. Это непрямая инъекция промпта. Считайте любой результат инструмента данными, ограничивайте, что агент может делать дальше, и требуйте подтверждения перед любой внешней записью.

13.4 Стоимость контекста — измерять, а не предполагать

Определения инструментов действительно занимают контекст, но это частично смягчено: Tool Search откладывает многие определения до надобности. Измеряйте через /context и /usage. Убирать ненужные серверы всё равно стоит — аргумент здесь безопасность и ясность, а не токены.

13.5 Организационный контроль

Администраторы могут ограничивать, какие серверы пользователи вправе добавлять, через списки разрешений и запретов в управляемой конфигурации. deniedMcpServers блокирует named-сервер целиком — включая claude-in-chrome, и именно так организация централизованно выключает интеграцию с браузером.

Глава 14. Переменные окружения и секреты

Файл .env — удобство разработчика, а не граница безопасности. Коммитьте только шаблон с именами, никогда со значениями.

14.1 Почему «Claude этого не видит» небезопасно

Если Claude вправе читать .env, содержимое попадает в вывод инструмента. Если он запустит команду, печатающую переменную окружения, значение попадёт в транскрипт открытым текстом. Подпроцесс может его передать. Фраза в CLAUDE.md «не читай секреты» — предпочтение, а не принуждение. Это заблуждение M04 и самое частое ложное убеждение у новичков.

14.2 Слоистые механизмы контроля

  1. Минимальные права. Выдавать учётные данные, ограниченные сервисом, действием и средой. Это единственный контроль, ограничивающий ущерб уже после раскрытия.
  2. Deny-правила разрешений. Блокировать чтение файлов и каталогов с секретами.
  3. Контроль учётных данных в песочнице. sandbox.credentials.files и .envVars, deny или mask. Запрещённые переменные сбрасываются перед каждой командой в песочнице.
  4. Сетевые ограничения. Запретить curl и wget на уровне Bash и разрешать конкретные домены через WebFetch(domain:…).
  5. Дисциплина вывода. Никогда не выводить, не логировать и не подставлять секрет в команду, которую увидит модель.
  6. Гигиена git. Игнорировать файлы секретов и просматривать staged-дифф перед каждым коммитом.
  7. Ротация. Немедленно отзывать, если учётные данные попали в транскрипт, коммит, лог, артефакт или недоверенный сервис.

Не вставляйте конфигурацию безопасности, не проверив, что она блокирует. Попросите Claude попытаться выполнить запрещённое чтение и подтвердите отказ, затем проверьте в /permissions, из какого файла пришло правило.

14.3 Реагирование на инцидент

  1. Остановить задачу.
  2. Отозвать или сменить учётные данные. Это делается раньше всего остального.
  3. Убрать их из файлов, логов и любого опубликованного артефакта.
  4. Если закоммичено — выполнить процедуру удаления чувствительных данных хостинг-провайдера; удалить последнюю строку недостаточно.
  5. Просмотреть транскрипт сессии, журналы аудита подключённых систем и — для организаций — журнал аудита Claude Code.
  6. Исправить тот механизм контроля, который допустил раскрытие, и добавить на него регрессионную проверку.

Глава 15. Превращать повторяемую работу в скиллы

Скилл — переиспользуемый пакет инструкций и необязательных ресурсов. Claude вызывает его, когда описание совпадает с задачей, либо вы зовёте его как /имя-скилла. В отличие от CLAUDE.md, тело скилла грузится только при использовании, поэтому длинный справочный материал почти ничего не стоит, пока не понадобится.

~/.claude/skills/<name>/SKILL.md     # пользовательская область
.claude/skills/<name>/SKILL.md       # область проекта

Пользовательские команды слились со скиллами: и .claude/commands/deploy.md, и .claude/skills/deploy/SKILL.md создают /deploy.

15.1 Строить скилл из наблюдённой работы

  1. Выполнить процедуру вручную, вместе с Claude, один раз.
  2. Определить входы, инструменты, решения, выходы и режимы отказа.
  3. Попросить Claude написать минимальный скилл из того, что реально произошло.
  4. Прочитать каждый файл и каждую выдачу инструмента.
  5. Проверить на действительно другом примере.
  6. Исправить вывод руками.
  7. Обновить скилл общим уроком, а не случайной деталью.

15.2 Frontmatter, важный для безопасности

ПолеДействие
allowed-toolsИнструменты, которыми Claude может пользоваться без спроса в течение хода, вызвавшего скилл. Выдача снимается с вашим следующим сообщением
disallowed-toolsИнструменты, убранные из пула на время активности скилла; тоже снимается со следующим сообщением

И отрендеренный SKILL.md попадает в разговор один раз и остаётся до конца сессии — Claude Code не перечитывает файл на последующих ходах, поэтому пишите постоянное руководство, а не одноразовые шаги.

Ставьте disable-model-invocation: true на всё, что имеет побочные эффекты — /commit, /deploy, /send-message. Вам не нужно, чтобы Claude сам решал, что код выглядит готовым к отгрузке.

15.3 Ревью безопасности скилла

Перед установкой или запуском стороннего скилла осмотрите: SKILL.md и каждый упомянутый файл; allowed-tools, disallowed-tools и блок hooks; инлайн-shell; установку пакетов и сетевые вызовы; читаемые и записываемые пути; доступ к учётным данным; любую инструкцию, отговаривающую от проверки или подавляющую вывод.

Контроли: disableBundledSkills выключает все встроенные скиллы кроме /doctor; skillOverrides ставит отдельный скилл в "off" или "user-invocable-only" без правки файла; deny-правило Skill ограничивает доступ Claude; disableSkillShellExecution заменяет строки инлайн-shell заглушкой.

CAUTION. Звёзды, число загрузок, рекомендация из видео или официально звучащее имя — не ревью безопасности. Закрепляйте проверенную версию и повторяйте ревью после каждого обновления. Заблуждение M12.

Глава 16. Делегировать ограниченную работу сабагентам

Сабагент — специализированный экземпляр с собственным окном контекста, системным промптом, доступом к инструментам и разрешениями. Делегируйте, когда независимость, фокус или параллелизм улучшают результат, — а не чтобы мелкое действие выглядело значительным.

16.1 Свежий контекст, форки и почему это важно

Обычный сабагент стартует с чистого листа: он получает собственный системный промпт, сообщение делегирования, иерархию CLAUDE.md, снимок git-status и предзагруженные скиллы. Он не получает историю разговора родителя, его стиль вывода и авто-память.

Форк устроен иначе: он наследует весь разговор, системный промпт родителя, инструменты и модель и делит с родителем кеш промпта. /subtask создаёт именно такой.

CAUTION — главная поправка этой главы. Режим форка включён по умолчанию в интерактивных сессиях, управляется переменной CLAUDE_CODE_FORK_SUBAGENT (1 — вкл, 0 — выкл). «Ревьюер», созданный походя в интерактивной сессии, унаследует те самые рассуждения, которые должен проверять. Если нужна настоящая независимость — используйте явное определение агента и подтвердите контекст ревьюера. Заблуждение M03.

Независимость для целей ревью убывает так: сабагент > участник команды > агент воркфлоу > форк. Неуточнённая просьба «дай ревьюера» в интерактивной сессии даёт наименее независимый вариант.

16.4 Бриф делегирования

Каждый промпт сабагенту должен называть: точный вопрос; файлы или источники, которыми можно пользоваться; разрешённые инструменты и действия; требуемый формат возврата; критерии успеха; когда остановиться и доложить о неопределённости. Никогда не делегируйте «почини всё».

Глава 17. Поведение по событиям: хуки

Хук выполняет настроенное действие в момент события жизненного цикла. Хуки — способ сделать так, чтобы нечто произошло из-за события, а не потому, что модель вспомнила предложение. Это единственный механизм в книге, одновременно детерминированный и написанный пользователем.

17.1 События

Наиболее значимые на практике:

  • SessionStart, SessionEnd — сопоставляются по типу старта (startup, resume, clear, compact, fork) и по причине завершения.
  • UserPromptSubmit — до обработки промпта; выход 2 отклоняет его.
  • PreToolUse — до вызова инструмента; выход 2 блокирует его.
  • PermissionRequest — когда вызову нужно решение по разрешению; возвращайте JSON-решение, а не выход 2.
  • PermissionDenied — после отказа авторежима; может задать retry.
  • PostToolUse, PostToolUseFailure, PostToolBatch — постфактум; не могут отменить внешний побочный эффект.
  • Stop, StopFailure, SubagentStart, SubagentStop, TeammateIdle — жизненный цикл хода и агента; выход 2 на Stop не даёт остановиться.
  • TaskCreated, TaskCompleted — общий список задач; выход 2 блокирует операцию.
  • PreCompact, PostCompact, InstructionsLoaded, ConfigChange, CwdChanged, DirectoryAdded, FileChanged, WorktreeCreate, WorktreeRemove, Notification, MessageDisplay, Elicitation, ElicitationResult.

ConfigChange заслуживает отдельного упоминания: он позволяет организации аудировать или блокировать изменения настроек, сделанные во время сессии.

17.2 Типы обработчиков

Доступны пять: command (shell или exec, с async и asyncRewake), http (POST, с интерполяцией заголовков allowedEnvVars), mcp_tool (вызов инструмента на уже подключённом сервере), prompt (однооборотная оценка моделью, плейсхолдер $ARGUMENTS, по умолчанию 30 секунд) и agent (порождает сабагента; экспериментально).

Таймауты по умолчанию: 600 секунд для command, http и mcp_tool — 30 секунд под UserPromptSubmit, 10 под MessageDisplay; 30 для prompt и 60 для agent. Хуки SessionEnd делят бюджет в 1,5 секунды.

17.3 Модель угроз

Хук — исполняемый код, запускаемый автоматически. Создавайте их из проверенных скриптов в репозитории, а не вставляйте из непроверенных источников; помните, что хуки из файлов настроек подчиняются доверию к рабочему пространству, а скилл может зарегистрировать хук, живущий до конца сессии.

18.2 Шлюз установки

Перед добавлением маркетплейса или плагина:

  1. Подтвердить точного издателя и репозиторий.
  2. Прочитать манифест и сверить каждый компонент с таблицей выше.
  3. Просмотреть хуки, исполняемые файлы, установочные скрипты, MCP-адреса, мониторы и выдачи инструментов.
  4. Поискать сетевые вызовы, чтение учётных данных, persistence и автообновления.
  5. Закрепить проверенную версию. Плагин без поля version берёт версию из цепочки запасных вариантов, а источник типа command обновляется в обход версионного шлюза.
  6. Проверить в изолированном профиле через --plugin-dir.
  7. Измерить влияние на контекст и расход.
  8. Записать владельца, назначение, версию, дату одобрения и процедуру удаления.

Anthropic ведёт два публичных маркетплейса: claude-plugins-official (курируется Anthropic, регистрируется автоматически при первом интерактивном запуске) и claude-community (сторонние заявки после ревью и автоматического скрининга; одобренные закрепляются на коммит SHA). Ни один из них не является гарантией.

CAUTION. Официальная документация утверждает, что плагины и маркетплейсы могут выполнять произвольный код с вашими пользовательскими привилегиями. «Установлено» означает «доверено к выполнению», а не «видно в меню». Заблуждение M18.

18.3 Собрать вместо того, чтобы принести

Если из большого плагина нужна одна процедура, написать маленький локальный скилл по её идее обычно безопаснее и проще, чем импортировать непрозрачный код и неиспользуемые коннекторы. Сохраняйте лицензии и указание авторства при адаптации чужого материала.

Часть V — Браузер, автономия и оркестрация

Организующий вопрос этой части — не «может ли оно это сделать», а «как я узнаю, что оно сделало».

Глава 20. Безопасно использовать Claude in Chrome

Claude открывает вкладки для браузерных задач и делит состояние входа вашего браузера — то есть может дотянуться до любого сайта, где вы уже авторизованы. Это и функция, и риск в одном предложении.

20.1 Предпосылки и подключение

Нужен Chrome, Edge или другой Chromium-браузер, расширение Claude in Chrome версии 1.0.36+ и прямой план Anthropic — Pro, Max, Team или Enterprise. Два ограничения регулярно застают врасплох: WSL не поддерживается, и сессии с API-ключом или долгоживущим токеном не могут пользоваться интеграцией вовсе, даже с --chrome, потому что расширение не аутентифицируется такими учётными данными.

claude --chrome     # включить на запуск
/chrome             # статус, разрешения, переподключение, выбор браузера

Интеграция работает, когда панель показывает Status: Enabled и Extension: Installed.

PRACTITIONER NOTE. Включение Chrome по умолчанию грузит браузерные инструменты в каждую сессию и увеличивает расход контекста. Предпочитайте --chrome тогда, когда он нужен.

20.2 Выделенный профиль браузера

Заведите профиль для агентной работы: только нужные задаче аккаунты; никакого разблокированного менеджера паролей; никаких посторонних вкладок; ограниченные разрешения сайтов; по возможности тестовые, а не боевые аккаунты; загрузки — в контролируемую папку. Окно инкогнито не является изоляцией аккаунта, если расширение и состояние входа по-прежнему доступны.

20.3 Повышать возможности ступенями

  1. Наблюдать — «Опиши эту страницу, ничего не делай».
  2. Навигировать — «Открой страницу настроек, ничего не меняй».
  3. Заполнить — «Заполни форму, но не отправляй».
  4. Проверить — «Покажи введённые значения и состояние валидации».
  5. Действовать — финальную отправку одобряет человек.

В режиме плана эта лестница обеспечивается за вас: браузерные вызовы только на чтение (read_page, get_page_text, find, чтение сообщений консоли и сетевых запросов, снимок экрана) идут без запроса, а клики, ввод, навигация, управление вкладками и запись GIF требуют одобрения. Вызов, в остальном читающий, всё равно спросит, если выставляет флаг, меняющий состояние, — например save_to_disk у снимка экрана; а browser_batch идёт без запроса, только если все действия внутри читающие.

20.4 Что браузер может выполнить

У загрузки файлов три ограничения: Claude может загрузить файл, только если сессии позволено его читать (поэтому deny-правило Read блокирует и загрузку); один аплоад ограничен 10 МБ суммарно; файлы с несколькими жёсткими ссылками отвергаются — частый случай внутри node_modules.

CAUTION. Снимки экрана, записи GIF, загрузки и текст страницы могут содержать чувствительную информацию, а запись фиксирует всё видимое на странице, где вы авторизованы. Эти артефакты попадают в транскрипт сессии или в файловую систему. Просматривайте их до того, как делиться.

20.5 Инъекция промпта и действие под аутентификацией

Веб-страница — недоверенный ввод. Текст на странице может велеть агенту бросить вашу задачу, раскрыть данные или уйти в другое место; это канонический канал непрямой инъекции промпта. Держите цель и разрешённые домены явными, ограничивайте сетевой доступ и требуйте подтверждения перед любой внешней записью.

CAUTION. Не используйте автоматизацию браузера для финансовых переводов, необратимых операций с аккаунтом, юридического акцепта или управления, критичного для безопасности, без специально построенной системы и независимого пути подтверждения человеком.

20.6 Computer use

Там, где задачу нельзя сделать в браузере, computer use позволяет Claude открывать приложения, кликать, печатать и видеть экран на macOS из CLI. Дисциплина та же, радиус поражения шире: профиль браузера изолировать можно, сессию рабочего стола — как правило, нет.

Глава 21. Держать работу в движении: цели

/goal задаёт условие завершения. После каждого хода небольшая быстрая модель проверяет, выполняется ли условие; если нет — Claude начинает следующий ход вместо того, чтобы вернуть управление вам. Одна цель активна на сессию, условие — до 4 000 символов.

/goal <условие>   # задать; ход начинается сразу
/goal             # статус: условие, длительность, ходы, расход токенов, причина
/goal clear       # снять (псевдонимы: stop, off, reset, none, cancel)

21.1 Что оценщик видит, а что нет

Оценщик не выполняет команд и не читает файлов. Он судит только по тому, что Claude вывел в разговор.

Этот единственный факт определяет, как выглядит хорошее условие. «Все тесты в test/auth проходят» работает, потому что Claude запускает тесты и их вывод попадает в транскрипт, где оценщик может его прочесть. «Закончи проект» не работает, потому что удовлетворяется простым утверждением.

Вердикта три: ещё не выполнено (Claude продолжает, принимая причину как указание), выполнено (цель снята, записано достижение) и невозможно (цель снята, записан провал с причиной). Ctrl+O показывает причину вердикта.

/goal реализован как Stop-хук на основе промпта, отсюда два следствия: он недоступен, когда disableAllHooks истинно после применения приоритета настроек или когда в управляемых настройках задано allowManagedHooksOnly; и он подчиняется тому же правилу доверия к рабочему пространству, что и хуки.

21.2 Анатомия безопасной цели

Включайте: конкретный результат; требуемые проверки; свидетельство, которое надо доложить; явные исключения; шлюзы человека; ограничение по ходам, времени или ресурсам; условие остановки при блокировке.

/goal Создай drafts/brief-v2.md из утверждённых источников. Цель считается
выполненной, только когда у каждого существенного утверждения есть строка
реестра источников, сабагент evidence-reviewer не сообщает ни одного
неподтверждённого утверждения высокой серьёзности, локальная проверка ссылок

пушь, не устанавливай ПО и не обращайся к аккаунтам. Остановись и спроси при
блокировке или после 20 ходов.

21.3 Какого поведения ожидать

  • Цель не меняет ваш режим разрешений. В ручном режиме Claude по-прежнему спрашивает перед вызовами, которых не допускают настройки. Чтобы ходы цели шли без присмотра, сочетайте её с авторежимом — осознанно и с песочницей.
  • Фоновая работа откладывает оценку. Если к концу хода ещё работает сабагент или фоновая команда, оценка пропускается до хода, завершившегося при отсутствии работающих задач.
  • Проверки связи отступают по экспоненте. Когда фоновая работа продержала цель в ожидании 30 минут, Claude Code выдаёт check-in; последующие удваивают интервал до четырёхкратного. CLAUDE_CODE_GOAL_CHECKIN_MINUTES меняет это, 0 — выключает.
  • Есть защита от отсутствия прогресса. Если Claude раз за разом отвечает оценщику без использования инструментов, Claude Code останавливает цикл, предупреждает и возвращает управление, оставив цель заданной.
  • Четыре отказа снимают цель: сбой аутентификации там, где Claude Code сам управляет учётными данными; исчерпанный баланс; переполнение контекста, которое автосжатие не смогло разгрести; недоступная модель. Временные ошибки вроде лимита частоты цель не снимают.
  • Цели переживают возобновление со сбросом счётчика ходов, таймера и базовой отметки токенов.

21.4 Настоящий множитель — контекст

Долго работающий агент работает не потому, что /goal волшебен, а потому что сочетает детальное предложение, документацию инструментов, освоенные процедуры, план, тесты и измеримое конечное состояние. Цель не может починить недостающие входные данные и не может сделать небезопасный доступ безопасным.

Глава 22. Динамические воркфлоу и ultracode

Динамический воркфлоу — JavaScript-скрипт, оркестрирующий сабагентов в масштабе. Claude пишет скрипт под описанную вами задачу, а среда выполняет его в фоне, пока ваша сессия остаётся отзывчивой. Требуется 2.1.154+; включается в /config.

Различие, которое здесь важно, — у кого план. С сабагентами, скиллами и командами агентов Claude решает ход за ходом, кого породить следующим, и каждый результат попадает в окно контекста. Скрипт воркфлоу держит цикл, ветвление и промежуточные результаты, поэтому в контексте Claude оказывается только итоговый ответ.

22.1 Точки входа

/deep-research <вопрос>   # встроенный воркфлоу: веерный поиск, перекрёстная
                          # проверка, отчёт со ссылками
/workflows                # просмотр прогресса
/effort ultracode         # усилие xhigh плюс автоматическая оркестрация
claude --effort ultracode # требуется 2.1.203+

Ключевое слово ultracode в промпте, который вы набрали сами, подключает одну задачу, не меняя усилия сессии. Это опт-ин только в набранном вами промпте: оно не запускает воркфлоу из -p, из сообщения SDK, не помеченного как человеческий ввод, из промпта задачи по расписанию, из вебхука или из ретранслированного в разговор комментария к pull request.

22.3 Семантика возобновления и почему она важна для стоимости

Возобновление работает только в пределах той же сессии. Повтор следует порядку старта агентов: кешированные результаты обрываются на первом агенте, который не завершился, и каждый агент, стартовавший после него, выполняется заново — даже если успел завершиться. Поэтому остановка посреди веера дорога, а воркфлоу, раскладывающий работу на много мелких агентов, сохраняет больше прогресса, чем тот, что состоит из нескольких длинных. Выход из Claude Code во время прогона означает, что следующая сессия начнёт его с нуля.

22.4 Когда воркфлоу окупается

Когда у задачи есть действительно независимые полосы: несколько семейств источников, исследуемых параллельно; несколько ревьюеров, независимо проверяющих одно предложение; крупное изменение, делимое по непересекающимся зонам ответственности; исследование, оспаривание и синтез, выигрывающие от раздельных контекстов.

Глава 23. Планирование в пределах сессии: /loop

/loop — встроенный скилл (псевдоним /proactive), перезапускающий промпт, пока сессия открыта. Это не cron.

23.1 Три формы, три поведения

Что вы даётеПримерЧто происходит
Интервал и промпт/loop 5m проверь деплойРаботает по фиксированному cron-расписанию
Только промпт/loop проверь деплойРаботает с интервалом, который Claude выбирает каждую итерацию, от минуты до часа, печатая задержку и причину

CAUTION — M01. Голый /loop не перечисляет ваши задачи по расписанию. Он запускает автономный цикл обслуживания: продолжает незавершённую работу, ухаживает за pull request текущей ветки — комментарии ревью, упавший CI, конфликты слияния — и выполняет проходы уборки, когда больше ничего не ожидает. Claude не начинает новых инициатив вне этой области, а необратимые действия идут, только если продолжают то, что транскрипт уже санкционировал, — но это всё равно автономное выполнение, о котором вы не просили. Для списка задач спросите словами или используйте CronList.

Заменить встроенный промпт можно, создав .claude/loop.md (проект, имеет приоритет) или ~/.claude/loop.md (пользователь).

23.2 Операционные ограничения

  • Claude Code должен работать и простаивать. Запланированный промпт срабатывает между ходами, никогда посреди ответа.
  • Минимальный интервал — одна минута. Единицы s, m, h, d.
  • Джиттер специфицирован, а не случаен. Повторяющиеся задачи срабатывают с задержкой до 30 минут — или до половины интервала для задач чаще часа, — а одноразовые, запланированные на :00 или :30, могут сработать на 90 секунд раньше. Смещение выводится из идентификатора задачи, поэтому оно стабильно. Средство: планируйте на минуту, отличную от :00 и :30, например 3 9 . Заблуждение M05.*
  • Нет догона. Задача, чьё время прошло, пока Claude был занят, срабатывает один раз при переходе в простой, а не по разу на каждый пропущенный интервал.
  • Истечение через семь дней с момента создания, с одним финальным срабатыванием.
  • Пятьдесят задач на сессию.
  • Время интерпретируется в вашем локальном часовом поясе.

23.3 Жизненный цикл: что на самом деле останавливает цикл

«В пределах сессии» не значит «привязано к сессии»:

  • Esc, пока /loop ждёт, снимает ожидающее пробуждение. Задачи, назначенные прямой просьбой к Claude, это не затрагивает.
  • Уход сессии в фон уносит задачи /loop в фоновую сессию, которая продолжает работать без терминала.
  • /clear очищает все задачи уровня сессии.
  • claude --resume или --continue восстанавливает неистёкшие повторяющиеся задачи и одноразовые, чьё время не прошло. Фоновые Bash-задачи и мониторы не восстанавливаются никогда. Заблуждение M02.

Под капотом используются CronCreate, CronList и CronDelete, принимающие стандартные пятипольные cron-выражения; расширенный синтаксис (L, W, ?, именованные псевдонимы) не поддерживается. CLAUDE_CODE_DISABLE_CRON=1 отключает планировщик целиком.

При срабатывании выполняются только те скиллы, которые Claude вправе вызывать сам. Встроенные команды, скиллы с disable-model-invocation: true, скиллы, придержанные через skillOverrides или deny-правило Skill, и промпты MCP приходят простым текстом.

23.4 Альтернатива: Monitor

Когда вы просите динамическое расписание /loop, Claude может вместо этого использовать инструмент Monitor: он запускает фоновый скрипт и передаёт каждую строку вывода обратно, вовсе избегая опроса. Обычно это экономнее по токенам и отзывчивее. Если вы ловите себя на опросе лога, сборки или очереди — просите монитор, а не цикл.

23.5 Подходящее и неподходящее

Подходит: проверка долгой сборки; перезапуск локальной проверки только на чтение; напоминание активной сессии осмотреть очередь; доклад о некритичном состоянии в присутствии человека.

Не подходит: всё, где есть обязательства по уровню сервиса; мониторинг безопасности, медицинский или аварийный; платежи и торговля; всё, что требует точного времени или догона; неприсмотренный разрушительный ремонт.

Всегда указывайте, что делать, когда условие отсутствует, неоднозначно или небезопасно. «Только доложить» — хорошее значение по умолчанию.

24.1 Что такое рутина на самом деле

Рутины в статусе research preview. Поведение, лимиты и поверхность API могут измениться.

Рутина — сохранённая конфигурация (промпт, один или несколько репозиториев, среда и набор коннекторов) с одним или несколькими прикреплёнными триггерами:

  • По расписанию — ежечасно, ежедневно, по будням, еженедельно либо один будущий момент времени.
  • API — HTTP POST на эндпойнт /fire конкретной рутины с bearer-токеном.
  • GitHub — события pull request и релизов, с фильтрами по автору, заголовку, телу, базовой и головной ветке, меткам, черновому состоянию и факту слияния.

Одна рутина может сочетать все три. Заблуждение M19: рутины широко описывают как сессии по расписанию — это треть функции.

Создаются на claude.ai/code/routines, в боковой панели Routines десктопного приложения (выбирая Cloud, а не Local) либо из CLI через /schedule (псевдоним /routines), поддерживающий также /schedule list, /schedule update и /schedule run. Выражения чаще ежечасных отвергаются.

24.2 Почему рутина заслуживает проектного ревью

Прогоны рутин автономны. Нет ни выбора режима разрешений, ни запросов одобрения.

Четыре следствия, и все четыре легко упустить:

  1. Все ваши подключённые коннекторы включены по умолчанию. Claude может пользоваться каждым инструментом включённого коннектора, включая запись, не спрашивая. Уберите всё, что рутине не нужно.
  2. Она действует от вашего имени. Коммиты и pull request несут вашего пользователя GitHub; сообщения Slack, тикеты и прочие действия коннекторов идут через ваши привязанные аккаунты.
  3. Защита веток частична. Claude пушит в ветки с префиксом claude/, которые принимаются всегда. Push в другую ветку отвергается, если она защищена, если у кого-то есть открытый pull request из неё или если она несёт коммиты другого автора.
  4. Переменные окружения видны всем, кто пользуется средой. Соразмеряйте область действия учётных данных.

24.3 Текст полезной нагрузки срабатывания недоверен по замыслу

Текст, пришедший с триггером — тело вебхука, комментарий к pull request, — это недоверенный ввод, а не инструкция от вас. Обращайтесь с ним как с данными.

24.4 Прежде чем активировать

CAUTION — M20. Зелёный статус прогона означает, что сессия стартовала и завершилась без инфраструктурной ошибки. Заблокированные запросы, отсутствующие инструменты коннектора и провалы самой задачи видны только в транскрипте. Читайте транскрипт, а не индикатор.

Часть VI — Распределённая и облачная работа

Глава 25. Продолжить локальную работу через Remote Control

Remote Control позволяет другому устройству, где вы вошли в аккаунт, наблюдать за процессом Claude Code, работающим на вашей машине.

Выполнение остаётся локальным. Код, файлы и команды никогда не покидают ваш компьютер. Путешествует разговор: он ретранслируется через API Anthropic по TLS и хранится на серверах Anthropic, пока соединение активно, чтобы синхронизироваться между устройствами. Это заблуждение M21 — и причина, по которой Remote Control отключён при Zero Data Retention.

/remote-control                            # псевдоним /rc
claude --remote-control research-brief     # псевдоним --rc
claude remote-control                      # серверный режим

Соединение использует несколько короткоживущих учётных данных с узкой областью, каждое ограничено своей целью и истекает независимо, чтобы сузить радиус поражения при компрометации любого из них.

Правила работы

  • Начинать с узкого каталога проекта, никогда с домашнего.
  • Сохранять обычный режим разрешений и песочницу. Удалённость — не повод расширять доступ.
  • Именовать сессии внятно, чтобы с телефона нельзя было спутать два проекта.

Глава 26. Облачные сессии, --cloud и --teleport

Claude Code в вебе — research preview для Pro, Max и Team, а также для Enterprise с соответствующими местами.

Облачная сессия работает на инфраструктуре Anthropic на claude.ai/code либо в самостоятельно размещённой среде вашей организации. Сессии сохраняются при закрытии браузера и наблюдаются из мобильного приложения.

Это другой механизм, чем Remote Control, и путаница между ними — самая частая ошибка в этой области. --cloud создаёт облачную сессию, которая работает где-то ещё; --remote-control выставляет локальную сессию для наблюдения.

26.1 Из терминала в облако

claude --cloud "Fix the authentication bug in src/auth/login.ts"

Облачная ВМ клонирует GitHub-remote текущего каталога на текущей ветке, а не ваш локальный checkout — сначала сделайте push, если у вас есть локальные коммиты. Один репозиторий за раз. Из репозитория, не связанного с GitHub, Claude Code упаковывает локальный репозиторий и загружает его: полная история по веткам плюс незакоммиченные изменения отслеживаемых файлов, до 100 МБ, неотслеживаемые файлы исключены, и без возможности запушить обратно, если не настроена аутентификация GitHub.

Отправить сообщение в идущую облачную сессию с любой машины, где вы вошли:

claude -p "ваше сообщение" --cloud <session-id>   # поставить в очередь и выйти
claude --cloud <session-id>                       # подключиться интерактивно

26.2 Доступ к GitHub и что он на самом деле даёт

Проверяйте, какие репозитории доступны сессии и с какими правами. Push в ветки с префиксом claude/ принимается всегда; прочие подчиняются защите веток.

Глава 27. Проталкивать события в сессию через каналы

Каналы — research preview. Требуют аутентификации Anthropic через claude.ai или ключ Console API; недоступны на Amazon Bedrock, Google Cloud Agent Platform и Microsoft Foundry. Организациям Team и Enterprise нужно включить их явно.

Канал — это MCP-сервер, который проталкивает события в идущую сессию, вместо того чтобы ждать запроса. Если обычный коннектор даёт Claude доступ к системе по требованию, то канал позволяет системе дотянуться до уже открытой у вас сессии — упавший CI, алерт мониторинга, сообщение в чате — пока Claude ещё держит ваши файлы открытыми и помнит, что вы отлаживали.

События приходят, только пока сессия открыта, поэтому постоянная схема означает фоновый процесс или постоянный терминал.

Каналы устанавливаются как плагины и требуют Bun. В превью входят Telegram, Discord и iMessage, плюс fakechat как локальная демонстрация.

CAUTION. Содержимое события — недоверенный ввод. Сообщение из чата или тело вебхука не являются инструкцией от вас; это данные.

Глава 28. Публиковать работу как артефакты

Артефакт — опубликованная страница (.html, .htm или .md, не больше 16 МиБ, одна страница; относительные ссылки не разрешаются — используйте якоря).

28.1 Кто что видит

Новый артефакт виден только вам. На планах Team и Enterprise можно дать доступ конкретным людям или всей организации и назначить редактора, который вправе публиковать новые версии. На Pro и Max единственный вариант, которым можно поделиться, — публичная ссылка, открытая любому в интернете без входа; на Team и Enterprise публичный доступ выключен, пока владелец не включит External sharing.

Каждая публикация становится версией, и элемент управления Share выбирает, какую версию видят зрители. Зрители из организации видят ваше имя; зритель, открывающий публичную ссылку извне организации, видит пометку о том, что содержимое создано пользователем и не проверено.

28.2 Живые данные через коннекторы

Страница может вызывать MCP-коннекторы при каждом просмотре, показывая текущие данные, а не снимок (2.1.209+). Claude объявляет, какие коннекторы странице позволено вызывать, и других она вызвать не может. Важна модель доступа:

  • Каждый зритель использует свои коннекторы. Вызовы идут через подключения просматривающего аккаунта, поэтому двое, открывшие один дашборд, могут увидеть разные данные. Страница никогда не видит чужих учётных данных.
  • Зрители сперва одобряют доступ, и отказ действует на эту загрузку страницы.
  • Действия тоже идут от аккаунта зрителя. Элемент управления, который отправляет сообщение или обновляет задачу, действует от имени того, кто нажал.

Артефакт, вызывающий коннекторы, нельзя опубликовать по публичной ссылке ни на одном плане. Просите Claude добавлять в каждый живой раздел запасное сообщение с названием нужного коннектора, чтобы зритель без подключения видел, что подключить, а не пустую панель.

Часть VII — Работа в масштабе

Глава 29. Параллельные сессии без коллизий

29.1 Предотвращать коллизии файлов

Основной механизм — git worktree: отдельный рабочий каталог на ветку, поэтому две сессии не пишут в одни и те же файлы.

Взаимодействие с хуками: ${CLAUDE_PROJECT_DIR} остаётся в корне проекта внутри worktree, тогда как cwd во входных данных хука показывает путь worktree, — скрипт хука обязан решить, что из этого он имеет в виду.

29.2 Обмен сообщениями между сессиями

Claude может перечислять и слать сообщения вашим другим сессиям на этой машине, а также доставать сессии на других машинах и в вебе. /list-agents (псевдоним /peers) их перечисляет.

CAUTION. Входящему сообщению сообщается, что оно пришло от другой сессии Claude, а не от вас. Сессия-равный не может одобрить запрос разрешения или дать согласие от вашего имени, и сессия, которой действие запретили, не может ретранслировать его другой сессии в обход проверки. В авторежиме классификатор считает ретранслированное заявление об одобрении недоверенным вводом и проверяет каждое сообщение перед доставкой. Считайте сообщения координационным вводом, но никогда — привилегированным управлением.

29.3 Беречь собственное внимание

  • Держать не больше двух-трёх интерактивных сессий, пока не узнаете свой предел.
  • Уводить в фон всё, что не требует частых решений.
  • Именовать сессии по результату.
  • Вести маленькую сводку: владелец, ветка, задача, статус, следующее решение человека.
  • Группировать ревью, а не проверять каждую минуту.
  • Перестать начинать новую работу, когда узким местом становится интеграция. Это и есть настоящий потолок, и он наступает раньше лимита токенов.

Глава 30. Команды агентов

30.1 Ограничения, которые стоит заложить в план

/resume и /rewind не восстанавливают внутрипроцессных участников команды, и ведущий может пытаться писать тем, кого уже нет; статус задач может отставать, блокируя зависимые; выключение ждёт текущего вызова инструмента; на сессию ровно одна команда, вложенных команд нет; ведущий фиксирован на всё время жизни сессии; собственные сабагенты внутрипроцессного участника работают на переднем плане, поэтому определение с background: true вернёт ошибку.

Начинайте с трёх-пяти участников. Стоимость в токенах растёт линейно с числом участников, накладные расходы на координацию — хуже, и три сфокусированных участника регулярно обходят пятерых разбросанных.

30.2 Когда команда лучше альтернатив

Команда — когда участникам нужно делиться находками и оспаривать друг друга: параллельное ревью с разными оптиками, конкурирующие гипотезы в отладочном расследовании, работа поперёк слоёв с ясными зонами ответственности.

  • Сабагенты — когда важен только результат.
  • Воркфлоу — когда повторяемой должна быть сама оркестрация.
  • Worktree — когда вопрос в изоляции файлов, а не в рассуждении.

Окупается прежде всего состязательный шаблон:

Пользователи сообщают, что приложение завершается после одного сообщения
вместо того, чтобы держать соединение. Породи пять участников для проверки
разных гипотез. Пусть они переписываются, пытаясь опровергнуть теории друг
друга, как в научном споре. Обнови документ с находками достигнутым
консенсусом и запиши, какие теории были отброшены и на основании какого
свидетельства.

Последовательное расследование закрепляется на первом правдоподобном объяснении. Независимые исследователи, активно пытающиеся друг друга опровергнуть, дают уцелевшую теорию, которая гораздо вероятнее является настоящей причиной.

30.3 Разрешения

bypassPermissions у ведущего распространяется на участников, и они не могут от него отказаться. Это одна из причин, по которой этот режим уместен только в изолированной одноразовой среде.

Глава 31. Корпоративная конфигурация и управляемая политика

Организация, записавшая свои стандарты в CLAUDE.md, задокументировала намерение. Организация, записавшая их в управляемые настройки, развернула механизм контроля. Управляемые настройки — единственный уровень, который пользователь не может снять, и они не переопределяются ничем, включая аргументы командной строки.

31.1 Правило приоритета, удивляющее администраторов

CAUTION. Когда политику доставляет больше одного управляемого источника, Claude Code использует первый источник, доставивший хотя бы один ключ политики, и игнорирует остальные. Он их не сливает и не показывает предупреждения о пропущенных источниках.

Порядок: удалённые настройки → MDM или политика ОС → файлы управляемых настроек → HKCU. Небольшое число межисточниковых ключей читается из каждого административного источника: замки песочницы, allowAllClaudeAiMcps, forceRemoteSettingsRefresh и — с 2.1.223 — env, сливаемый по переменным.

/status на машине показывает, какой источник выбран на самом деле.

Облачные сессии вообще не читают MDM-профиль устройства: политика для сессии, размещённой у Anthropic, должна приходить из управляемых настроек на сервере.

31.2 Минимально жизнеспособная корпоративная политика

{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Read(~/.ssh/**)",
      "Read(~/.aws/**)"
    ],
    "disableBypassPermissionsMode": "disable"
  },
  "allowManagedPermissionRulesOnly": true,
  "allowManagedHooksOnly": true,
  "allowManagedMcpServersOnly": true,
  "sandbox": {
    "enabled": true,
    "network": { "allowManagedDomainsOnly": true },
    "credentials": {
      "files":   [{ "path": "~/.aws/credentials", "mode": "deny" }],
      "envVars": [{ "name": "GITHUB_TOKEN", "mode": "deny" }]
    }
  },
  "strictKnownMarketplaces": true,
  "disableSideloadFlags": true
}

31.3 Чего управляемая политика не достаёт

Она не делает недоверенный ввод доверенным, не проверяет сторонний код за вас и не превращает отчёт агента в свидетельство.

Глава 33. Наблюдаемость, контроль расходов и доступность

33.1 OpenTelemetry

Claude Code экспортирует метрики, логи и — в бете — трассы через OpenTelemetry. Это тот механизм, который превращает «мы используем ИИ-агента» в нечто, что функция контроля может изучить.

export CLAUDE_CODE_ENABLE_TELEMETRY=1
export OTEL_METRICS_EXPORTER=otlp          # otlp | prometheus | console | none
export OTEL_LOGS_EXPORTER=otlp             # otlp | console | none
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc    # grpc | http/json | http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://collector.example.com:4317
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer <token>"

Разворачивайте это на весь парк через блок env управляемых настроек.

Экспортируются решения по разрешениям, смены режима, подключения коннекторов, загрузки плагинов, события аутентификации и отказы модели, и каждое событие несёт идентификатор промпта, восстанавливающий всю активность одной инструкции.

Организация, включившая это, может ответить аудитору. Организация, не включившая, — не может.

  3. Добавить правило с областью по путям для sources/**, запрещающее изменение.
  4. Добавить templates/claim-ledger.md и templates/brief.md.
  5. Осмотреть авто-память через /memory и убрать неточное и чрезмерно обобщённое.

Свидетельство: /context показывает ожидаемые файлы инструкций и никаких других; инструкции не противоречат друг другу.

Стадия 3 — Выбрать регистр

Создать стиль вывода «Аналитик свидетельств» и выбрать его через /config. Начать новую сессию, чтобы системный промпт пересобрался.

Свидетельство: первый ответ новой сессии различает утверждение источника и собственный вывод без отдельной просьбы.

Стадия 4 — Сделать переиспользуемую процедуру

  1. Выполнить один бриф вручную, вместе с Claude.
  2. Создать скилл research-brief из наблюдённой процедуры.
  3. Прочитать каждый файл и каждую выдачу инструмента. Свести allowed-tools к минимуму.
  4. Проверить на действительно другом наборе источников.

Свидетельство: второй прогон соблюдает тот же контракт вывода, не перенося тематических допущений из первого.

Стадия 5 — Добавить независимого ревьюера

  1. Создать сабагента evidence-reviewer только на чтение.
  2. Убедиться, что это не форк. Режим форка — умолчание в интерактивных сессиях: вызовите агента по имени и по его первому выводу проверьте, что он не знает о черновом разговоре.
  3. Убедиться, что родительская сессия не в acceptEdits, bypassPermissions или auto — каждый из них перебивает permissionMode ревьюера. На планах Pro, Max и Team сессия стартует именно в auto, поэтому это не формальность.

Свидетельство: ревьюер называет утверждения, которые вы намеренно оставили неподтверждёнными.

Стадия 6 — Добавить ровно один элемент ограниченной автоматизации

Один хук, один монитор или одна цель — не три сразу.

Стадия 7 — Отрендерить и проверить

Проверки должны действительно выполниться, а их вывод — быть осмотрен.

Стадия 8 — Человеческий шлюз выпуска

Продвижение из drafts/ в deliverables/ не может быть пройдено агентом самостоятельно.

Заключительная мысль

Внедряйте возможности с той скоростью, с какой способны подтверждать их результат, и не быстрее.

Четыре элемента брифа — Outcome, Context, Boundaries, Evidence — проходят через всю книгу: они же контракт плана (глава 6), бриф делегирования (глава 16), условие завершения (глава 21) и шлюз выпуска (глава 34). Пропущенный четвёртый элемент — это то, что превращает возможности в переделку.

Приложение L. Модель зрелости внедрения (предложение автора)

Пять уровней организационной способности, у каждого — свои принудительные контроли, требуемое свидетельство и ответственный владелец. Автор прямо оговаривает, что это его собственная конструкция, предложенная как средство упорядочивания, и она не проверялась эмпирически.

Порядок вопросов для решения — тот же, что в главе 32: режим разрешений по умолчанию и кто его меняет → принудительность песочницы → допустимые коннекторы, плагины и маркетплейсы → допустимость автономного выполнения и чьё одобрение → что покидает периметр и на каких условиях хранения → кто отвечает, когда агент действует.

Приложение K. Повторная сверка

Автор предлагает пересверять книгу ежеквартально либо перед тем, как опереться на неё в значимом решении, и записывать изменения в реестр свидетельств.

Практический минимум для читателя этого издания: перед тем как положиться на конкретное имя настройки, флаг или числовой лимит — открыть официальную документацию и сверить. Дисциплина и категории рисков из этой книги устареют нескоро; номера версий и имена ключей — быстро.
