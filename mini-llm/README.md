# mini-LLM — языковая модель с нуля на NumPy

Маленькая GPT-подобная модель, написанная целиком вручную: токенизатор,
трансформер, **обратное распространение без автодиффа**, AdamW, генерация.
Единственная зависимость — NumPy. Ни PyTorch, ни TensorFlow, ни GPU.

Смысл проекта — не побить ChatGPT, а показать, что «магия» LLM умещается
в ~700 строк понятного кода: та же архитектура, что у GPT-2, только в
миллион раз меньше параметров.

```
данные ─► токенизатор ─► [ трансформер ] ─► вероятности следующего токена ─► сэмплирование
                              ▲                        │
                              └──── AdamW ◄─ градиенты ─┘
```

## Быстрый старт

```bash
cd mini-llm
pip install -r requirements.txt          # только numpy

python3 tests/test_grad.py               # проверка: градиенты верны (~10 с)
python3 data/make_corpus.py              # сгенерировать корпус (уже лежит в data/)
python3 train.py --steps 900 --tokenizer bpe --out runs/my-run
python3 generate.py --run runs/my-run --prompt "Егор и Диана" --temperature 0.7
```

Обучение на 4 CPU занимает порядка 10–20 минут для конфигурации по умолчанию.
Чтобы просто проверить, что всё живо, хватит `--steps 100` (около минуты).

| Файл | Что делает |

| `generate.py` | Генерация из сохранённой модели |

## Как устроена модель

Архитектура — уменьшенный GPT-2 (pre-LayerNorm):

```
токены ─► эмбеддинг токенов + эмбеддинг позиций
        ─► [ блок ] × n_layer
        ─► финальный LayerNorm
        ─► логиты = скрытое состояние × эмбеддингᵀ   (weight tying)
```

Один блок:

```
x ──┬──► LayerNorm ──► causal self-attention ──┐
    └──────────────────────────────────────────(+)──┬──► LayerNorm ──► MLP(GELU) ──┐
                                                    └──────────────────────────────(+)──► x
```

Ключевые детали, которые обычно прячет фреймворк:

- **Causal-маска.** Токен видит только себя и прошлое. В коде это
  `np.where(mask, att, -1e9)` перед softmax; тест `check_causality`
  проверяет, что будущее действительно не протекает в прошлое.
- **Multi-head attention** — это один большой матмул `x @ W_qkv`, который
  затем «нарезается» на головы через reshape/transpose. Головы — не разные
  слои, а разные подпространства одного и того же вектора.
- **Weight tying.** Выходного слоя нет: логиты считаются умножением на
  транспонированную матрицу эмбеддингов. Экономит `vocab × n_embd` параметров
  и обычно улучшает качество маленьких моделей.
- **Residual + pre-LN.** Именно остаточные связи позволяют градиенту дойти
  до нижних слоёв; в коде это видно буквально — `dx` складывается из двух
  путей (в обход и через ветку).
- **Инициализация проекций** внутри residual делится на `sqrt(2·n_layer)` —
  трюк из GPT-2, без него глубокая сеть стартует со слишком большой дисперсией.

## Почему можно верить рукописному backprop

Потому что он сверен с численной производной:

```
df/dw ≈ (f(w + ε) − f(w − ε)) / 2ε
```

`tests/test_grad.py` в режиме float64 проверяет выборку из **каждого**
параметра модели. Худшее расхождение — порядка 1e-4 относительной ошибки на
заметных градиентах, то есть на уровне шума самих конечных разностей.
Дополнительно тест проверяет: round-trip токенизаторов, отсутствие утечки
будущего через маску и способность модели выучить одну последовательность
наизусть (loss < 0.02 за 300 шагов).

Если вы правите `model.py` — запускайте этот тест. Он ловит ошибки в
backward, которые иначе выглядят просто как «модель почему-то плохо учится».

## Токенизаторы

| | `--tokenizer char` | `--tokenizer bpe` |
| --- | --- | --- |
| Словарь | все символы корпуса (~60) | 256 байтов + слияния (`--vocab-size`) |
| Длина текста | 1 токен = 1 символ | примерно в 2,2 раза короче |
| Обучение | мгновенно | доли секунды на 400 КБ |
| Незнакомые символы | отбрасываются | кодируются всегда (работает с байтами) |

BPE выгоднее: при том же `block_size` модель видит вдвое больше текста.
Побочный эффект байтового уровня — отдельный токен может быть «половиной»
буквы, поэтому декодирование одного токена иногда даёт `�`; на целой
последовательности текст собирается точно.

## Параметры обучения

```bash
python3 train.py \
  --data data/corpus.txt \
  --tokenizer bpe --vocab-size 512 \
  --block-size 64 \          # длина контекста в токенах
  --n-layer 3 --n-head 4 --n-embd 128 \
  --batch-size 32 --steps 900 \
  --lr 3e-3 --warmup 100 --grad-clip 1.0 \
  --dropout 0.0 \
  --out runs/bpe-demo
```

Как читать лог:

```
шаг   250/900 | loss 1.4231 (сглаж. 1.4815) | lr 2.71e-03 | |g| 0.53 | 2100 ток/с | осталось ~630 с
  -> val loss 1.3902 | перплексия 4.02 (сохранено)
```

- **loss** — кросс-энтропия в натах. Стартует около `ln(размер словаря)`
  (для словаря 512 это ≈ 6,2) — это уровень «модель угадывает наугад».
- **перплексия** = `exp(loss)`: «из скольких вариантов модель фактически
  выбирает». 4,0 значит, что неопределённость упала с 512 до четырёх.
- **|g|** — норма градиента до обрезки. Если она постоянно упирается в
  `--grad-clip`, снизьте `--lr`.
- Чекпоинт сохраняется только когда val loss улучшился, так что в `--out`
  всегда лежит лучшая версия, а не последняя.

Если val loss растёт, а train падает — переобучение: добавьте
`--dropout 0.1`, уменьшите модель или возьмите корпус побольше.

## Генерация

```bash
python3 generate.py --run runs/bpe-demo --prompt "Программа дня" \
                    --temperature 0.7 --top-k 40 --max-new-tokens 200 --n 3
```

- `--temperature 0` — жадный выбор, всегда один и тот же текст, быстро
  скатывается в повторы.
- `0.6–0.9` — рабочий диапазон.
- `> 1.2` — модель начинает «бредить».
- `--top-k 40` оставляет 40 лучших вариантов, `--top-p 0.9` — минимальный
  набор с суммарной вероятностью 90%. Обычно достаточно чего-то одного.

## Свой корпус

Подойдёт любой UTF-8 текстовый файл:

```bash
python3 train.py --data /путь/к/моему.txt --tokenizer bpe --out runs/mine
```

Ориентиры: от 100 КБ текста модель начинает выдавать правдоподобные слова,
от 1 МБ — правдоподобные фразы. Корпус в `data/corpus.txt` синтетический и
намеренно шаблонный (свадебные приглашения в тему этого репозитория):
на таком материале маленькая модель за минуты учится связной структуре, и
прогресс хорошо виден на глаз.

## Ограничения (честно)

- Это **тренажёр**, а не продукт: 0,7 млн параметров против сотен миллиардов
  у больших моделей. Модель продолжает текст по статистике корпуса и не
  «понимает» вопросов.
- Только CPU и только float32/float64. NumPy не даёт ни fused-ядер, ни GPU.
- Нет KV-кэша: при генерации контекст пересчитывается на каждый токен. Для
  `block_size ≤ 128` это доли миллисекунды, но на больших контекстах было бы
  узким местом.
- `--resume` продолжает обучение с сохранённых весов, но состояние AdamW
  (моменты) при этом начинается заново.
- Нет instruct-дообучения и RLHF — только предобучение на предсказание
  следующего токена.
