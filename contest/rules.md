# Правила конкурса: расхождение → судья → синтез

Не дуэль, а производственный конвейер. N строителей делают РАЗНЫЕ концепции
одного продукта, судья выбирает победителя и «трофеи» из проигравших,
синтезатор собирает финальную версию, критик доводит её итерациями.
Цель — не «обыграть соперника», а максимум пользы для заказчика.

## Фазы

**Ф0. Критерии.** Оркестратор выводит из брифа 4–6 приёмочных критериев
(К1…Кn) — конкретных и проверяемых, про ценность для заказчика, не про
абстракции. Показывает пользователю критерии и концепт-рамки; правки
пользователя — закон. Итог — `contest/criteria.md`.

**Ф1. Расхождение.** N строителей (по умолчанию 3) параллельно строят полные
версии в `contest/variants/<имя>/`. Каждому назначена СВОЯ концепт-рамка
(стилевая/структурная гипотеза) — рамки обязаны быть далёкими друг от друга,
это защита от сходимости. Строители друг друга не видят и не читают.

**Ф2. Судейство.** Судья оценивает каждую версию по каждому критерию
(0–10 + обоснование в 1–2 фразы), называет победителя по сумме и составляет
**трофейный список**: конкретные элементы проигравших версий (с путями к
файлам), которые объективно сильнее аналогов победителя и заслуживают
переноса. Итог — `contest/verdict.md`.

**Ф3. Синтез.** Синтезатор копирует победителя в `contest/final/` и
переносит трофеи. Стиль и архитектура победителя доминируют — трофеи
адаптируются под них, а не наоборот. Слепое склеивание запрещено.

**Ф4. Доводка (цикл, по умолчанию до 2 итераций).** Критик (тот же судья в
режиме ревью) проверяет `contest/final/` по критериям и выдаёт список
дефектов по убыванию важности, либо вердикт «ПРИНЯТО». Строитель-доводчик
чинит строго по списку. «ПРИНЯТО» или исчерпание итераций — конец цикла.

**Ф5. Сдача.** Оркестратор отдаёт пользователю: путь/превью финала, таблицу
оценок (до и после доводки), список перенесённых трофеев, пути к исходным
вариантам.

## Принципы (выводы из эксперимента с ареной)

- **Критерии = приёмка.** Судья меряет только по `criteria.md`; «нравится /
  не нравится» вне критериев — в комментарий, не в счёт.
- **Разнообразие принудительное.** Одинаковый бриф без разных рамок даёт
  клонов — рамки формулирует оркестратор ДО старта и следит, чтобы они
  не пересекались.
- **Никакой информационной игры.** Ни блефа, ни деклараций, ни приватных
  планов — токены идут в продукт.
- **Трофеи важнее победы.** Проигравшие версии — источник идей; вердикт без
  трофейного списка считается неполным (пустой список — только с явным
  обоснованием «переносить нечего»).
- **Анти-Гудхарт.** Судья штрафует за оптимизацию «под судью» в ущерб
  пользователю (нагромождение фич ради галочек по критериям).

## Границы

- Строитель пишет только в свою папку `contest/variants/<имя>/`;
  синтезатор и доводчик — только в `contest/final/`.
- Файлы конкурса (`criteria.md`, `verdict.md`, отчёты) ведёт оркестратор.
- Арсенал свободный: MCP, скиллы, скриншоты, тесты — всё, что подключено
  к проекту.
