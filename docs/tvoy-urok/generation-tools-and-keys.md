# «Твой урок» — инструменты, API и ключи для генерации презентаций: полный разбор

**Дата:** 23.07.2026 · **Основа:** три параллельных веб-ресёрча (рынок инструментов; технологический стек «LLM → JSON → PPTX/PDF»; РФ-доступы и ключи). Дополняет `presentation-generation-analysis.md` (архитектура) и `llm-cost-model.md` (экономика) — с **поправками** к обоим, см. раздел 6.

## 0. TL;DR

1. **Готового чужого движка брать не нужно и нельзя**: у лидеров точности (NotebookLM, Gemini-in-Slides, Copilot) нет API; у Gamma API есть, но кредиты дороги, PPTX-экспорт ненадёжен, оплата из РФ — только посредники. Ниша «точная генерация + редактируемый PPTX + рубли» открыта.
2. **Наш выбранный паттерн подтверждён рынком**: «LLM(+RAG) → структурированный JSON → детерминированный рендер python-pptx по мастер-шаблону» — это то, как устроены лучшие API-игроки (SlideSpeak — JSON-вход, open-source Presenton — HTML-шаблоны). Точность отделяется от вёрстки: факты контролирует retrieval, рендер ничего не выдумывает.
3. **Две плохие новости для экономики** (правки к `llm-cost-model.md`):
   - наценка РФ-прокси на Claude — реально **2–4×**, а не 5,5%: себестоимость текста презентации ~26–40 ₽ вместо ~13 ₽;
   - **бесплатный API Kandinsky (FusionBrain) фактически мёртв** (фримиум ~20 генераций/мес, перебои, док отдаёт 503). Картинки: YandexART ~1,5–2,2 ₽/шт (основной), Kandinsky внутри GigaChat API (fallback), self-host Kandinsky 5.0 (Apache 2.0) — стратегический вариант.
4. **Ключи, которые нужно завести** (минимальный продакшн-набор): ProxyAPI (Claude, рубли, закрывающие документы) + AITunnel (резерв), API-ключ сервисного аккаунта Yandex Cloud (YandexGPT/YandexART/эмбеддинги, folder_id), GigaChat B2B (Сбер, + сертификаты НУЦ Минцифры), опционально DeepSeek (дешёвая массовка). Секреты — в Yandex Lockbox.
5. **Технические правки к архитектуре**: autofit в python-pptx не существует — собственный измеритель текста (Pillow `getlength` по TTF); PPTX→PDF — через Gotenberg (stateful LibreOffice), а не голый `soffice` на запрос; схема дека — плоская, без `anyOf/oneOf` (иначе отвалится GigaChat-fallback); на Sonnet 5 / Opus 4.8 **не слать `temperature`/`top_p`/`budget_tokens` — это 400**.

### 1.3. Кто умеет фактическую точность (source-grounding)

Ранжирование: NotebookLM (только из источников, цитаты) → Gemini-in-Slides (грандинг в Drive-файлы) → Copilot (из Word/PDF) → SlideSpeak (JSON/док-вход) → Plus AI → Gamma (вход до 100k токенов, но без глубокого RAG). Общий вывод исследований: RAG/грандинг статистически значимо снижает галлюцинации; правильная архитектура — **разделить контент (RAG + контролируемый JSON) и вёрстку (детерминированный рендер)**. Наш пайплайн так и устроен; ни один из доступных в РФ конкурентов этого не делает.

## 2. Алгоритм генерации: подтверждённый эталон

Семишаговый пайплайн из `presentation-generation-analysis.md` (раздел 4) остаётся в силе. Уточнённая версия с учётом ресёрча:

```
POST /api/generate {type:"presentation", subject, grade, topic, wishes?, source_doc_id?}
  │
  ├─ 1. Препроцессинг: документ → текст → чанки; эмбеддинги multilingual-e5-large
  │      (локально, MIT, префиксы query:/passage:) → RAG-выборка
  ├─ 2. Сценарий: JSON-схема дека (ПЛОСКАЯ: без anyOf/oneOf, без maxLength-надежд — §3.1)
  ├─ 3. Промпт 5 слоёв, разложенный по стабильности под prompt caching (§3.5):
  │      [роль+методика | схема+темы | ФГОС-выборка | профиль класса] — кэш;
  │      [тема+wishes+SOURCE] — хвост без кэша
  ├─ 4. LLM: (а) outline → (б) контент. Основной — Claude Sonnet 5 (через ProxyAPI,
  │      structured output output_config.format / messages.parse());
  │      черновик/массовка — DeepSeek V4 Flash (JSON mode + клиентская валидация);
  │      РФ-fallback — GigaChat (schema без union'ов!)
  ├─ 5. Валидация: Pydantic по схеме → пословный линтер (лимиты слов, «ё», тире,
  │      Sentence case) → измеритель текста Pillow по TTF (§3.4) → CoVe даты/числа
  │      → LLM-судья (Haiku 4.5) → ≤3 точечных ретрая по слайдам
  ├─ 6a. Картинки: YandexART (async operations, ~1,5–2,2 ₽/шт) — основной;
  │      Kandinsky через GigaChat API — fallback; кэш по хэшу промпта; БЕЗ текста в картинках
  ├─ 6b. Рендер: python-pptx + мастер-шаблон (именованные слоты) → PPTX;
  │      PPTX → PDF: Gotenberg (stateful LibreOffice + шрифты в образе);
  │      A4-раздатка: WeasyPrint из того же JSON
  └─ 7. Сохранение → редактор → экспорт
```

Что здесь «функции и настройки» по стадиям — детально в §3; какие ключи подключать — в §4.

## 3. Строительные блоки: функции, настройки, грабли

### 3.1. Structured output по провайдерам

| Провайдер | Механизм | Гарантируется | НЕ гарантируется / грабли |
|---|---|---|---|
| **Claude** (Sonnet 5, Opus 4.8, Haiku 4.5) | `output_config: {format: {type:"json_schema", schema:{...}}}` на `messages.create()`; высокоуровнево — `client.messages.parse()` с Pydantic-моделью → `response.parsed_output`. Strict tools: `strict: true` в определении тула | валидный JSON по структуре схемы; enum, const, anyOf/allOf, $ref, форматы строк | **maxLength/minimum/maximum/рекурсия — SDK молча вырезает и валидирует на клиенте**; обрыв по max_tokens → неполный JSON; несовместимо с prefill. **`temperature`/`top_p`/`top_k`/`budget_tokens` → 400** на Sonnet 5/Opus 4.8; thinking — `{type:"adaptive"}` + `output_config.effort`. Первый запрос с новой схемой — разовая компиляция, потом 24 ч кэш схемы |
| **OpenAI** | `response_format: {type:"json_schema", json_schema:{name, schema, strict:true}}` | constrained decoding — структурно невалидный вывод невозможен | те же ограничения схемы; refusal-поле; схема ест input-токены |
| **Gemini** | `responseJsonSchema` (2.5+, полноценный JSON Schema) или `responseSchema` (OpenAPI-подмножество, важен `propertyOrdering`) | структура | большая схема «дек на 15 слайдов» → `400 InvalidArgument` без диагностики; дробить |
| **DeepSeek** | только JSON mode (`{"type":"json_object"}` + слово «json» и пример в промпте) — **json_schema-режима нет** | синтаксическая валидность | известный баг: иногда пустой content → ретрай обязателен; модели `deepseek-v4-*` (v3-алиасы отключаются 24.07.2026) |
| **GigaChat** | `response_format: json_schema` + function calling; SDK `gigachat` с Pydantic | базовая структура | **не поддерживает `anyOf`/`oneOf`/`allOf`** — полиморфный слайд через union не пройдёт. Схема дека должна быть плоской: единый объект слайда с `role`-enum и опциональными блоками (наша схема в analysis-доке уже такая — сохранить это свойство) |

**Правило пайплайна:** структуру гарантирует провайдер, значения и длины — только наш клиентский слой (Pydantic + пословный линтер + измеритель текста). Это относится ко всем провайдерам без исключений.

### 3.2. Рендер PPTX

- **python-pptx (~1.0.x)** — основной выбор: полный доступ к слайдам/плейсхолдерам/фигурам/таблицам, XML-хаки через lxml. Два жёстких ограничения:
  - **Autofit не существует.** `MSO_AUTO_SIZE.TEXT_TO_FIT_SHAPE` — лишь XML-флаг; пересчёт кегля делает только сам PowerPoint при открытии файла (issues #973, #715). Файл, идущий сразу в LibreOffice → PDF, останется с переполнением. `fit_text()` требует локальный TTF и не учитывает bold-раны. Вывод: **считать текст самим** (§3.4).
  - **Шрифты не встраивает** — тот же набор TTF обязан стоять в Docker-образе конвертации; пользователям PPTX отдаём только с общедоступными free-шрифтами (§3.6).
  - **SVG не умеет** (issue #394) — вставка только конвертацией SVG→EMF (Inkscape) или XML-хаком.
- **PptxGenJS (v4.x)** — альтернатива, если рендер на Node: `defineSlideMaster()` + именованные placeholder'ы (нативная поддержка «мастер + слоты»), **SVG из коробки** (svgBlip + PNG-fallback), нативные чарты, auto-paging таблиц. Autofit — та же беда, что у python-pptx.
- **docxtemplater** (шаблоны с {тегами}): слайд-модуль платный (€500/год/модуль). **Aspose.Slides** (~$3–4K/год): единственный с настоящим autofit, SVG→фигуры и PPTX→PDF без LibreOffice — держать в уме как «купить, если упрёмся». **officegen** — мёртв, не использовать.
- **Паттерн «мастер-шаблон + слоты»** (подтверждён всеми успешными реализациями): дизайнер готовит .pptx с layout'ами и именованными плейсхолдерами → JSON строго под слоты → рендерер заполняет. Лимиты каждого слота известны заранее → проверяемы измерением до рендера.

### 3.3. PPTX → PDF и HTML → PDF

- **Gotenberg v8** (рекомендация вместо голого `soffice --convert-to pdf`): Docker-образ с HTTP API (`/forms/libreoffice/convert`), держит **stateful LibreOffice** (без 1–3 с холодного старта на запрос), настройки очереди `--libreoffice-max-queue-size`, `--libreoffice-restart-after`; PDF/A, merge, метаданные.
- В образ конвертации обязательны шрифты: наши TTF тем + `fonts-liberation`, `fonts-noto`, метрические замены MS-шрифтов `fonts-crosextra-carlito/caladea` + `fc-cache -f`. Голый LibreOffice не параллелится в одном профиле (`-env:UserInstallation=...` на процесс).
- HTML-ветка (A4-раздатка): **WeasyPrint v63+** — flexbox полностью, grid — большинство раскладок; скорость ~единицы PDF/с — для раздатки достаточно. Экзотика на будущее: Typst/Touying (миллисекундные сборки, есть экспорт PPTX-картинками), Paged.js (нужен Chromium).
- Визуальный регресс-тест PPTX↔PDF на эталонных деках — остаётся обязательным (риск №4 analysis-дока).

### 3.4. Измерение текста (замена несуществующему autofit)

```python
from PIL import ImageFont
font = ImageFont.truetype("PTSans-Regular.ttf", size_px)  # px = pt * 96/72
line_w = font.getlength("Строка тезиса по-русски")         # advance width, быстро
ascent, descent = font.getmetrics()                         # высота строки ≈ (a+d) * 1.2
```

- Жадный перенос по словам с замером `getlength()` каждой строки; высота блока = строки × line height (межстрочный коэффициент PowerPoint ≈1,2). Единицы: pt ↔ px ↔ EMU (1 pt = 12700 EMU).
- Для кириллических гротесков advance-метрики Pillow точны (нет шейпинга лигатур); fonttools (`hmtx`) — быстрая консервативная оценка без кернинга (+1–3% запаса); uharfbuzz — эталон, здесь избыточен.
- Трёхуровневая защита из analysis-дока сохраняется: (1) лимиты схемы как подсказка LLM + пословный линтер + ретрай «сократи до N слов», (2) замер Pillow → ступенчатое снижение кегля (16→15→14), (3) слайд-продолжение.

### 3.5. Prompt caching и Batch API (Anthropic, правила середины 2026)

- Кэш — **префиксный по байтам**, порядок `tools → system → messages`, до 4 breakpoint'ов `cache_control: {"type":"ephemeral"}` (5 мин; `"ttl":"1h"` — запись 2×). Чтение ≈0,1× input, запись 1,25×. Минимальный кэшируемый префикс: Opus 4.8 — 4096 токенов, Sonnet — 1024–2048 (короче — молча не кэшируется).
- Раскладка нашего 5-слойного промпта по убыванию стабильности: [роль+методика] → bp → [схема дека + темы шаблонов] → bp → [ФГОС-выборка по {предмет, класс}] → bp → [профиль класса] → bp → [тема, wishes, SOURCE-чанки] без кэша.
- Тихие инвалидаторы (главные баги на практике): `datetime.now()`/UUID в system, `json.dumps` без `sort_keys=True`, условные секции, разный набор тулов. Диагностика: `usage.cache_read_input_tokens == 0` на повторе ⇒ искать инвалидатор.
- **Batch API −50%** (до 100k запросов/батч, обычно <1 ч, результаты матчить по `custom_id`): для прегенерации библиотек по кодификатору ФГОС и массовой пересборки под новый шаблон. Скидка **складывается** с кэшем; structured output в батче работает.

### 3.6. Схемы/диаграммы и шрифты

- **Диаграммы**: 4–6 фиксированных типов (процесс-стрелки, таймлайн, сравнение, оргсхема, mind-map) — **нативными фигурами pptx** (`add_shape` + `add_connector` + текстфреймы): текст остаётся текстом, конвертируется в PDF с настоящими шрифтами, редактируем. LLM отдаёт только данные диаграммы (узлы/этапы) в JSON. Mermaid/D2 — лишь fallback для произвольных схем (PNG@2–3× или SVG через EMF); mermaid-cli тянет Chromium (~170MB) — в основной пайплайн не брать.
- **Шрифты** (все OFL 1.1 — коммерческое использование и встраивание в PDF разрешены): текстовые с настоящим Bold — **PT Sans / PT Serif** (пан-кириллика, лучший дефолт), Golos Text, Inter, Noto. Дисплейные к темам: `manuscript` — Ruslan Display / Podkova; `clay`/детские — Balsamiq Sans (есть Bold), Comfortaa; рукописный с настоящим Bold — только **Caveat**. Правило: у дисплейного нет Bold → акцент размером/цветом, faux-bold запрещён (наследие Bahnschrift Light не воспроизводить).

## 4. Какие ключи подключать (карточки подключения)

### 4.1. Claude через РФ-прокси — основной текстовый LLM

Прямой доступ к api.anthropic.com из РФ невозможен (оплата). Схема всех агрегаторов: «замени base_url и ключ», совместимость с официальным SDK.

| Провайдер | Как получить | Наценка | Особенности |
|---|---|---|---|
| **ProxyAPI** (proxyapi.ru) — основной | регистрация по email, оплата ₽/счёт юрлицу, закрывающие документы | **~3–4×** от цен Anthropic (Sonnet 5: 800/4500 ₽ за 1M in/out; кэш-чтение 80 ₽/1M) | есть Anthropic-нативный маршрут (structured output, cache_control, streaming работают); Batch −50% |
| **AITunnel** (aitunnel.ru) — резерв | аналогично, рубли | **~2×** | OpenAI-совместимый формат; 20+ провайдеров одним ключом |
| OpenRouter | криптооплата (+5%) | ~5,5% | для юрлица «серый» путь — только dev/эксперименты |

```bash
ANTHROPIC_BASE_URL=https://api.proxyapi.ru/anthropic   # нативный маршрут (точный путь — в кабинете)
ANTHROPIC_API_KEY=<ключ ProxyAPI>
```

⚠️ Через OpenAI-совместимый слой прокси теряются `output_config`, cache_control-брейкпоинты, adaptive thinking — использовать **нативный Anthropic-маршрут**. Держать двух провайдеров за одним внутренним интерфейсом (SLA посредника — наш риск).

### 4.2. Yandex Cloud (AI Studio) — «домашний» провайдер: YandexGPT + YandexART + эмбеддинги

- Ключ: сервисный аккаунт → роли `ai.languageModels.user` + `ai.imageGeneration.user` → **API-ключ** (заголовок `Authorization: Api-Key ...`). Обязателен `folder_id`: модели адресуются `gpt://<folder_id>/...`, `art://<folder_id>/yandex-art`.
- **YandexART — основной генератор картинок**: только async (`imageGenerationAsync` → operation_id → поллинг → base64), 10–60 с на картинку, **~1,5–2,2 ₽/шт**, линейка 2.5. Генерировать параллельно с валидацией текста (как и было в плане), очередь + ретраи.
- YandexGPT 5.x — дешёвый вспомогательный текст в контуре РФ (Lite от ~0,2 ₽/1K токенов); лимит контекста синхронного API — дробить по слайдам.
- Биллинг в тот же платёжный аккаунт, данные не покидают контур — идеально под 152-ФЗ.

```bash
YC_FOLDER_ID=b1g...
YC_API_KEY=AQVN...
```

### 4.3. GigaChat (Сбер) — РФ-fallback текста И картинок

- Регистрация: developers.sber.ru, для SaaS — договор ИП/юрлица (scope `GIGACHAT_API_B2B`/`CORP`; физлицам — `GIGACHAT_API_PERS`). Выдаётся **Authorization key** (base64 `client_id:client_secret`).
- Аутентификация двухшаговая: Authorization key → **access token на 30 минут** (`https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, заголовок RqUID) → Bearer-запросы к `gigachat.devices.sberbank.ru/api/v1`. SDK `gigachat` (PyPI) рефрешит сам; при своих воркерах — кэш токена с mutex.
- **Сертификаты НУЦ Минцифры обязательны**: Russian Trusted Root CA + Sub CA в Docker-образ (`update-ca-certificates`), иначе TLS-ошибка.
- Цены: Lite ~65 ₽/1M, Pro ~500 ₽/1M, Max ~650 ₽/1M; **эмбеддинги ~14 ₽/1M**. Бонус: **генерация изображений Kandinsky встроена в тот же API** (image → file_id → `GET /files/{id}/content`) — легальный рублёвый fallback картинок.
- Ограничение: structured output без `anyOf/oneOf` (см. §3.1).

```bash
GIGACHAT_AUTH_KEY=<base64 client_id:client_secret>
GIGACHAT_SCOPE=GIGACHAT_API_B2B
```

### 4.4. DeepSeek — дешёвая массовка (опционально)

- Ключ: platform.deepseek.com → `sk-...`, OpenAI-совместимый `base_url=https://api.deepseek.com`. Оплата — зарубежная карта/посредник (или те же РФ-агрегаторы с наценкой).
- Цены V4 Flash: ~$0.14/1M input (**$0.0028 cache hit**), $0.28/1M output — в 20–50 раз дешевле Claude. Роль: alt-тексты, подписи, сокращения, черновики. JSON mode капризный (пустой content → ретрай), json_schema нет — только с клиентской валидацией.
- Юр. нюанс: КНР, не под 152-ФЗ — только обезличенный учебный контент.

### 4.5. Kandinsky (FusionBrain) — ⚠️ статус изменился

Исторический бесплатный API (пары X-Key/X-Secret, api-key.fusionbrain.ai) **в 2026 фактически мёртв**: фримиум ~20 генераций/мес (Creator 499 ₽/мес ~200), перебои, документация отдаёт 503. Продакшн на нём не строить. Замены: YandexART (основной) → Kandinsky через GigaChat API (fallback) → **self-host Kandinsky 5.0** (Apache 2.0, github.com/kandinskylab) на GPU в Yandex Cloud — стратегический вариант при масштабе (фиксированная стоимость GPU вместо пер-картинки).

### 4.6. Эмбеддинги RAG

**`intfloat/multilingual-e5-large`** — локально: MIT, 1024-мерные, ~2,2 GB, CPU/малая GPU, префиксы `query:`/`passage:` обязательны. Данные не уходят наружу. Managed-альтернативы: Yandex embeddings (тот же API-ключ) или GigaChat (~14 ₽/1M). Свежие открытые альтернативы при желании: Qwen3-Embedding-0.6B.

### 4.7. Секреты и 152-ФЗ

- Ключи — в **Yandex Lockbox**, в контейнеры через env при старте; ключи прокси ротируются в кабинете без смены договора.
- Во внешние LLM (Claude/DeepSeek) — только тексты учебников/тем **без ПДн**. ФИО учеников, email, любые идентификаторы — нельзя (трансграничная передача, с 2025 фактически разрешительный порядок). PII-фильтр перед каждым внешним вызовом; с 2026 требования к обезличиванию ужесточены (данные не должны деанонимизироваться сопоставлением).
- Ветки с ПДн (проверка работ по фото и т.п.) — только GigaChat/Yandex/локальные модели. БД, загрузки, векторное хранилище, логи — в РФ. В логи не писать тела промптов с потенциальными ПДн и ключи; хранить request_id провайдеров для инцидентов.

## 5. Presenton и SlideSpeak: что взять как референс

- **Presenton** (Apache 2.0) — изучить в первую очередь: контракт API (`POST /api/v1/ppt/presentation/generate`: контент, число слайдов, язык, шаблон, формат экспорта), устройство HTML/Tailwind-шаблонов и конвертацию «существующий PPTX → переиспользуемый шаблон». Решение «шаблоны на HTML + печать» vs наш «python-pptx + мастер» — сравнить на прототипе: HTML-шаблоны быстрее в дизайн-итерациях, python-pptx даёт честный редактируемый PPTX. Возможный гибрид: HTML — для превью/PDF, python-pptx — для экспорта.
- **SlideSpeak** — референс продуктового контракта API: JSON-вход, «1 кредит = 1 слайд», загрузка документов и экспорт бесплатны, списание только за успех — хорошая модель для наших тарифов на API (если будем открывать свой API школам/интеграторам).
- **Gamma Generate API** — референс параметров генерации (tone, audience, numCards, темы, выбор модели картинок) для нашей формы «пожеланий учителя».

## 6. Поправки к предыдущим документам

### К `llm-cost-model.md` (себестоимость)

1. **Цены Claude пересчитать через прокси-наценку.** В модели заложены официальные цены + 5,5% — реальность: ProxyAPI ~3–4× (Sonnet 5: 800/4500 ₽ за 1M), AITunnel ~2×. Текстовая часть презентации (outline+контент+судья+ретраи ≈ 13 ₽ по официальным ценам) через ProxyAPI → **~35–45 ₽**, через AITunnel → **~25 ₽**. Митигации: (а) AITunnel основным, ProxyAPI резервом — либо торг за объёмы; (б) черновик на DeepSeek V4 Flash + финализация Sonnet 5 (потенциально −40–60% текстовой части); (в) агрессивный prompt cache (чтение 80 ₽/1M у ProxyAPI — дёшево); (г) Batch −50% на прегенерацию.
2. **Строку «Kandinsky ×14 = 0 ₽» удалить.** Реалистичная строка картинок: YandexART ×10–14 ≈ 15–30 ₽ (с кэшем по хэшу промпта — кратно меньше на популярных темах). Риск маржи изображений, отмеченный в ТЗ, подтверждён и усилен.
3. **Итог по стандартной презентации: ~40–75 ₽ вместо ~13 ₽** (до оптимизаций). Списание 2 кредитов (11,9–16,3 ₽/кредит) держит маржу только с оптимизациями (б)–(г) или ценой 3 кредитов на дек с картинками на всех слайдах. Пересчитать тарифную сетку до запуска.

### К `presentation-generation-analysis.md` (архитектура)

4. **Роутер моделей**: DeepSeek V4 Flash повышается с «массовки» до кандидата на черновую генерацию контента (цена/качество), Sonnet 5 — финализация и сложные предметы; GigaChat — fallback обеих ролей. Схема дека обязана остаться плоской (без union) ради GigaChat-совместимости — текущая схема этому уже соответствует, зафиксировать как требование.
5. **Картинки**: дефолт — YandexART (не Kandinsky/FusionBrain); fallback — Kandinsky в GigaChat API; стратегически — self-host Kandinsky 5.0.
6. **PDF-конвертация**: Gotenberg вместо прямого вызова LibreOffice (stateful-инстанс, очередь, PDF/A).
7. **Autofit**: подтверждено — не полагаться вовсе; измеритель Pillow `getlength` + деградация кегля (уже в плане, теперь с конкретикой реализации).
8. **Конкурентное окно подтверждено**: NotebookLM (теперь с редактируемым PPTX-экспортом!) и Gemini-in-Slides быстро растут в точности, но остаются без API и без рублёвой оплаты. Наше окно — «точность NotebookLM + редактируемый PPTX + ФГОС + рубли + 152-ФЗ». NotebookLM-экспорт в PPTX стал редактируемым — аргумент «у них растр» ослаб, упор в маркетинге смещать на ФГОС-валидацию, шаблоны и доступность из РФ.
