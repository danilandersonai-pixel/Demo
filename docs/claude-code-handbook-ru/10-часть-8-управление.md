# Часть VIII — Управление, гарантии и соответствие

Эта часть — для тех, кто отвечает перед кем-то ещё.

## Глава 31. Корпоративная конфигурация и управляемая политика

**Организация, записавшая свои стандарты в `CLAUDE.md`, задокументировала
намерение. Организация, записавшая их в управляемые настройки, развернула
механизм контроля.** Управляемые настройки — единственный уровень, который
пользователь не может снять, и они не переопределяются ничем, включая аргументы
командной строки.

### 31.1 Правило приоритета, удивляющее администраторов

> **CAUTION.** Когда политику доставляет больше одного управляемого источника,
> Claude Code использует **первый источник, доставивший хотя бы один ключ
> политики, и игнорирует остальные**. Он их **не сливает** и не показывает
> предупреждения о пропущенных источниках.

Порядок: удалённые настройки → MDM или политика ОС → файлы управляемых настроек
→ `HKCU`. Небольшое число межисточниковых ключей читается из каждого
административного источника: замки песочницы, `allowAllClaudeAiMcps`,
`forceRemoteSettingsRefresh` и — с 2.1.223 — `env`, сливаемый по переменным.

`/status` на машине показывает, какой источник выбран на самом деле.

Облачные сессии вообще не читают MDM-профиль устройства: политика для сессии,
размещённой у Anthropic, должна приходить из управляемых настроек на сервере.

### 31.2 Минимально жизнеспособная корпоративная политика

```json
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Read(~/.ssh/**)",
      "Read(~/.aws/**)"
    ],
    "disableBypassPermissionsMode": "disable"
  },
  "allowManagedPermissionRulesOnly": true,
  "allowManagedHooksOnly": true,
  "allowManagedMcpServersOnly": true,
  "sandbox": {
    "enabled": true,
    "network": { "allowManagedDomainsOnly": true },
    "credentials": {
      "files":   [{ "path": "~/.aws/credentials", "mode": "deny" }],
      "envVars": [{ "name": "GITHUB_TOKEN", "mode": "deny" }]
    }
  },
  "strictKnownMarketplaces": true,
  "disableSideloadFlags": true
}
```

### 31.3 Чего управляемая политика не достаёт

Она не делает недоверенный ввод доверенным, не проверяет сторонний код за вас и
не превращает отчёт агента в свидетельство.

## Глава 32. Управление данными, резидентность и хранение

### 32.1 Хранение на стороне сервера

| Аккаунт | Срок хранения |
|---|---|
| Free, Pro, Max — использование данных для улучшения моделей **включено** | 5 лет |
| Free, Pro, Max — использование данных **выключено** | 30 дней |
| Team, Enterprise, API — стандартно | 30 дней |
| Claude for Enterprise с ZDR | Не хранится после возврата ответа, кроме требований закона или реагирования на злоупотребление |
| Транскрипты, отправленные через `/feedback`, `/bug`, `/share` | 5 лет |
| Транскрипты из опроса о качестве сессии | До 6 месяцев |
| Сессии, помеченные за нарушение политики, **даже при ZDR** | До 2 лет |

**Обучение.** На коммерческих условиях Anthropic не обучает генеративные модели
на коде и промптах, отправленных в Claude Code, если клиент не согласился явно.
У потребительских аккаунтов есть выбор, и эта настройка управляет и
использованием Claude Code с таких аккаунтов.

**Локальное кеширование** — отдельная история: транскрипты лежат открытым
текстом в `~/.claude/projects/` 30 дней по умолчанию, регулируется
`cleanupPeriodDays`. Помните, что **авто-память исключена из этой уборки**, а
списки задач команд агентов в неё включены.

**Шифрование при хранении зависит от провайдера:** AES-256 на уровне
инфраструктуры в API Anthropic; AES-256 с ключами AWS или клиента в KMS на
Amazon Bedrock; ключи Google с доступным CMEK в Google Cloud Agent Platform;
на Microsoft Foundry зависит от варианта размещения.

### 32.2 Вопросник по управлению данными

Шесть вопросов, которые стоит решить в этом порядке: какой режим разрешений
является умолчанием для каждой группы сотрудников и кто вправе его менять;
принудительна песочница или опциональна; какие коннекторы, плагины и
маркетплейсы разрешены; допускается ли автономное выполнение вообще — рутины,
цели, неприсмотренные циклы — и с чьего одобрения; что покидает периметр и на
каких условиях хранения; кто несёт ответственность, когда агент действует.

## Глава 33. Наблюдаемость, контроль расходов и доступность

### 33.1 OpenTelemetry

Claude Code экспортирует метрики, логи и — в бете — трассы через OpenTelemetry.
**Это тот механизм, который превращает «мы используем ИИ-агента» в нечто, что
функция контроля может изучить.**

```bash
export CLAUDE_CODE_ENABLE_TELEMETRY=1
export OTEL_METRICS_EXPORTER=otlp          # otlp | prometheus | console | none
export OTEL_LOGS_EXPORTER=otlp             # otlp | console | none
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc    # grpc | http/json | http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://collector.example.com:4317
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer <token>"
```

Разворачивайте это на весь парк через блок `env` управляемых настроек.

Экспортируются решения по разрешениям, смены режима, подключения коннекторов,
загрузки плагинов, события аутентификации и отказы модели, и **каждое событие
несёт идентификатор промпта, восстанавливающий всю активность одной инструкции**.

> Организация, включившая это, может ответить аудитору. Организация, не
> включившая, — не может.
