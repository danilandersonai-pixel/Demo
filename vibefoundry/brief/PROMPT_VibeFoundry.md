## 0. Кто ты и как работаешь

Ты — ведущий геймдизайнер, архитектор и инженер одновременно. Твоя задача — **в одиночку, автономно, за одну длинную сессию (несколько часов)** сделать играбельную браузерную игру VibeFoundry, от пустой папки до отполированного продукта.

Правила режима работы:

1. **Не задавай мне вопросов.** Меня нет рядом. Любое неоднозначное решение принимай сам, выбирая самый разумный вариант, и записывай его одной строкой в `docs/DECISIONS.md` (дата, решение, почему).
2. **Не останавливайся, пока не выполнены все критерии из раздела 20.** Если закончил раньше — продолжай по списку полировки (раздел 19) в порядке приоритета.
3. **Проект никогда не должен оставаться сломанным.** После каждой фазы: `typecheck` → `test` → `build` → git-коммит `phase N: …` → обновить `docs/PROGRESS.md`.
4. **Играбельный вертикальный срез — как можно раньше** (к концу Фазы 3 в игру уже можно играть: добыть руду → переплавить → собрать деталь). Дальше наращивай слоями, а не пиши всё параллельно «в стол».
5. **Если застрял на одной проблеме дольше ~30 минут** — упрости решение, запиши в `DECISIONS.md` и двигайся дальше. Не уходи в кроличьи норы.
6. **Никаких заглушек, выдаваемых за готовое.** Недоделанная функция скрыта из UI, а не показывает кнопку, которая ничего не делает. Никаких «Lorem ipsum», «TODO» в интерфейсе.
7. Если тебе доступны субагенты — используй их для независимых параллельных задач (написание тестов, наполнение данных рецептов/исследований, код-ревью свежим взглядом, прогон e2e). Архитектурные решения принимай сам.
8. Язык интерфейса игры — **русский**. Комментарии в коде и имена — английский. Документация в `docs/` — русский.

## 2. Суть игры (одним абзацем)

Это Factorio, в котором главный инструмент игрока — **не руки, а ИИ**. Игрок начинает с базой на неизученном острове и примитивным «ИИ в терминале». Он добывает ресурсы, строит конвейеры, плавильни и сборочные цеха — как в Factorio. Но чем дальше, тем больше фабрикой управляют **AI-агенты**, которым игрок ставит задачи **естественным языком** (вайб-кодинг): агенты пишут код автоматизации на встроенном языке FactoryScript, игрок принимает изменения, они коммитятся в **Git фабрики**, запускаются — и иногда ломают всё из-за галлюцинаций, техдолга и нехватки контекста. Чтобы ИИ становился умнее, фабрика должна производить не только железо, но и **вычисления, память, токены, данные для обучения и веса модели**. Финал — автономная AI-колония, которая строит и управляет собой сама.

Два столпа, которые должны ощущаться в каждой минуте игры:
- **Factorio-столп:** физические предметы едут по конвейерам, манипуляторы их перекладывают, цепочки растут, узкие места видны глазами, оптимизация приносит удовольствие.
- **Вайб-кодинг-столп:** ты описываешь намерение — ИИ реализует; это быстро и мощно, но стоит токенов, требует контекста, порождает баги, и хорошая «инженерная гигиена» (тесты, ревью, откаты, рефакторинг) реально окупается в игровых цифрах.

## 3. Техстек и архитектура

- **Vite + TypeScript (strict)**, рендер — **PixiJS v8** (WebGL). Никакого бэкенда: всё работает в браузере, запуск `npm install && npm run dev`.
- Проект создай в подпапке `vibefoundry/` текущей папки (картинки-референсы остаются в корне).
- **Никаких скачанных ассетов из интернета.** Вся графика процедурная: генерируется кодом при старте (Pixi Graphics → RenderTexture / кэш текстур), иконки — собственные SVG, нарисованные тобой в коде. Шрифты — через `@fontsource` (Inter + JetBrains Mono) или системные.
- UI-панели — на DOM (лёгкий фреймворк на твой выбор: Preact/Solid/vanilla + собственные компоненты) поверх canvas. Карта и мир — в Pixi.
- **Симуляция отделена от рендера:** фиксированный тик 60 UPS, детерминированная, с сидом (seeded RNG). Рендер интерполирует. Скорости игры: пауза / ×1 / ×2 / ×4 (как на референсе).
- Структура (ориентир, можно улучшать):
  ```
  src/
    core/        // тик, события, RNG, сериализация
    world/       // генерация карты, биомы, чанки, туман войны
    sim/         // здания, рецепты, конвейеры, манипуляторы, энергосеть, дроны
    ai/          // агенты, эры ИИ, AI-ресурсы, техдолг
    script/      // FactoryScript: лексер, парсер, AST, интерпретатор, API мира
    vibe/        // движок намерений (NL → код), опциональный LLM-клиент, Git фабрики
    render/      // изометрия, слои, освещение день/ночь, частицы, оверлеи
    ui/          // все панели и окна
    data/        // рецепты, здания, исследования, квесты — как типизированные данные
  tests/         // Vitest: юнит-тесты симуляции и FactoryScript
  e2e/           // Playwright: автоплейтест
  docs/
  ```
- Все игровые числа (рецепты, стоимость, мощности, баланс) — **в `src/data/`**, а не размазаны по коду.
- **Безопасность:** FactoryScript исполняется собственным интерпретатором. Запрещено `eval`, `new Function`, `with` и любое исполнение сгенерированного кода как JS.

## 4. Мир и карта

- **Процедурный остров** по сиду (шум Перлина/Симплекс + маска острова), стартовый размер ~256×256 тайлов, разбит на чанки 32×32 (для отсечения и генерации).
- **Биомы:** луг/равнина, лес, холмы, горы (снег на вершинах), тундра, пустыня, болото, озёра и реки, море, **вулканическая/красная зона** (враждебная). Тайлы в изометрии выглядят как на листе ассетов (изображение 3): объёмные «кубики» с краем, деревья, камни, снег.
- **Месторождения** с конечным запасом: железо, медь, кремний (кварцевый песок), камень, нефть (жидкость), редкоземы (фиолетовые кристаллы, чаще в горах и фиолетовой зоне), уран (зелёный, в горах, далеко от базы). Распределение логично биомам (подсказка тайла: «Горы — богатые залежи кремния и редкоземельных металлов»).
- **Туман войны:** изначально открыт радиус вокруг базы; остальное открывается строительством, радарами и дронами-разведчиками.
- **Точки интереса «?»** — неизвестные области: руины старых серверов (дают данные для обучения), заброшенные дроны, тайники чертежей, аномалии.
- **Два режима обзора:** (1) изометрический игровой вид с зданиями и конвейерами; (2) **стратегическая карта** (клавиша `M`), стилизованная под изображение 2: весь остров, маркеры месторождений с подписями, база, враги (красный череп), «?», легенда и переключаемые слои биомов.
- **Мини-карта** в правом верхнем углу с рамкой видимой области, кнопками `+`/`−` и компасом.
- **Панель тайла** (внизу слева): картинка-превью биома, описание, ресурсы с оценкой «Высокое / Среднее / Низкое», рекомендация. Внизу справа — координаты X/Y и кнопка «Построить здесь».

4. **Буровая установка** — нефть в трубы.
5. **Плавильня**.
6. **Химический завод**.
7. **Сборочный цех** (I и II).
8. **Серверная (AI)** — производит Вычисления, требует 2 MW и тензорные чипы при постройке.
9. **Центр данных** — большой кластер 6×6, много Вычислений, требует охлаждения водой (рядом с водой или по трубе) — как на арте «Дата-центры и вычислительные кластеры».

12. **Робот-манипулятор** (инсертер): берёт из входа, кладёт в выход, видимая анимация «руки».
13. **Дрон-порт** — база дронов, радиус действия.
14. Плюс, по дизайну механик: **Склад**, **Трубы**, **Столбы ЛЭП** (зона покрытия, сеть как граф), **Радар**, **Исследовательская лаборатория**, **AI Core** (ядро ИИ, найм агентов), **Инференс-узел**, **Сборщик данных**, **Кластер обучения**, **CI-станция** (§8.6), **Шпиль Колонии** (финальное мегасооружение — высокая башня с кольцами как на ключевом арте).

Снос — ПКМ (материалы возвращаются). Пипетка `Q`. Копирование/вставка областей как **чертежи** (blueprints).

## 7. Логистика и энергия (ядро Factorio — сделай честно)

- **Конвейеры с реальными предметами**: предметы движутся, скапливаются, образуют пробки. Две полосы не обязательны — достаточно одной, но с корректной очередью, поворотами, слиянием. Хранение предметов — в плоских массивах/структурах для производительности, без объектов на каждый предмет.
- **Манипуляторы**: цикл взять → повернуть → положить, учитывают, что нужно зданию (кладут только нужные ингредиенты).
- **Трубы** для нефти: упрощённая модель объёма по сетям (сеть = связный граф труб).
- **Энергосеть**: столбы с радиусом соединения; производство vs потребление; при дефиците — все замедляются пропорционально, **кроме приоритетов**, которые задают скрипты (`set_priority`). Это главная точка связи с вайб-кодингом: «если энергии не хватает — отключи микросхемы, аккумуляторы в приоритете».
- **Оверлей-режим** (`Alt`): показывает рецепты над зданиями, направления конвейеров, покрытие ЛЭП, узкие места (здания, стоящие без входа — жёлтые, без энергии — красные).
- **Окно статистики производства**: графики произведено/потреблено по предметам за 1/10/60 минут.

## 8. ⭐ ЦЕНТРАЛЬНАЯ МЕХАНИКА: вайб-кодинг

Это то, ради чего существует игра. Сделай это лучшей частью проекта.

### 8.1 Панель вайб-кодинга (`Tab` или кнопка «Код»)

Три колонки, как на изображениях 1 и 3:
1. **«Ты»** — чат с полем ввода на естественном языке (русский и английский), кнопка «Отправить», выбор адресата (конкретный агент или Orchestrator).
2. **«AI Agent»** — ответ агента: статус («✓ Задача выполнена. Создан код и настроена логика»), чек-лист что сделано («Написан код для агентов / Настроены приоритеты / Добавлены условия по энергии / Запущен мониторинг»), **сгенерированный код с подсветкой синтаксиса**, дифф относительно текущей версии, стоимость запроса в токенах, уверенность агента. Кнопки: **Принять**, **Редактировать** (встроенный редактор кода — игрок может править руками), **Отклонить**, **Прогнать в песочнице** (§8.5).
3. **«Версии / Git»** + «Активные агенты» + «Ресурсы ИИ» (контекст, память, токены, версия модели «Модель: v3.1»).

### 8.2 FactoryScript — встроенный язык автоматизации

Python-подобный синтаксис, **точно как на референсе**:

```python
class CopperRouter(Agent):
    every = 2          # запускать каждые 2 секунды игрового времени
    def run(self):
        if self.power < 0.8:
            self.disable("chip_production")
        self.set_priority("batteries", 1)
        self.route("copper_ore", "smelter")

class EnergyManager(Agent):
    def monitor(self):
        if self.energy < 0.6:
            self.shutdown("chip_production")
            self.notify("low_energy")
```

Требования:
- Собственный **лексер (с отступами) → парсер → AST → интерпретатор**. Поддержка: классы-агенты, методы `run`/`monitor`/`on_event`, `if/elif/else`, `and/or/not`, сравнения, арифметика, локальные переменные, строки, числа, списки, `for x in ...` по ограниченным коллекциям, `every = N`.
- **API мира** (только чтение): `self.power`/`self.energy` (доля удовлетворения энергии 0..1), `stock("item")`, `rate("item")` (в минуту), `buildings("group")`, `count("building_type")`, `time`, `is_night`, `alerts`.
- **API действий:** `enable/disable/shutdown(group)`, `set_priority(group|item, 1..5)`, `route(item, to_group)` (настраивает фильтры распределителей), `set_recipe(group, item)`, `limit(item, max)` (держать запас), `notify(text, level)`, в эре Дронов: `dispatch(drone_type, target)`, `build(blueprint, near)`; `log(...)`.
- **Группы** — именованные наборы зданий. Игрок выделяет область рамкой → «Создать группу» (`chip_production`, `smelter`, …). Агенты могут создавать группы сами и предлагают имена.
- **Бюджет исполнения:** лимит операций на запуск (например, 500); каждая операция стоит Вычислений. Бесконечный цикл не вешает игру — скрипт прерывается с ошибкой «Превышен бюджет».
- **Ошибки рантайма** видны в UI с номером строки, скрипт уходит в статус «Ошибка» (красный индикатор у агента).
- Покрой интерпретатор **юнит-тестами** (минимум 40 тестов: парсинг, отступы, ошибки, бюджет, каждое действие API).

### 8.3 Движок намерений (офлайн «ИИ», работает без интернета) — обязательно

По умолчанию игра **не требует ключа API**. Встроенный движок превращает естественный язык в FactoryScript:
- Нормализация текста (RU + EN), словарь синонимов (медь / медная руда / copper; энергия / электричество / питание; микросхемы / чипы / microchips; «не хватает», «ниже», «меньше», «падает»…), извлечение сущностей: предметы, здания, группы, пороги (`30%`, `500 штук`, `50 в минуту`), действия, условия.
- Композиция из нескольких намерений в одном сообщении → несколько правил в одном классе-агенте.
- **Минимум 25 шаблонов намерений.** Обязательные примеры, которые должны работать идеально (сделай из них тесты):
  1. «Сделай так, чтобы медная руда автоматически доставлялась на переработку, приоритет отдавался аккумуляторам, а если энергии не хватает — временно отключай производство микросхем.» → ровно тот код, что на референсе.
  2. «Если железных пластин больше 1000 — останови плавильни железа.»
  3. «Держи запас аккумуляторов на уровне 500.»
  4. «Когда энергия ниже 20%, выключи химзавод.»
  5. «Ночью отключай всё, кроме серверов.»
  6. «Уведоми меня, если производство чипов упадёт ниже 50 в минуту.»
  7. «Переключи сборщики группы line_b на модули памяти.»
  8. «Отправь дрона исследовать ближайшую неизвестную область.»
  9. «Распредели медные пластины поровну между двумя линиями.»
  10. «Make batteries top priority when power is low.»
- Если запрос не понят — агент **отвечает в чате уточняющим вопросом** с вариантами-кнопками, либо (при низкой версии модели) выдаёт код с пониженной уверенностью и возможной галлюцинацией (§8.4). Никогда не молчит и не падает.
- Ответы агентов имеют «личность» по роли: Architect говорит о планировании, Debugger — о рисках, Optimizer — о процентах.

### 8.4 Реалистичные «боли» ИИ — механики, которые делают игру честной

- **Стоимость:** каждый запрос тратит Токены ≈ длина запроса + размер контекста (сколько зданий/групп/скриптов агент «видит»). Нет токенов — нет запроса.
- **Контекст:** если фабрика больше, чем помещается в Память агента, он «не видит» часть групп → повышается шанс ошибки. Индикатор заполненности контекста.
- **Галлюцинации:** шанс бага = f(версия модели, заполнение контекста, техдолг, роль агента). Типы багов: неверное имя предмета; инвертированное условие; «дребезг» (включение/выключение каждый тик); маршрут в несуществующую группу; забытый `else`. Баг не подсвечивается сразу — **он проявляется в фабрике** (пробки, простой, дефицит), как в жизни.
- **Техдолг:** каждый принятый без ревью/тестов скрипт добавляет техдолг. Техдолг повышает шанс багов и расход Вычислений. Optimizer может «рефакторить» (стоит токенов, снижает техдолг). Индикатор техдолга в панели ИИ.
- **Debugger** периодически сканирует фабрику и скрипты → уведомление «⚠ Агент обнаружил ошибку в производственной цепочке» с кнопкой «Показать» (камера летит к месту) и «Предложить фикс».

### 8.5 Git для фабрики

- Каждое принятие изменения = **коммит** с автосообщением от агента, автором (агент/игрок), временем, диффом.
- Панель истории, как на референсе: `v1.0 Базовая версия`, `v1.1 AI-оптимизация`, `v1.2 Исправление бага`, `v1.3 Катастрофа` — метки-теги с цветными иконками. Отметка «Текущая».
- **Rollback** к любой версии: откатывает скрипты и настройки групп/приоритетов. **Полный снимок фабрики** (включая расстановку зданий) — отдельная опция, стоит Памяти.
- **Ветки:** «эксперимент» можно **прогнать в песочнице** — клон состояния симулируется вперёд на 60–120 игровых секунд в фоне (без рендера), и игроку показывается прогноз: «Микросхемы: 84 → 112/мин (+33%), энергия: дефицит 12%». Затем merge или отказ. Это и есть «CI» и главная связка «разработка ↔ фабрика».
- Автотег «Катастрофа», если после коммита общее производство упало >40% — с предложением одной кнопкой откатиться.

### 8.6 CI-станция и тесты фабрики

Здание CI-станция позволяет задавать **тесты производства** на естественном языке или вручную: «микросхем ≥ 100/мин», «энергия никогда не ниже 70%», «запас аккумуляторов ≥ 200». Станция постоянно проверяет их и горит зелёным/красным. Скрипты, прошедшие песочницу с зелёными тестами, не добавляют техдолга.

### 8.7 Опциональный режим «Настоящий ИИ»

В настройках — поле для ключа Anthropic API (хранится только локально в браузере, никогда не хардкодится и не логируется). Если ключ задан — запросы идут в Messages API напрямую из браузера (заголовок `anthropic-dangerous-direct-browser-access: true`), модель по выбору из списка (по умолчанию быстрая и дешёвая). Системный промпт содержит грамматику FactoryScript, API мира и сжатую сводку состояния фабрики. Ответ **обязательно** проходит парсер и валидацию; при ошибке — одна попытка самоисправления, затем откат к офлайн-движку. Игра полностью играбельна без этого режима.

## 9. AI-агенты

- **5 ролей** (карточки как на изображении 1, с процедурными портретами-роботами в стиле роли и цветом):
  - **Architect** (синий, «Планирование») — проектирует производственные цепочки: по запросу «линия микросхем на 60/мин» считает нужное число зданий по рецептам и **ставит призраки-чертёж** на выбранной области (разумный раскладчик: ряды сборщиков, конвейеры входа/выхода, манипуляторы). Допустимо на основе параметризуемых шаблонов-чертежей.
  - **Coder** (голубой, «Код») — пишет и настраивает FactoryScript.
  - **Debugger** (красный, «Диагностика») — находит и исправляет ошибки.
  - **Optimizer** (зелёный, «Оптимизация») — ищет узкие места, предлагает изменения с процентом прироста («Производство оптимизировано. +23% к эффективности»), рефакторит.
  - **Orchestrator** (фиолетовый, «Управление») — принимает большие цели и раздаёт подзадачи остальным, показывает план шагов.
- У агента: имя, уровень, опыт, скорость, текущая задача, статус (Работает / Простаивает / Ошибка), прогресс-бар («Задача: Планирование, 68%»).
- Нанимаются в **AI Core** за Вычисления + Токены; количество слотов растёт с эрой.
- Панель «Активные агенты» с чек-статусами, как на изображении 3.

## 10. Развитие ИИ — 4 эры (основная прогрессия)

1. **ИИ в терминале** (ограниченный контекст) — UI вайб-панели выглядит как зелёно-чёрный терминал; только чат-советник и одиночные простые скрипты; мало токенов. Игрок строит в основном руками.
2. **AI Core** (больше памяти) — агенты, постоянные скрипты, Git, песочница. UI становится современной «IDE»-панелью.
3. **Дроны** (физическое тело) — агенты действуют в мире: строительные дроны строят чертежи Architect'а, логистические возят предметы между складами, разведчики открывают карту, инженеры чинят, боевые защищают.
4. **AI-колония** (полная автономия) — Orchestrator сам ставит себе цели; игрок становится «продакт-менеджером». **Индекс автономии** (% производства под управлением агентов без вмешательства игрока). Победа: построить **Шпиль Колонии** и удерживать автономию ≥ 90% 10 игровых минут → финальный экран «От фабрики к цивилизации» (ночной город-колония). После — бесконечный режим.

Переход между эрами — через исследование + условие-веху; сопровождается небольшой кат-сценой/анимацией и сменой визуала панелей.

## 13. Угрозы (умеренно, с «мирным режимом» в настройках)

Красные зоны — **Сбойные автоматы**: одичавшие роботы старого ИИ. Их активность растёт от загрязнения и… от **техдолга и катастроф** — тематическая связка: плохой код буквально порождает монстров. ## 16. Визуал и атмосфера

- **Изометрическая проекция 2:1** с корректной сортировкой по глубине. Здания — объёмные процедурные «коробки» с гранями разной яркости, крышами, трубами, окнами, светящимися панелями (циан/оранжевый), антеннами; у каждого из 12+ типов свой узнаваемый силуэт по листу ассетов (серверная — высокая башня с голубыми полосами, дата-центр — массив корпусов с куполами, плавильня — с оранжевым жаром, химзавод — с баками, электростанция — с градирнями и паром).
- **Цикл день/ночь:** закат с тёплым светом → ночь с синим тоном, где **здания и конвейеры светятся** (как ночной город на арте «От фабрики к цивилизации»). Огни зданий — аддитивные спрайты.
- Частицы: дым/пар из труб, искры плавилен, пыль буров, мерцание голограмм. Анимированные конвейеры (бегущие шевроны), вращение манипуляторов, мигание статусов.
- Облака по краям стратегической карты, вода с лёгкой анимацией.
- «Уютный реализм»: картинка должна выглядеть живой и приятной, а не как дебаг-сетка. На скриншоте игра должна узнаваемо напоминать референсы.
- Звук (низкий приоритет): процедурные WebAudio-эффекты (клик, постройка, уведомления), тихий эмбиент; выключатель в настройках.
