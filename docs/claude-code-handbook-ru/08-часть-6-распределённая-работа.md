# Часть VI — Распределённая и облачная работа

## Глава 25. Продолжить локальную работу через Remote Control

Remote Control позволяет другому устройству, где вы вошли в аккаунт, наблюдать
за процессом Claude Code, работающим на **вашей** машине.

> **Выполнение остаётся локальным.** Код, файлы и команды никогда не покидают
> ваш компьютер. Путешествует разговор: он ретранслируется через API Anthropic
> по TLS и **хранится на серверах Anthropic, пока соединение активно**, чтобы
> синхронизироваться между устройствами. *Это заблуждение M21 — и причина, по
> которой Remote Control отключён при Zero Data Retention.*

```
/remote-control                            # псевдоним /rc
claude --remote-control research-brief     # псевдоним --rc
claude remote-control                      # серверный режим
```

Соединение использует несколько короткоживущих учётных данных с узкой областью,
каждое ограничено своей целью и истекает независимо, чтобы сузить радиус
поражения при компрометации любого из них.

### Правила работы

- Начинать с узкого каталога проекта, **никогда с домашнего**.
- Сохранять обычный режим разрешений и песочницу. **Удалённость — не повод
  расширять доступ.**
- Именовать сессии внятно, чтобы с телефона нельзя было спутать два проекта.

## Глава 26. Облачные сессии, `--cloud` и `--teleport`

> Claude Code в вебе — research preview для Pro, Max и Team, а также для
> Enterprise с соответствующими местами.

Облачная сессия работает на инфраструктуре Anthropic на `claude.ai/code` либо в
самостоятельно размещённой среде вашей организации. Сессии сохраняются при
закрытии браузера и наблюдаются из мобильного приложения.

> **Это другой механизм, чем Remote Control, и путаница между ними — самая
> частая ошибка в этой области.** `--cloud` создаёт облачную сессию, которая
> работает где-то ещё; `--remote-control` выставляет **локальную** сессию для
> наблюдения.

### 26.1 Из терминала в облако

```
claude --cloud "Fix the authentication bug in src/auth/login.ts"
```

Облачная ВМ клонирует **GitHub-remote текущего каталога на текущей ветке**, а не
ваш локальный checkout — **сначала сделайте push**, если у вас есть локальные
коммиты. Один репозиторий за раз. Из репозитория, не связанного с GitHub,
Claude Code упаковывает локальный репозиторий и загружает его: полная история по
веткам плюс незакоммиченные изменения отслеживаемых файлов, до 100 МБ,
неотслеживаемые файлы исключены, и без возможности запушить обратно, если не
настроена аутентификация GitHub.

Отправить сообщение в идущую облачную сессию с любой машины, где вы вошли:

```
claude -p "ваше сообщение" --cloud <session-id>   # поставить в очередь и выйти
claude --cloud <session-id>                       # подключиться интерактивно
```

### 26.2 Доступ к GitHub и что он на самом деле даёт

Проверяйте, какие репозитории доступны сессии и с какими правами. Push в ветки с
префиксом `claude/` принимается всегда; прочие подчиняются защите веток.

## Глава 27. Проталкивать события в сессию через каналы

> Каналы — research preview. Требуют аутентификации Anthropic через claude.ai
> или ключ Console API; недоступны на Amazon Bedrock, Google Cloud Agent Platform
> и Microsoft Foundry. Организациям Team и Enterprise нужно включить их явно.

Канал — это MCP-сервер, который **проталкивает** события в идущую сессию, вместо
того чтобы ждать запроса. Если обычный коннектор даёт Claude доступ к системе по
требованию, то канал позволяет системе дотянуться до **уже открытой у вас
сессии** — упавший CI, алерт мониторинга, сообщение в чате — пока Claude ещё
держит ваши файлы открытыми и помнит, что вы отлаживали.

События приходят, только пока сессия открыта, поэтому постоянная схема означает
фоновый процесс или постоянный терминал.

Каналы устанавливаются как плагины и требуют Bun. В превью входят Telegram,
Discord и iMessage, плюс `fakechat` как локальная демонстрация.

> **CAUTION.** Содержимое события — недоверенный ввод. Сообщение из чата или
> тело вебхука не являются инструкцией от вас; это данные.

## Глава 28. Публиковать работу как артефакты

Артефакт — опубликованная страница (`.html`, `.htm` или `.md`, не больше 16 МиБ,
одна страница; относительные ссылки не разрешаются — используйте якоря).

### 28.1 Кто что видит

Новый артефакт виден **только вам**. На планах Team и Enterprise можно дать
доступ конкретным людям или всей организации и назначить **редактора**, который
вправе публиковать новые версии. На Pro и Max единственный вариант, которым
можно поделиться, — **публичная ссылка, открытая любому в интернете без входа**;
на Team и Enterprise публичный доступ выключен, пока владелец не включит
**External sharing**.

Каждая публикация становится версией, и элемент управления Share выбирает, какую
версию видят зрители. Зрители из организации видят ваше имя; зритель,
открывающий публичную ссылку извне организации, видит пометку о том, что
содержимое создано пользователем и не проверено.

### 28.2 Живые данные через коннекторы

Страница может вызывать MCP-коннекторы при каждом просмотре, показывая текущие
данные, а не снимок (2.1.209+). Claude объявляет, какие коннекторы странице
позволено вызывать, и других она вызвать не может. Важна модель доступа:

- **Каждый зритель использует свои коннекторы.** Вызовы идут через подключения
  просматривающего аккаунта, поэтому двое, открывшие один дашборд, могут увидеть
  разные данные. Страница никогда не видит чужих учётных данных.
- **Зрители сперва одобряют доступ**, и отказ действует на эту загрузку
  страницы.
- **Действия тоже идут от аккаунта зрителя.** Элемент управления, который
  отправляет сообщение или обновляет задачу, действует от имени того, кто нажал.

**Артефакт, вызывающий коннекторы, нельзя опубликовать по публичной ссылке ни на
одном плане.** Просите Claude добавлять в каждый живой раздел запасное
сообщение с названием нужного коннектора, чтобы зритель без подключения видел,
что подключить, а не пустую панель.
